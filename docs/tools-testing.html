    Testing

    Tests live next to the code in files named *_test.ktm. Each void testXxx(testing.T *t) in them is a test; ktm test finds them, compiles them with the code they test and runs them, as go test does.

    A first test#

    // geo/area.ktm
module geo;

pub i64 area(i64 w, i64 h) { return w * h; }

pub u8 *kind(i64 w, i64 h) { return w == h ? "square" : "rect"; }

i64 clamp(i64 n) { return n &lt; 0 ? 0 : n; }

    // geo/area_test.ktm: in the module, so it sees clamp too
module geo;
import testing;

void testArea(testing.T *t) {
    t.equal(area(3, 4), 12);
    t.equal(area(0, 9), 0);
}

void testKind(testing.T *t) {
    t.equal(kind(2, 2), "square");
    t.equal(kind(2, 3), "square");
}

void testClamp(testing.T *t) {
    t.check(clamp(-5) == 0, "clamp(-5) is %d", clamp(-5));
}

    $ ktm test ./geo
--- FAIL: testKind (0.00s)
    area_test.ktm:11: got "rect", want "square"
FAIL
FAIL	./geo	0.00s  (2 passed, 1 failed)
$ echo $?
1

    A failed check doesn't stop its test: every failure is listed, with its file and line. Passing tests print nothing but the summary line; -v shows each one.

    Where tests go#

    • In a module's directory, starting with the module's line (module geo;): the test is part of the module and uses every name in it, pub or not.
    • Next to main.ktm, with no module line: the test imports modules as the program does and sees their pub names. It can't call the functions of main.ktm itself: put what you want to test in a module.
    • *_test.ktm files are left out of everything else: ktm build, ktm run, ktm -lib and an import never read them.
    • A test is a top-level void testXxx(testing.T *t): test, then nothing or a name that doesn't start with a lower-case letter (testParse, test2; not testing or tester). Other functions in the file are helpers.
    • Tests run in the order they are written, file by file in name order, one directory at a time.

    testing.T#

    CallWhat it does
    t.check(ok), t.check(ok, "fmt", ...)Fails the test when ok is false, with the message (printf's format)
    t.equal(got, want)Fails with got X, want Y unless they are equal: integers (bools, chars, enums: t.equal(n > 0, true) shows got 0, want 1), f64, and text as u8 *, u8[] or String (the bytes are compared; null only equals null)
    t.fail("fmt", ...)Fails the test with a message; it goes on
    t.fatal("fmt", ...)Fails the test and ends it (the rest of the test would make no sense)
    t.skip("fmt", ...)Ends the test, counted as skipped: no database, wrong platform
    t.log("fmt", ...)A message, printed when the test fails or with -v
    t.hasFailed()Has it failed so far?
    t.nameThe test's name, as "testKind"
    • Every message starts with the file and line of the call (the methods take @caller parameters).
    • A test that throws and doesn't catch fails with the error's message, file and line; the next test runs. fatal and skip end a test by throwing too, so a try around them in the test catches them.
    • A crash (a segmentation fault) ends the directory's run: FAIL dir [crashed: -v shows in which test].

    Table tests#

    Many cases, one test: an array of structs and a loop. The message says which case failed.

    module geo;
import testing;

struct AreaCase { i64 w, h, want; };

void testAreaTable(testing.T *t) {
    AreaCase cases[] = {
        {1, 1, 1},
        {2, 5, 10},
        {7, 0, 0},
    };
    for (auto c : cases) {
        t.check(area(c.w, c.h) == c.want, "area(%d, %d) = %d, want %d",
                c.w, c.h, area(c.w, c.h), c.want);
    }
}

    Running tests#

    $ ktm test                 # the tests in this directory
$ ktm test ./geo           # in one directory
$ ktm test ./...           # in this one and every one under it
$ ktm test -run Area ./... # only the tests whose name contains Area
$ ktm test -v              # every test, and its log messages
$ ktm test -jit -Memsafe   # with the JIT, reporting leaks and bad frees
    $ ktm test ./...
ok  	.	0.00s  (1 passed)
ok  	geo	0.00s  (4 passed)
$ ktm test -jit -v .
=== RUN   testFromOutside
--- PASS: testFromOutside (0.00s)
PASS
ok  	.	0.00s  (1 passed)
    • One line per directory: ok or FAIL, the time, and how many tests passed, failed and were skipped. A directory without test files says [no test files]; one that doesn't compile prints the errors and FAIL dir [build failed or exited early].
    • The exit code is 0 when every test passed, 1 otherwise: ktm test ./... works as a CI step.
    • ./... leaves out directories starting with . or _, and testdata (a place for the files tests read).
    • Tests compile ahead of time, as ktm -run; -jit runs them with the JIT. Other flags go to the compiler: -Werror, -DNAME, --install-dir=....
    • Tests run in the directory ktm test was started in.

    In a project#

    In a project with a ktm.mod (see Packages), ktm test finds modules and packages as ktm build does: from the project's root, with the versions in ktm.mod, downloading the ones that are missing. Run it from the root or any directory under it.

    shapes/
├── ktm.mod          // module example.com/you/shapes
├── main.ktm
├── main_test.ktm    // import geo, testing;
└── geo/
    ├── area.ktm
    ├── area_test.ktm
    └── table_test.ktm
