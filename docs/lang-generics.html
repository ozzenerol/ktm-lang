    Generics

    Structs, methods and functions can take type parameters. Each use is compiled for its types: the same code you would write by hand, with no void * and no casts.

    At a glance

    T max<T>(T a, T b) { return a > b ? a : b; }
max(3, 7);  max<f64>(1, 2.5);        // inferred, or written
struct Pair<K, V> { K key; V value; };
Pair<u8 *, f64> p;
void Stack<T>.push(T x) { ... }       // a method of a generic struct
type Ints = Stack<i64>;              // name an instance

    Generic functions#

    T max<T>(T a, T b)
{
  return a > b ? a : b;
}

void swap<T>(T *a, T *b)
{
  T t = *a;
  *a = *b;
  *b = t;
}

void main()
{
  printf("%d %.1f %c\n", max(3, 7), max(1.5, 0.5), max('a', 'z'));
  i64 x = 1, y = 2;
  swap(&x, &y);
  printf("%d %d\n", x, y);
  printf("%.1f\n", max<f64>(1, 2.5));     // written out: 1 becomes 1.0
}

    7 1.5 z
2 1
2.5

    A call works the types out from the arguments, through pointers, slices, fn types and generic structs. When nothing says what a parameter is, write it: make<i64>().

    Generic structs#

    struct Pair<K, V> { K key; V value; };

Pair<K, V> pairOf<K, V>(K k, V v)
{
  Pair<K, V> p = {k, v};
  return p;
}

void main()
{
  Pair<u8 *, f64> pi = {"pi", 3.14};
  auto e = pairOf("e", 2.72);
  Pair<i64, bool> flag = pairOf(7, true);
  printf("%s=%.2f %s=%.2f %d=%d\n", pi.key, pi.value, e.key, e.value, flag.key, flag.value);
  printf("%s\n", typeof(e));
}

    pi=3.14 e=2.72 7=1
Pair<u8 *, f64>

    A type is always written with its arguments, nested ones too: Stack<Stack<i64>>.

    Methods of a generic struct#

    import mem;

struct Stack<T> { T *items; i64 len; i64 cap; };

void Stack<T>.push(T x)
{
  if (self.len == self.cap) {
    self.cap = self.cap ? self.cap * 2 : 4;
    self.items = mem.realloc(self.items, sizeof(T) * self.cap);
  }
  self.items[self.len++] = x;
}

T Stack<T>.pop() { return self.items[--self.len]; }
bool Stack<T>.empty() { return self.len == 0; }
void Stack<T>.free() { mem.free(self.items); }

void main()
{
  ad Stack<i64> nums = {null, 0, 0};
  for (i64 i = 1; i <= 5; i++) { nums.push(i * i); }
  while (!nums.empty()) { printf("%d,", nums.pop()); }
  printf("\n");

  ad Stack<u8 *> words = {null, 0, 0};
  words.push("first");
  words.push("second");
  printf("%s\n", words.pop());
}

    25,16,9,4,1,
second

    Methods with type parameters of their own#

    A method can have type parameters of its own, written after its name as for a function. It works on a plain struct, and on a generic one next to the struct's parameters.

    struct Counter { i64 n; };

i64 Counter.addAll<V>(V[] xs)
{
  for (auto x : xs) { self.n += (i64)x; }
  return self.n;
}

V Counter.zero<V>() { V z; return z; }

struct Pair<T> { T a; T b; };

Pair<U> Pair<T>.map<U>(fn(T) U f)
{
  Pair<U> p = {f(self.a), f(self.b)};
  return p;
}

f64 half(i64 x) { return (f64)x / 2.0; }
u8 *sign(f64 x) { return x >= 1.0 ? "big" : "small"; }

void main()
{
  Counter c = {0};
  u8 bytes[] = {1, 2, 3};
  f64 floats[] = {1.5, 2.5};
  printf("%d %d\n", c.addAll(bytes), c.addAll(floats));
  printf("%d\n", c.zero<i64>());

  Pair<i64> p = {1, 5};
  Pair<u8 *> s = p.map(&half).map(&sign);
  printf("%s %s\n", s.a, s.b);
}

    6 9
0
small big
    • A call works out the method's own parameters from its arguments, as for a generic function: self takes no part, and the struct's parameters come from the receiver (a Pair<i64> gives T = i64). Write them when nothing says what they are, as for c.zero<i64>() whose V is only in the return type.
    • Each set of type arguments makes its own instance, Counter.addAll<u8>, the first time it is called.
    • The method is found on a pointer, on a call's result (p.map(...).map(...)) and on a struct that derives from its struct, as any method is. pub works as for any method.
    • Its own parameter names can't be the struct's: Pair<T>.f<T> is an error.
    • It shares its name with nothing: not a field, not a plain method, not another generic method of the struct.

    Generic functions over generic structs#

    struct Box<T> { T value; };

T unbox<T>(Box<T> *b) { return b.value; }

T sum<T>(T[] xs)
{
  T total = 0;
  for (auto x : xs) { total += x; }
  return total;
}

void main()
{
  Box<f64> b = {2.5};
  i64 ints[] = {1, 2, 3};
  f64 floats[] = {0.5, 0.25};
  printf("%.1f %d %.2f\n", unbox(&b), sum(ints), sum(floats));
}

    2.5 6 0.75

    A generic base#

    struct List<T> { T items[4]; i64 len; };
struct Counted<T> : List<T> { i64 adds; };

void List<T>.add(T x) { self.items[self.len++] = x; }

void main()
{
  Counted<i64> c;
  c.len = 0;
  c.adds = 0;
  c.add(10);
  c.adds++;
  printf("%d %d %d\n", c.len, c.items[0], c.adds);
}

    1 10 1

    The library's generics#

    The containers are generic: vec.Vec<T>, map.Map<K, V>, set.Set<T>, list.List<T>.

    import map, vec;

void main()
{
  ad vec.Vec<u8[]> names = vec.new<u8[]>();
  names.push("ann");
  names.push("bob");
  ad map.Map<u8[], i64> ages = map.new<u8[], i64>();
  ages.set("ann", 41);
  for (auto n : names) { printf("%s %d\n", n, ages.getOr(n, -1)); }
}

    ann 41
bob -1

    Errors are checked per instance#

    The body is checked for each type it is used with. max of two structs is an error at the >, with a note naming the instance (max<Point>) and the call that asked for it.

    In modules and libraries#

    • pub works as for any declaration; outside, write coll.Vec<i64> and coll.vecNew<i64>().
    • A library built with -lib keeps its generics as source, and each program makes the instances it uses.

    Not yet#

    • Constraints on type parameters.
    • Generic enums.
    • Number parameters (Array<T, 16>).
    • A different body for one type (specialisation).
    • Several generic methods of one name, or a generic method next to a plain one of its name.
    • The address of a generic method (&s.f): wrap the call in a function.
