    LibraryReference: coro

    The coroutine loop

    One coroutine per connection, all on one thread. coro.go starts a coroutine in the loop, coro.run runs the loop, and the I/O calls pause only the coroutine that waits.

    At a glance

    coro.go(&handler, arg);        // start a coroutine in this thread's loop
coro.run();                    // until every one has ended
// inside a loop coroutine:
coro.accept(listener)   coro.read(fd, buf)   coro.write(fd, data)   coro.dial(host, port)
coro.wait(fd, events, ms)   coro.sleep(ms)   coro.waitChild(pid)   coro.close(fd)
coro.park(ms)   coro.unpark(c)
coro.stop();                   // stop taking work; finish what is in flight

    An echo server#

    The server and its clients run as coroutines in one loop, on one thread.

    import coro, cstr, libc, net;

i32 gListen;

void *serveOne(void *arg)
{
  i32 fd = (i32)(i64)arg;
  u8 buf[256];
  i64 n;
  while ((n = coro.read(fd, buf, 5000)) > 0) {      // pauses until data comes
    coro.write(fd, buf[0:n]);                       // pauses while the socket is full
  }
  coro.close(fd);
  return null;
}

void *acceptor(void *unused)
{
  i32 fd;
  while ((fd = coro.accept(gListen)) != -1) { coro.go(&serveOne, (void *)(i64)fd); }
  return null;                                      // coro.stop() was called
}

void *client(void *word)
{
  i32 fd = coro.dial("127.0.0.1", net.localPort(gListen), 5000);
  coro.write(fd, cstr.view(word));
  u8 buf[64];
  i64 n = coro.read(fd, buf, 5000);
  printf("%s -> %s\n", word, buf[0:n]);
  coro.close(fd);
  return null;
}

void *clients(void *unused)
{
  client("ping");
  client("hello");
  coro.stop();                                      // let the server finish
  return null;
}

void main()
{
  gListen = net.listen(0, "127.0.0.1", 16);
  coro.go(&acceptor);
  coro.go(&clients);
  coro.run();
  libc.close(gListen);
  printf("stopped\n");
}

    ping -> ping
hello -> hello
stopped

    The calls#

    CallPauses untilReturns
    coro.read(fd, buf, ms)Something can be readBytes read, 0 at end of file, -1 on error or timeout
    coro.write(fd, data, ms)All of data is writtendata.len, or -1 (EPIPE, never SIGPIPE)
    coro.accept(listener, ms)A client connectsA non-blocking fd; -1 on timeout, error or coro.stop()
    coro.dial(addr, port, ms)The connection is madeA non-blocking fd, or -1 with os.errno()
    coro.wait(fd, events, ms)fd is ready for eventsIts revents (above 0), or 0 on timeout
    coro.waitIdle(fd, events, ms)The same, for waiting on more workAlso -1 once coro.stop() is called
    coro.sleep(ms), coro.yield()Time passes / the others had a turn
    coro.park(ms)Another coroutine (of this loop or another thread's) calls coro.unpark(c)1, or 0 on timeout, -1 on coro.stop(); an unpark before the park makes it return at once. No syscall within a loop; coro.unpark from another thread works too (through the loop's mailbox, one write)
    coro.waitChild(pid, ms)A child process exitsIts wait status, or -1
    coro.close(fd)Closes the fd and tells the loop
    • ms is optional everywhere: leave it out to wait without a limit.
    • Close the fds you wait on with coro.close, not libc.close.
    • A read on a busy stream goes straight on without waiting, for 4 ms at most before others get a turn.
    • Out of fds, coro.accept rests instead of spinning, so no client is dropped.
    • coro.dial still waits for the system resolver on a host name: give a numeric address where that matters.

    Timers alongside I/O#

    import coro;

void *ticker(void *name)
{
  for (i64 i = 1; i <= 3; i++) {
    coro.sleep(40);
    printf("%s tick %d\n", name, i);
  }
  return null;
}

void *slow(void *unused)
{
  coro.sleep(60);
  printf("slow done\n");
  return null;
}

void main()
{
  coro.go(&ticker, "a");
  coro.go(&slow);
  coro.run();
  printf("all done\n");
}

    a tick 1
slow done
a tick 2
a tick 3
all done

    Waiting for child processes#

    Three jobs run at once, each waited for by its own coroutine, while another keeps working.

    import coro, proc;

void *job(void *arg)
{
  u8 *script = arg;
  u8 *argv[4] = {"/bin/sh", "-c", script, null};
  proc.Proc *p = proc.spawn(argv);
  i32 st = coro.waitChild(p.pid, 5000);
  proc.setStatus(p, st);
  printf("[%s] exit %d\n", script, p.exitCode);
  proc.release(p);
  return null;
}

void *busy(void *unused)
{
  for (i64 i = 0; i < 3; i++) {
    printf("still working\n");
    coro.sleep(200);
  }
  return null;
}

void main()
{
  coro.go(&job, "sleep 0.5; exit 3");
  coro.go(&job, "sleep 0.1");
  coro.go(&job, "sleep 0.3; exit 1");
  coro.go(&busy);
  coro.run();
}

    still working
[sleep 0.1] exit 0
still working
[sleep 0.3; exit 1] exit 1
still working
[sleep 0.5; exit 3] exit 3

    Heavy work#

    A loop runs one coroutine at a time and switches only when one waits, so a coroutine that computes for 20 ms holds every other coroutine of its loop for 20 ms. coro.offload(fn, arg) runs fn(arg) on a worker thread instead (a pool with a thread per core, started on first use) and the coroutine waits for it as it waits for I/O:

    struct Resize { Image *in; Image *out; };

void resize(void *arg) {
  Resize *r = arg;
  r.out = scale(r.in, 0.5);          // seconds of computing
}

void handler(http.Writer *w, http.Request *r) {
  Resize job;
  job.in = load(r);
  coro.offload(&amp;resize, &amp;job);    // the loop serves other requests meanwhile
  send(w, job.out);
}

    What fn throws is thrown again in the caller. fn runs on another thread, so it must not use the loop (coro.read, coro.park, ...); arg is its link to the caller. Outside a loop coroutine offload just calls fn(arg). crypto's password hashing uses it by itself.

    Stopping#

    coro.stop() winds the loop down: coro.accept and coro.waitIdle return -1 from then on, while other waits go on, so the work in flight finishes and coro.run returns. coro.stopping() tells whether it was called (a server sends Connection: close then).

    Ctrl-C and SIGTERM fit as one more coroutine:

    void *onSignal(void *unused)
{
  if (coro.waitIdle(signal.stopInit(), libc.POLLIN) > 0) { coro.stop(); }
  return null;
}

// in main, before coro.run():
coro.go(&onSignal);

    It uses waitIdle, so it doesn't keep the loop alive once everything else has ended.

    Errors#

    • coro.inLoop() is true in a coroutine of a loop (coro.go, coro.serve): a library uses it to choose coro.read or a blocking read.
    • The loop calls throw coro.ERR_LOOP when they can't work: coro.run inside a coroutine, coro.read outside one, a loop where every coroutine waits forever with no fd.
    • When a loop coroutine throws, the loop releases it and coro.run throws the error on. The other coroutines stay; calling coro.run again carries on with them.

    Backends#

    On Linux the loop uses io_uring where the kernel allows it (6.1 or later, and not blocked, as Docker's default profile does); otherwise epoll (Linux), kqueue (macOS), or poll. Every backend behaves the same.

    import coro;

void *show(void *unused)
{
  u8[] b = coro.backend();
  printf("a known backend: %d\n", b.equals("uring") || b.equals("epoll") || b.equals("kqueue") || b.equals("poll"));
  return null;
}

void main()
{
  coro.go(&show);
  coro.run();
}

    a known backend: 1

    KTM_CORO_BACKEND=uring, epoll, kqueue or poll picks one; a backend the system can't give falls back to the next one down.

    A turn of the loop costs the fds that are ready, not every fd that is open: ten thousand idle connections cost nothing.
