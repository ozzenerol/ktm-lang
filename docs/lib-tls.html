    LibraryReference: net.tls

    TLS

    net.tls encrypts a connection, as a client or a server. It is built on mbedTLS, which ships inside ktm: nothing has to be installed, and only programs that import net.tls; carry it. TLS 1.2 and 1.3.

    A client#

    import net.tls;

void main()
{
  tls.Conn *c = tls.dial("example.com", 443);     // checks the certificate against the system's CAs
  defer c.close();
  c.write("HEAD / HTTP/1.1\r\nHost: example.com\r\nConnection: close\r\n\r\n");
  u8 buf[4096];
  i64 n = c.read(buf[0:], 5000);
  printf("%s %s\n%.*s", c.version(), c.cipher(), n, buf);
}

    TLSv1.3 TLS1-3-CHACHA20-POLY1305-SHA256
HTTP/1.1 200 OK
...

    tls.dial throws tls.ERR_TLS when it can't connect or the server's certificate isn't trusted, with the reason: the server's certificate isn't trusted: The certificate Common Name (CN) does not match with the expected CN.

    Connections#

    CallWhat it does
    c.read(buf, ms)Bytes read, 0 once the peer closed, -1 on an error or after ms (-1: no limit); c.error() says why
    c.write(data, ms)Writes all of data: data.len, or -1
    c.close()Tells the peer, frees the connection, closes the socket
    c.version(), c.cipher(), c.alpn()"TLSv1.3", the cipher suite, the protocol ALPN chose
    c.peerCert(&sigHash)The peer's certificate (DER), for channel binding
    c.pending()Decrypted bytes a read gets without the socket

    In a loop coroutine (coro.go, coro.serve, net.http handlers) every wait pauses only the coroutine; anywhere else it blocks the thread.

    Contexts#

    A tls.Context is a configuration: the trusted CAs, a certificate, how to verify. Make one and use it for every connection, from any thread; tls.dial(host, port) uses a shared one with the system's CAs.

    tls.Config cfg;
cfg.caFile = "/etc/app/ca.pem";            // trust this CA instead of the system's
tls.Context *ctx = tls.client(&amp;cfg);

i32 fd = net.dial("db.internal", 5432);
// ... a protocol's own start, then:
tls.Conn *c = ctx.connect(fd, "db.internal");   // TLS over a socket you already have
    tls.Config fieldMeaning
    verifyVerify.full (the chain and the name, the default), Verify.chain (any name), Verify.none (no checks)
    caFile, caPemTrusted CAs; neither: the system's (SSL_CERT_FILE picks a file)
    certFile, keyFile (or certPem, keyPem)This side's certificate and key: a server's, or a client certificate
    keyPasswordFor an encrypted key
    alpnProtocols to offer or accept, "h2,http/1.1"
    handshakeMsThe handshake's limit (30 s)

    A server#

    tls.Config cfg;
cfg.certFile = "server.pem";
cfg.keyFile = "server.key";
tls.Context *ctx = tls.server(&amp;cfg);

i32 fd = net.accept(listener);
tls.Conn *c = ctx.accept(fd);
u8 buf[4096];
i64 n = c.read(buf[0:]);
c.write(buf[0:n]);
c.close();

    A server given CAs (caFile) asks clients for a certificate and checks it.

    Notes#

    • A context outlives its connections: close them before ctx.free().
    • TLS 1.0 and 1.1, and renegotiation, are off.
    • mbedTLS 3.6 (Apache-2.0), in src/vendor/mbedtls, unchanged.
