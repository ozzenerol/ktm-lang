    Packages

    A package is a module in its own git repository, used by its path, as in Go: import "github.com/user/repo";. The project's ktm.mod says which versions; ktm get fetches them, ktm build builds with them. There is no registry: a version is a git tag, and any git host works.

    A project that uses one#

    $ mkdir users-api && cd users-api
$ ktm mod init github.com/you/users-api
ktm: created ktm.mod for github.com/you/users-api
$ ktm get github.com/ozzenerol/ktm-pg
ktm: added github.com/ozzenerol/ktm-pg v0.1.0
    // main.ktm
import "github.com/ozzenerol/ktm-pg";      // its module line says `module pg;`: used as pg.X
import net.http;

i32 main()
{
  pg.Pool *db = pg.open("postgres://app:secret@localhost/app");
  ...
}

    $ ktm build            # main.ktm of this directory, into ./users-api
$ ktm run . --port 8080   # or build and run it, with arguments

    ktm.mod and ktm.sum#

    module github.com/you/users-api

ktm 0.20

require (
	github.com/ozzenerol/ktm-pg v0.1.0
	github.com/someone/color v1.1.0 // indirect
)

replace github.com/someone/color => ../color
    • module is the project's own path: its other packages are imported by it too (import "github.com/you/users-api/store"; is its directory store).
    • ktm is the ktm version it needs; an older compiler refuses it.
    • require lists every package the build uses and the version; // indirect marks one only another package needs. A package that is only required by a dependency, for code the project never imports, isn't listed (see Only what the code needs).
    • replace uses a local copy (=> ../color, a path starting with ./, ../ or /) or another repository's version (=> github.com/fork/color v1.1.2).
    • ktm.sum holds a hash of each version's files. A download that doesn't match is refused, so a version can't change under you (a moved tag, a tampered repository). Commit both files.

    Importing#

    • The path is in quotes; its name in the code is its module line (import "github.com/ozzenerol/ktm-pg"; is pg). import p = "..."; gives it another name.
    • A directory of a package is a package too: import "github.com/user/repo/sub";.
    • The standard library and the program's own modules keep their plain form: import net.http;.
    • A package from another repository's files are read-only in the cache (~/.cache/ktm/mod, or KTM_CACHE).

    Versions#

    A version is a git tag vMAJOR.MINOR.PATCH (v1.2.0, v0.3.1-rc.1). A build uses, for each package, the highest version anything requires: a package always gets at least what it asked for, and nothing newer than someone asked for. The same ktm.mod gives the same build, with no lock file.

    • One major version of a package per build: v1 and v2 of the same package together are an error naming who wants which.
    • Fetching never runs a package's code: git clones, ktm hashes.
    • A private repository works like any other: git uses your SSH key or credential helper (ktm never asks for a password).

    Only what the code needs#

    A package is downloaded only when the project imports one of its directories, directly or through another package's imports. github.com/ozzenerol/ktm-migrate requires ktm-pg for its postgres directory; a project that imports only ktm-migrate (or its sqlite directory) never downloads ktm-pg, and its ktm.mod doesn't list it.

    $ ktm get github.com/ozzenerol/ktm-migrate
ktm: downloading github.com/ozzenerol/ktm-migrate v0.1.0
ktm: added github.com/ozzenerol/ktm-migrate v0.1.0
$ ktm mod why github.com/ozzenerol/ktm-pg
github.com/ozzenerol/ktm-pg v0.1.0 <- github.com/ozzenerol/ktm-migrate v0.1.0 <- example.com/me/app (ktm.mod)
but no package the project imports needs it: it isn't downloaded or built

    Import "github.com/ozzenerol/ktm-migrate/postgres" and the next ktm build downloads ktm-pg (its hash goes into ktm.sum); ktm mod tidy adds its // indirect line.

    • A package's requirements count only when it is needed: its own ktm.mod is read then, and may raise the version of something else the build uses. A package nothing imports can't raise anything (as in Go since 1.17).
    • ktm get path counts path as imported: ktm get github.com/ozzenerol/ktm-migrate/postgres fetches ktm-pg too.
    • Imports in a dependency's *_test.ktm files don't count; the project's own tests do.
    • ktm mod tidy drops a line nothing needs any more (an // indirect line older ktm versions wrote for every requirement of a dependency); it never lowers a version.
    • ktm mod list, verify and download work on what the build needs.

    Commands#

    CommandWhat it does
    ktm mod init [path]A new ktm.mod here (the path defaults to the directory's name)
    ktm get path[@v1.2.0|@latest|@none]Adds or changes a requirement, fetches it and what it needs; @none removes it
    ktm mod tidyMakes ktm.mod and ktm.sum match the imports: adds what is imported, drops what isn't
    ktm build [dir], ktm run [dir] [args]Builds (or runs) main.ktm, fetching what is missing; the binary is named after the module path
    ktm test [dir | ./...]Runs the tests in *_test.ktm files, with the project's packages: see Testing
    ktm mod downloadFetches what the build needs into the cache
    ktm mod listThe packages and versions a build uses
    ktm mod why pathWho imports a package, and the chain of requirements down to it
    ktm mod verifyChecks the cached files against ktm.sum
    ktm mod fmtChecks ktm.mod and rewrites it in the standard layout

    Publishing a package#

    1. A repository whose root has ktm.mod (module github.com/you/thing) and the module's .ktm files, each starting with module thing;.
    2. Tag a release and push the tag: git tag v0.1.0 && git push origin v0.1.0. That's it: ktm get github.com/you/thing finds it.
    3. Never move a tag: ktm.sum files that recorded it will refuse the new files. Tag a new version instead.

    The repository is the first three elements of the path (host/user/repo), fetched over HTTPS; git's url.<base>.insteadOf settings redirect it (a mirror, SSH).
