    Debugging

    Find memory bugs with -Memsafe, and look at every stage of the compiler: tokens, syntax tree, IR, assembly.

    Memory bugs: -Memsafe#

    Run with -jit -Memsafe. Double frees and wild frees are reported (and skipped) as they happen; leaks when main returns or the program calls exit(). Each report names the file and line in your code that allocated or freed the block, and the library function it went through (via str.from): the one your code called, never a private helper of it, since with -Memsafe a library function isn't inlined into your code.

    import mem;

void main()
{
  u8 *a = mem.alloc(16);
  u8 *b = mem.alloc(32);
  mem.free(a);
  mem.free(a);      // double free
}                   // b leaks
    $ ktm -jit -Memsafe leaky.ktm
Free: double free of 0x559df8f63ca8 (16 bytes)
  allocated   at leaky.ktm:5 in main
  first freed at leaky.ktm:7 in main
  this free   at leaky.ktm:8 in main - ignored, heap unharmed
memsafe: 1 allocation(s) (32 bytes) never freed
  0x559df8f63df8        32 bytes  at leaky.ktm:6 in main
    • A leak is a block nothing points to any more. What a global, the library or (when the program calls exit()) a live variable still holds at exit is in use, not a leak: it is listed apart, under still in use at exit ... not leaks. So a program that ends while it still holds its data needs no frees just for the report.
    • The check is conservative: a word that looks like a pointer keeps a block alive. A small function inlined into its caller leaves its variables in the caller's frame, so what it dropped can count as in use.
    • It works in any thread.
    • Every heap block is tracked: mem.alloc and friends, and what the library allocates for you (a String, a vec.Vec), reported at your line with via str.from, via vec.new<String> and so on. A module's global initialisers show as in <module>'s globals.
    • The REPL always tracks allocations: replHeap(); lists the live ones.

    Errors at run time#

    • An out-of-range slice index throws ERR_BOUNDS with the index, the length and where.
    • An uncaught error prints its code, message, file and line, and exits with 1.
    • Writing to a string literal faults: copy it with str.from first.
    void main()
{
  i64 nums[3] = {1, 2, 3};
  i64[] s = nums;
  i64 i = 3;
  try {
    printf("%d\n", s[i]);
  } catch (Error e) {
    printf("%s (%s:%d)\n", e.message, e.file, e.line);
  }
}

    index 3 out of range for length 3 (example.ktm:7)

    Looking under the hood#

    ktm -tokens main.ktm         # what the lexer sees
ktm -ast main.ktm            # the parsed program
ktm --dump-ir main.ktm       # the SSA intermediate representation
ktm -S -o- main.ktm          # the generated assembly
ktm --expand main.ktm        # the code @json and @yaml wrote
ktm -cfg main.ktm && dot -Tpng main.dot -o main.png   # a control flow graph

    -cfg-png and -cfg-svg write the image directly (they need Graphviz).

    Native debuggers#

    A compiled ktm program is a normal executable: gdb and lldb can run it, set breakpoints on function names (break main) and show registers and memory.
