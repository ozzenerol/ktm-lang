    LibraryReference: mem

    Memory

    The mem module allocates, resizes and frees. Nothing is garbage collected.

    FunctionDoes
    mem.alloc(size)Allocates size bytes (not zeroed)
    mem.allocZero(size)Allocates size zeroed bytes
    mem.realloc(p, size)Resizes; mem.realloc(null, n) is mem.alloc(n)
    mem.free(p)Releases it; null is fine
    mem.size(p)The size that was asked for (0 for null)
    mem.copy(dst, src, n)Copies n bytes, front to back; returns dst
    mem.set(dst, byte, n)Fills n bytes; returns dst

    Allocating#

    import mem;

struct Player { u8 *name; i64 score; };

void main()
{
  Player *team = mem.allocZero(3 * sizeof(Player));
  defer mem.free(team);
  team[0].name = "ada";
  team[0].score = 10;
  printf("%s %d, %d bytes, second is empty: %d\n",
         team[0].name, team[0].score, mem.size(team), team[1].name == null);
}

    ada 10, 48 bytes, second is empty: 1

    Growing#

    mem.realloc always moves the block and copies what fits. When it fails it returns null and the old block is untouched, so keep the old pointer until you know it worked.

    import mem;

void main()
{
  i64 cap = 2, len = 0;
  i64 *items = mem.alloc(cap * sizeof(i64));
  for (i64 i = 1; i <= 5; i++) {
    if (len == cap) {
      i64 *bigger = mem.realloc(items, cap * 2 * sizeof(i64));
      if (!bigger) { break; }     // items is still valid
      items = bigger;
      cap *= 2;
    }
    items[len++] = i * 10;
  }
  printf("%d items, room for %d, last %d\n", len, cap, items[len - 1]);
  mem.free(items);
}

    5 items, room for 8, last 50

    A vec.Vec does this for you.

    Copying and filling#

    import mem;

void main()
{
  u8 a[8], b[8];
  mem.set(a, 'x', 8);
  mem.copy(b, "abcdefg", 8);    // 7 letters and the NUL
  a[7] = 0;
  printf("%s %s\n", a, b);

  i64 src[3] = {1, 2, 3}, dst[3];
  mem.copy(dst, src, sizeof(src));
  printf("%d %d %d\n", dst[0], dst[1], dst[2]);
}

    xxxxxxx abcdefg
1 2 3

    mem.copy copies front to back. For overlapping buffers use libc.memmove.

    Where it differs from C#

    • mem.allocZero takes one argument, the total size, unlike calloc(count, size).
    • All three allocators return null when out of memory or when the size is absurd (a negative size passed as a u64).
    • Each block keeps its size in a hidden header, so only pointers from these functions may go to mem.free, mem.size and mem.realloc. Memory from C's malloc goes back to C's free.

    Owning memory#

    The usual pattern: free in the same scope with defer, or give the value a free() method and declare it with ad.

    import mem;

struct Grid { i64 w, h; u8 *cells; };

Grid gridNew(i64 w, i64 h)
{
  Grid g = {w, h, mem.allocZero(w * h)};
  return g;
}
void Grid.free() { mem.free(self.cells); }
void Grid.set(i64 x, i64 y) { self.cells[y * self.w + x] = 1; }

void main()
{
  ad Grid g = gridNew(4, 3);
  g.set(1, 2);
  printf("%d %d\n", g.cells[2 * 4 + 1], g.cells[0]);
}

    1 0

    Finding memory bugs#

    Run with -jit -Memsafe: double frees and wild frees are reported (and skipped) as they happen, and leaks at exit, each with the line that allocated or freed the block.

    import mem;

void main()
{
  u8 *a = mem.alloc(16);
  u8 *b = mem.alloc(32);
  mem.free(a);
  mem.free(a);      // double free
}                   // b leaks
    $ ktm -jit -Memsafe leaky.ktm
Free: double free of 0x559df8f63ca8 (16 bytes)
  allocated   in `main`+23, line 5
  first freed in `main`+55, line 7
  this free   in `main`+64, line 8 - ignored, heap unharmed
memsafe: 1 allocation(s) (32 bytes) never freed
  0x559df8f63df8        32 bytes  in `main`+42, line 6
    • Only blocks from mem.alloc, mem.allocZero and mem.realloc are tracked.
    • Strings and containers the library allocates for you are not, so leaking one goes unreported.
