    Tools

    One binary, ktm, does everything: compiling, JIT, REPL, language server and debugging output.

    Compiling#

    ktm main.ktm -o app          # build ./app
ktm main.ktm                 # build ./a.out
ktm -S main.ktm -o main.s    # assembly only
ktm -S -o- main.ktm          # assembly to stdout
ktm -c main.ktm -o main.o    # object file, to link later
ktm main.ktm util.o -o app   # link object files in
ktm -DDEBUG main.ktm         # define a macro (no value)
ktm -Werror main.ktm         # treat warnings as errors

    Link C libraries with -clibs, or record them in the source with #link:

    ktm game.ktm -clibs="-lSDL2 -lm" -o game

    ktm hands the generated assembly to the system C compiler through a temporary file in $TMPDIR (/tmp if unset), one per compile and removed afterwards, so several compiles can run at once.

    All flags#

    FlagWhat it does
    -o <file>Output file name
    -runCompile to a temporary binary, run it and delete it; arguments after the file are passed to the program and its exit code becomes ktm's
    -jitCompile in memory and run (x86_64 and arm64)
    -MemsafeWith -jit: report double frees, wild frees and leaks at exit
    -replInteractive session
    -lspLanguage server over stdio, for editors
    -SEmit assembly only
    -o-With -S: write the assembly to stdout
    -cEmit an object file
    -fPICPosition-independent code, for object files that go into shared libraries
    -lib <name>Build lib<name>.a and a shared library and install them under the install prefix
    -clibs="..."Extra linker flags, such as -lcurl
    -D<NAME>Define a macro (no value)
    -WerrorTreat warnings as errors
    --install-dir <dir>Use <dir>/include and <dir>/lib instead of the install prefix
    --target <triple>Cross-compile: x86_64-unknown-linux-gnu, x86_64-apple-darwin, aarch64-apple-darwin, …
    -ast, -tokensPrint the syntax tree or the token stream and exit
    --dump-irPrint the intermediate representation
    -cfg, -cfg-png, -cfg-svgWrite a Graphviz control flow graph (PNG and SVG need Graphviz)
    --mem-statsReport the compiler's own memory use
    --version, --helpVersion and build details; all flags

    The JIT#

    ktm -jit file.ktm assembles machine code into memory with ktm's built-in assembler and runs it. No C compiler, linker or files are involved, so it starts fast. Arguments after the file are passed to the program. A file with no main has nothing to run: -jit says so and exits with 1. Use #ifjit / #ifaot for code that should differ between the two modes.

    ktm -jit server.ktm 8080

    The REPL#

    ktm -repl

    ktm runs as you type it. Functions, structs, globals and #defines accumulate across the session, and the value of a trailing expression is echoed:

    &gt; i64 Sq(i64 x) { return x * x; }
&gt; Sq(7);
49
&gt; printf("hello %d\n", Sq(3));
hello 9
    • Line editing, history (~/.ktm_repl_history) and tab completion are built in.
    • ~/.ktm_rc.ktm is included at start-up. Put #define KTM_NO_REPL_HELLO in it to hide the welcome message.
    • replDisasm("name"); disassembles a function. replDel("name"); forgets a definition so you can redefine it.
    • replListFn(); lists the functions defined so far. replFindFn("name"); shows the functions whose names contain name.
    • replListGVars(); lists the globals. replClassRep("name"); prints a struct, class or union. replEval("code"); runs a string as REPL input. replHeap(); lists the live allocations, biggest first. replReloadRc(); reads ~/.ktm_rc.ktm again.
    • @ ls -la runs a shell command. It goes through system(), so @ cd doesn't change the REPL's directory.
    • Allocations are tracked, so leaks and bad frees are reported.

    Editor support#

    ktm -lsp is a language server. It works with any editor that speaks LSP and gives:

    • errors and warnings as you type, a module's files checked as the module they belong to;
    • hover with the declaration and its doc comment (the comment right above it, or after it on its line), for functions, methods, fields, enums and their members, modules, aliases and generics, the standard library's included;
    • completion: names in scope, fields and methods after . and ->, a module's names after its prefix, an enum's members, and the modules an import can name;
    • signature help in calls, with the parameter you are on and every overload;
    • go to definition, find references, highlighting of a name's uses, and rename;
    • the document outline and workspace symbol search;
    • semantic highlighting: modules, types, enums and members, functions and methods, fields, parameters, locals, constants and macros, with the standard library's marked;
    • folding (blocks, comments, imports, #if regions) and inlay hints with the type of each auto variable.

    Neovim#

    The syntax, filetype detection and indent settings install into <prefix>/share/ktm/vim (in a checkout: src/syntax-highlighting/vim). Add it to the runtime path and start the server for ktm files:

    vim.opt.rtp:append("/usr/local/share/ktm/vim")

vim.api.nvim_create_autocmd("FileType", {
  pattern = "ktm",
  callback = function(ev)
    vim.lsp.start({
      name = "ktm",
      cmd = { "ktm", "-lsp" },
      root_dir = vim.fs.root(ev.buf, { ".git" })
                 or vim.fs.dirname(vim.api.nvim_buf_get_name(ev.buf)),
    })
    vim.lsp.inlay_hint.enable(true, { bufnr = ev.buf })
  end,
})

    Semantic highlighting needs nothing more: Neovim colours the server's tokens with its @lsp.type.* groups (link @lsp.type.namespace.ktm and the others to change them).

    Vim#

    set runtimepath+=/usr/local/share/ktm/vim
filetype plugin indent on
syntax on

    Other editors#

    Point your editor's generic LSP client at the command ktm -lsp for .ktm and .ktmh files. If ktm isn't installed, add --install-dir=/path/to/build/prefix so it can find the standard library. Set KTM_LSP_LOG=1 in the server's environment to log its traffic to stderr.

    Libraries#

    Build your own ktm library and install it next to the standard one:

    ktm -lib mylib --install-dir=$HOME/.local mylib.ktm

    This produces libmylib.a and a shared library in $HOME/.local/lib. Mark the functions and globals it exports pub. To use the library, declare its functions, and its globals with extern (extern i64 count;, extern fn(i64) i64 hook;), usually in a .ktmh header you #include, and add #link <mylib>.

    Looking under the hood#

    ktm -tokens main.ktm                 # what the lexer sees
ktm -ast main.ktm                    # the parsed program
ktm --dump-ir main.ktm               # the SSA intermediate representation
ktm -S -o- main.ktm                  # the generated assembly
ktm -cfg main.ktm && dot -Tpng main.dot -o main.png
