    4. Configuration

    The port is written in the code, and so will the database's address be. A server reads such things from its environment: variables and a .env file for development, flags on the command line to override them.

    Settings#

    /* Settings: SHELF_PORT, SHELF_ACCESS_LOG, SHELF_MAX_BOOKMARKS from the
 * environment or .env, flags over them */
struct Settings {
    i64 port;
    bool accessLog;
    @min(1) i64 maxBookmarks;
};

Settings gSettings;

    The settings are a struct, with the same rules as a request. Each field's variable is the prefix and its name in capitals: maxBookmarks with "SHELF_" is SHELF_MAX_BOOKMARKS (@env("NAME") picks another). maxBookmarks is new: create answers 507 once that many are saved.

    main#

    i32 main(i32 argc, u8 **argv)
{
    /* defaults, then .env and the environment, then the command line */
    gSettings.port = 8080;
    gSettings.maxBookmarks = 10000;
    config.loadDotenv(".env");
    try {
        config.fromEnv(reflect.of(gSettings), "SHELF_");
    } catch (Error e) {
        log.error("%s", e.message);     /* every bad or missing variable, by name */
        os.exit(2);
    }

    flag.Set *fs = flag.new("shelf", "a bookmarks API");
    defer fs.free();
    i64 *port = fs.integer("port", gSettings.port, "the port to listen on", 'p');
    bool *accessLog = fs.boolean("access-log", gSettings.accessLog, "log every request");
    fs.parseOrExit(argc, argv);

    http.Mux mux;
    mux.handle("GET /bookmarks", &list);
    mux.handle("POST /bookmarks", &create);
    mux.handle("GET /bookmarks/{id}", &get);
    mux.handle("DELETE /bookmarks/{id}", &remove);

    http.Options o;
    o.threads = 1;
    o.accessLog = *accessLog;
    log.info("Shelf listening on http://localhost:%d", *port);
    return http.listen((i32)*port, &mux, null, &o);
}
    1. The defaults are what the struct holds before anything is read.
    2. config.loadDotenv(".env") sets the variables in .env, but never one the real environment already has. Then config.fromEnv reads them into the struct and checks the rules. When a variable isn't a number where a number goes, or breaks a rule, it throws one error naming every bad variable: a server that can't run says why and stops at once, not at the first request.
    3. flag takes the command line: --port 9000, -p 9000, --access-log, and -h for a help text made from them.

    Try it#

    $ cat .env
SHELF_PORT=8080
SHELF_ACCESS_LOG=yes
SHELF_MAX_BOOKMARKS=2

$ ktm run .
2026-10-14T15:23:14.892Z INFO  Shelf listening on http://localhost:8080
2026-10-14T15:23:15.038Z INFO  POST /bookmarks 201 134 0.044ms
2026-10-14T15:23:15.043Z INFO  POST /bookmarks 201 134 0.016ms
2026-10-14T15:23:15.048Z INFO  POST /bookmarks 507 29 0.011ms

$ ktm run . -- -h
usage: shelf [flags] [arguments]

a bookmarks API

flags:
  -p, --port int    the port to listen on (default 8080)
      --access-log  log every request (default true)
  -h, --help        show this help

$ SHELF_MAX_BOOKMARKS=0 ktm run .
2026-10-14T15:35:27.194Z ERROR config: SHELF_MAX_BOOKMARKS: must be at least 1
    • log.info and log.error write timestamped lines to stderr (Logging); o.accessLog adds a line per request with its status, size and time.
    • Don't commit .env (it ends up holding passwords): commit a .env.example instead.
    • In production the same variables come from the service manager or the container, and .env isn't there: loadDotenv then sets nothing.
