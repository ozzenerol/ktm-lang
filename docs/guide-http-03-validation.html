    3. Validation and errors

    So far Shelf saves anything: an empty url, "not a link", the same link twice. Rules on the request's fields fix the first two, and a check in the handler the third.

    Rules on fields#

    Only NewBookmark and one line of create change:

    @json struct NewBookmark {
    @required @url @max(2048) u8[] url;
    @max(200) u8[] title;
};
        NewBookmark in = http.decodeValid&lt;NewBookmark&gt;(r);    /* a 422 by itself when a rule fails */

    http.decodeValid decodes as http.decode does, then checks the rules. When one fails, the handler stops there and the client gets a 422 that names each field and what is wrong with it:

    $ curl -X POST localhost:8080/bookmarks -d '{"url": "not a link", "title": "x"}'
{"error":"invalid request","fields":[{"field":"url","message":"not a URL"}]}

$ curl -X POST localhost:8080/bookmarks -d '{}'
{"error":"invalid request","fields":[{"field":"url","message":"is required"}]}
    RuleHolds when
    @requiredThe field has a value (not empty, not 0, not null)
    @min(n), @max(n)A number is at least / at most n; a text has at least / at most n characters
    @url, @emailThe text is an absolute URL / looks like an email address
    @oneOf("a", "b")The text is one of those

    A field that is empty and not @required passes its other rules, so title may be left out. The full list is in Validation.

    Rules that need the data#

    "Already saved" isn't a property of the request: the handler checks it and answers 409 Conflict itself.

    void create(http.Writer *w, http.Request *r)
{
    NewBookmark in = http.decodeValid&lt;NewBookmark&gt;(r);    /* a 422 by itself when a rule fails */
    for (i64 i = 0; i &lt; gBookmarks.len; i++) {
        if (str.equals(gBookmarks.data[i].url[0:], in.url)) {
            w.error(409, "that link is already on the shelf");
            return;
        }
    }
    Bookmark b;
    b.id = uuid.v7().string();
    b.url = str.from(in.url);
    b.title = str.from(in.title.len ? in.title : in.url);   /* no title yet: the link itself */
    b.createdAt = date.formatUnix(date.unixNow(), "%Y-%m-%dT%H:%M:%SZ");
    gBookmarks.push(b);
    w.json(201, reflect.of(b));
}

    The error format#

    Every error Shelf sends has the same shape, {"error": "..."}, plus fields for a 422, so a client handles them in one place:

    CodeMeaningWho sends it
    400Not the JSON we expecthttp.decode, http.decodeValid
    404No such thinga handler, w.error(404, ...); the mux for unknown paths
    405Wrong method for this paththe mux
    409It conflicts with what is therea handler
    422Well-formed, but a rule failshttp.decodeValid
    500A bug: the handler threwthe server, which logs where

    The last row is worth knowing: a handler that throws doesn't take the server down. The request gets a 500, the log gets the error and the line it came from, and the next request is served as usual.
