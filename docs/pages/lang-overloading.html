Overloading

Several functions can share a name when their parameter types differ. A call picks the one its arguments fit best.

A first example


void show(i64 n)        { printf("number %d\n", n); }
void show(f64 x)        { printf("float %.2f\n", x); }
void show(u8[] s)       { printf("text %s\n", s); }
void show(i64 a, i64 b) { printf("pair %d, %d\n", a, b); }

void main()
{
  show(42);
  show(2.5);
  show("hello");
  show(1, 2);
}

number 42
float 2.50
text hello
pair 1, 2

Methods and a module's functions overload the same way.


import str;

struct Counter { i64 n; };
void Counter.add(i64 by)     { self.n += by; }
void Counter.add(u8[] word)  { self.n += word.len; }

void main()
{
  Counter c = {0};
  c.add(3);
  c.add("four");
  String s = str.from("owned");
  defer s.free();
  c.add(s);                  // a String is passed as its u8[]
  printf("%d\n", c.n);
}

How a call picks

  1. Every overload the arguments can convert to is a candidate. A conversion that would only warn (a pointer for an integer) doesn't count.
  2. Each argument fits its parameter, best to worst:
    • exactly: the same type, or an array or string literal for a slice of its element;
    • in the same family: another integer width or sign, a String for a u8[], any pointer for void *;
    • as an integer for a float.
  3. The overload that fits every argument at least as well as any other, and one better, wins. On a tie, the one that needs no defaults and no ... extras wins.

Anything else is an error that lists the overloads.

Integer literals are i64


void f(i32 x) { printf("i32\n"); }
void f(i64 x) { printf("i64\n"); }

void main()
{
  f(5);           // a literal is an i64
  f((i32)5);      // cast for the other one
  i32 small = 5;
  f(small);
}

With only f(i32) and f(i16), f(5) is ambiguous: cast it.

Enums are their own type


enum Color { red, green };

void paint(Color c) { printf("color %d\n", c); }
void paint(i32 n)   { printf("number %d\n", n); }

void main()
{
  paint(Color.green);
  paint((i32)7);
}

color 1
number 7

Defaults and ties


void send(u8[] msg)                { printf("plain: %s\n", msg); }
void send(u8[] msg, i64 retry = 3) { printf("retry %d: %s\n", retry, msg); }

void main()
{
  send("a");       // both fit; the one without a default wins
  send("b", 5);
}

plain: a
retry 5: b

Taking the address of an overload

&f picks the overload whose type the destination asks for.


i64 size(i64 n)  { return n; }
i64 size(u8[] s) { return s.len; }

i64 apply(fn(u8[]) i64 f, u8[] s) { return f(s); }

void main()
{
  fn(i64) i64 byNumber = &size;
  printf("%d %d\n", byNumber(7), apply(&size, "four"));
}

7 4

auto p = &size; has no type to pick by, so it is an error.

Rules

  • Two overloads with the same parameter types and different return types are an error.
  • A derived struct's method hides every overload of that name in its base.
  • ...s can't be spread into an overloaded function.
  • An extern "c" function has one C symbol and can't be overloaded.
  • Overloads with @caller parameters must all start with the same ones; a call fills them in, then picks the overload.
  • A function with no overloads keeps its plain symbol. Overloaded ones carry their parameter types in the symbol, shown in messages as show(u8[]).
