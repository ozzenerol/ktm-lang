JIT and code generation

A child forked by a JIT-run program on macOS can crash

On macOS (Apple Silicon), a program run with ktm -jit that calls libc.fork() sometimes gets a child that is killed by SIGBUS right after the fork, before it runs any of its own code: about once in a hundred runs, under heavy load. Compiled programs are not affected, and neither is Linux. proc.spawn uses posix_spawn, not fork.

Workaround: on macOS, compile a program that forks (ktm main.ktm -o main && ./main) instead of running it with -jit, or start processes with proc.spawn.
