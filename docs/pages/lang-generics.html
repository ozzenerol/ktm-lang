Generics

Structs, methods and functions can take type parameters. Each use is compiled for its types: the same code you would write by hand, with no void * and no casts.

At a glance

T max(T a, T b) { return a > b ? a : b; }
max(3, 7);  max(1, 2.5);        // inferred, or written
struct Pair { K key; V value; };
Pair p;
void Stack.push(T x) { ... }       // a method of a generic struct
type Ints = Stack;              // name an instance

Generic functions


T max(T a, T b)
{
  return a > b ? a : b;
}

void swap(T *a, T *b)
{
  T t = *a;
  *a = *b;
  *b = t;
}

void main()
{
  printf("%d %.1f %c\n", max(3, 7), max(1.5, 0.5), max('a', 'z'));
  i64 x = 1, y = 2;
  swap(&x, &y);
  printf("%d %d\n", x, y);
  printf("%.1f\n", max(1, 2.5));     // written out: 1 becomes 1.0
}

7 1.5 z
2 1
2.5

A call works the types out from the arguments, through pointers, slices, fn types and generic structs. When nothing says what a parameter is, write it: make<i64>().

Generic structs


struct Pair { K key; V value; };

Pair pairOf(K k, V v)
{
  Pair p = {k, v};
  return p;
}

void main()
{
  Pair pi = {"pi", 3.14};
  auto e = pairOf("e", 2.72);
  Pair flag = pairOf(7, true);
  printf("%s=%.2f %s=%.2f %d=%d\n", pi.key, pi.value, e.key, e.value, flag.key, flag.value);
  printf("%s\n", typeof(e));
}

pi=3.14 e=2.72 7=1

A type is always written with its arguments, nested ones too: Stack<Stack<i64>>.

Methods of a generic struct


import mem;

struct Stack { T *items; i64 len; i64 cap; };

void Stack.push(T x)
{
  if (self.len == self.cap) {
    self.cap = self.cap ? self.cap * 2 : 4;
    self.items = mem.realloc(self.items, sizeof(T) * self.cap);
  }
  self.items[self.len++] = x;
}

T Stack.pop() { return self.items[--self.len]; }
bool Stack.empty() { return self.len == 0; }
void Stack.free() { mem.free(self.items); }

void main()
{
  ad Stack nums = {null, 0, 0};
  for (i64 i = 1; i <= 5; i++) { nums.push(i * i); }
  while (!nums.empty()) { printf("%d,", nums.pop()); }
  printf("\n");

  ad Stack words = {null, 0, 0};
  words.push("first");
  words.push("second");
  printf("%s\n", words.pop());
}

second

Generic functions over generic structs


struct Box { T value; };

T unbox(Box *b) { return b.value; }

T sum(T[] xs)
{
  T total = 0;
  for (auto x : xs) { total += x; }
  return total;
}

void main()
{
  Box b = {2.5};
  i64 ints[] = {1, 2, 3};
  f64 floats[] = {0.5, 0.25};
  printf("%.1f %d %.2f\n", unbox(&b), sum(ints), sum(floats));
}

2.5 6 0.75

A generic base


struct List { T items[4]; i64 len; };
struct Counted : List { i64 adds; };

void List.add(T x) { self.items[self.len++] = x; }

void main()
{
  Counted c;
  c.len = 0;
  c.adds = 0;
  c.add(10);
  c.adds++;
  printf("%d %d %d\n", c.len, c.items[0], c.adds);
}

1 10 1

The library's generics

The containers are generic: vec.Vec<T>, map.Map<K, V>, set.Set<T>, list.List<T>.


import map, vec;

void main()
{
  ad vec.Vec names = vec.new();
  names.push("ann");
  names.push("bob");
  ad map.Map ages = map.new();
  ages.set("ann", 41);
  for (auto n : names) { printf("%s %d\n", n, ages.getOr(n, -1)); }
}

ann 41
bob -1

Errors are checked per instance

The body is checked for each type it is used with. max of two structs is an error at the >, with a note naming the instance (max<Point>) and the call that asked for it.

In modules and libraries

  • pub works as for any declaration; outside, write coll.Vec<i64> and coll.vecNew<i64>().
  • A library built with -lib keeps its generics as source, and each program makes the instances it uses.

Not yet

  • Constraints on type parameters.
  • Generic enums.
  • Number parameters (Array<T, 16>).
  • A different body for one type (specialisation).
  • Methods with type parameters of their own, void S.f<V>(V x) (an error that says so): a generic struct's methods use its parameters; otherwise write a generic function that takes the struct.
