Command-line flags

flag reads a program's flags as Go's flag package does, with the GNU forms people type too: --port=80, --port 80, -p 80, -p80, -vq for two booleans, Go's -port 80, and -- to end the flags. Flags and arguments may come in any order, and -h prints a help text made from what you declared.


import flag;

void main()
{
  flag.Set *fs = flag.new("server", "serves the API");
  defer fs.free();
  i64 *port = fs.integer("port", 8080, "the port to listen on", 'p');
  bool *verbose = fs.boolean("verbose", false, "log every request", 'v');
  u8[] *db = fs.string("db", "postgres://localhost/app", "the database");

  /* a real program passes main's argc and argv: fs.parseOrExit(argc, argv); */
  u8 *argv[5] = {"server", "-v", "--port=9000", "data.csv", "--db=postgres://db/prod"};
  if (!fs.parse(5, argv)) { return; }
  printf("%d %d %.*s %.*s\n", *port, *verbose, db.len, db.ptr, fs.arg(0).len, fs.arg(0).ptr);

  String help = fs.usage();
  printf("%.*s", help.len, help.ptr);
  help.free();
}

9000 1 postgres://db/prod data.csv
usage: server [flags] [arguments]

serves the API

flags:
  -p, --port int  the port to listen on (default 8080)
  -v, --verbose   log every request
      --db text   the database (default "postgres://localhost/app")
  -h, --help      show this help

Each declaration gives a pointer to the flag's value, which holds the default until parse sets it. The last argument, a character, is the flag's short form (leave it out for none). parseOrExit is what most programs want: -h prints the help and exits 0; a mistake prints what was wrong and the help to stderr and exits 2.

CallWhat it does
flag.new(name, about)A set of flags for a program; fs.free() frees it, its subcommands and the values
fs.boolean, fs.integer, fs.number, fs.string(name, default, help, short): a bool *, i64 *, f64 * or u8[] *
fs.parseOrExit(argc, argv)Parse, or print and exit (0 for -h, 2 for a mistake)
fs.parse(argc, argv)true, or false with fs.error() and fs.helpAsked()
fs.nargs(), fs.arg(i)The arguments that aren't flags ("" past the end)
fs.given(name)Was the flag on the command line (as opposed to its default)?
fs.usage()The help text, a new String
fs.command(name, about), fs.chosen()A subcommand with flags of its own; the one on the command line, or null

Booleans

--verbose turns a boolean on; --verbose=false (or 0, no) turns one off, which is how a flag that defaults to true is cleared. A boolean never takes the next word as its value, so -v file is the flag and an argument.

Subcommands


flag.Set *app = flag.new("app");
bool *dry = app.boolean("dry-run", false, "change nothing", 'n');
flag.Set *serve = app.command("serve", "serves the API");
i64 *port = serve.integer("port", 80, "the port");
flag.Set *migrate = app.command("migrate", "runs the migrations");
app.parseOrExit(argc, argv);         // app -n serve --port 81
if (app.chosen() == serve) { ... *port ... serve.arg(0) ... }

The flags before the subcommand's name are the program's, the ones after it the subcommand's. -h after the name prints the subcommand's help.

Text values are views of argv (or of the default), so there is nothing to free.
