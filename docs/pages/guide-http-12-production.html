12. Production

The last steps from a program on your laptop to a service: HTTPS, a health check for whatever watches it, time limits, and a way to ship and run it that survives restarts and deploys.

Two megabytes, needing only the C library: the standard library, ktm-pg and ktm-migrate are compiled in, and so is TLS. Copy it with the migrations directory and it runs.

HTTPS

Two more settings, the certificate chain and its key as PEM files, and main serves over TLS when they are set:

    if (gSettings.tlsCert.len) {
        log.info("Shelf listening on https://localhost:%d", *port);
        return https.listen((i32)*port, &mux, gSettings.tlsCert, gSettings.tlsKey, db, &o);
    }
SHELF_TLS_CERT=/etc/letsencrypt/live/shelf.example.com/fullchain.pem
SHELF_TLS_KEY=/etc/letsencrypt/live/shelf.example.com/privkey.pem

Behind a load balancer or a proxy that ends TLS (nginx, Caddy, a cloud load balancer), leave them unset: the proxy speaks HTTPS to the world, Shelf plain HTTP to the proxy, and SHELF_TRUSTED_PROXIES (chapter 10) gives the real client addresses back.

Health and time limits

/* GET /health: for the load balancer and the monitoring. 200 while the
 * database answers, 503 when it doesn't (the instance takes no traffic) */
void health(http.Writer *w, http.Request *r)
{
    pg.Pool *db = r.app;
    try {
        pg.Conn *c = db.acquire();
        defer c.release();
        c.setQueryTimeout(1000);        /* a database that doesn't answer in a second is down */
        c.ping();
    } catch (Error e) {
        w.error(503, "the database doesn't answer");
        return;
    }
    w.text(200, "ok");
}
    pg.Options po;
    po.queryTimeoutMs = 5000;           /* no request waits on a query for more than 5 s */
    po.acquireTimeoutMs = 2000;         /* nor 2 s for a connection (the default is 30) */
    pg.Pool *db = pg.open(gSettings.databaseUrl, &po);
  • GET /health is for the load balancer and the monitoring: 200 while the database answers, 503 when it doesn't, so traffic goes to instances that can serve it.
  • Every query has a time limit: a slow query is cancelled on the server and the request gets a 500, instead of waiting forever and holding a connection. The health check's is tighter.
  • So does getting a connection: when the database stops answering (a hung machine, a network split), requests and the health check give up after 2 s instead of piling up. With the database frozen, /health answers 503 within those 2 s, and 200 again once it is back.
  • The server has its own limits for slow clients: a request must arrive within 30 s, an idle kept-alive connection closes after 120 s (http.Options' readTimeoutMs, idleTimeoutMs).

Stopping cleanly

On SIGTERM (what systemd, Docker and Kubernetes send) and Ctrl-C, http.listen stops taking connections, lets the requests in flight finish, waits for background work, and returns; the defers in main close the pool. A deploy that replaces one instance at a time drops no request.

Running it with systemd

[Unit]
Description=Shelf, a bookmarks API
After=network-online.target postgresql.service

[Service]
User=shelf
WorkingDirectory=/opt/shelf
EnvironmentFile=/etc/shelf.env
ExecStart=/opt/shelf/shelf
Restart=on-failure
# SIGTERM: Shelf finishes the requests in flight, then exits
KillSignal=SIGTERM
TimeoutStopSec=30

[Install]
WantedBy=multi-user.target
$ sudo cp shelf /opt/shelf/ && sudo cp -r migrations /opt/shelf/
$ sudo systemctl enable --now shelf
$ journalctl -u shelf -f

/etc/shelf.env holds the same SHELF_* variables as .env, readable only by root and the shelf user. The server migrates the database at start, so a deploy is: copy the new binary and migrations, systemctl restart shelf.

Or in a container

# Build with ktm (it assembles and links with gcc), run on a slim image: the binary needs only libc
FROM debian:trixie AS build
RUN apt-get update && apt-get install -y --no-install-recommends ca-certificates curl unzip git gcc libc6-dev \
 && curl -fsSL https://github.com/ozzenerol/ktm-lang/releases/download/v0.21.0/ktm-v0.21.0-linux-x86_64.zip -o /tmp/ktm.zip \
 && unzip -q /tmp/ktm.zip -d /opt && /opt/ktm-v0.21.0-linux-x86_64/install.sh
WORKDIR /src
COPY . .
RUN ktm build

FROM debian:trixie-slim
COPY --from=build /src/shelf /usr/local/bin/shelf
COPY migrations /app/migrations
WORKDIR /app
USER nobody
EXPOSE 8080
CMD ["shelf"]

ktm compiles to assembly and links with the system's C compiler, so the build stage has gcc; the image that runs has only the binary and the migrations.

$ docker build -t shelf .
$ docker run -p 8080:8080 --env-file .env shelf
