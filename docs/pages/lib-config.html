Settings from the environment

config fills a struct of settings from environment variables, and from a .env file for development. Each field's variable is a prefix and the field's name in SNAKE_CASE: databaseUrl with the prefix APP_ reads APP_DATABASE_URL.


import config, proc, reflect;

enum Level { debug, info, warn };

struct Settings {
  i64 port;
  @required String databaseUrl;
  @env("LOG_LEVEL") Level level;
  bool verbose;
};

void main()
{
  proc.setenv("APP_DATABASE_URL", "postgres://localhost/app");
  proc.setenv("LOG_LEVEL", "warn");
  proc.setenv("APP_VERBOSE", "yes");

  Settings s;
  s.port = 8080;                     /* a default: APP_PORT isn't set */
  config.fromEnv(reflect.of(s), "APP_");
  printf("%d %s %d %d\n", s.port, s.databaseUrl, s.level == Level.warn, s.verbose);
  config.free(reflect.of(s));

  proc.unsetenv("APP_DATABASE_URL");
  proc.setenv("APP_PORT", "80x");
  try {
    config.fromEnv(reflect.of(s), "APP_");
  } catch (Error e) {
    printf("%s\n", e.message);
  }
}

8080 postgres://localhost/app 1 1
config: APP_PORT: `80x` isn't a whole number that fits i64; APP_DATABASE_URL is required

A field keeps what it holds when its variable isn't set (or is set to ""), so defaults are whatever you put in the struct first. fromEnv sets every field it can, then throws config.ERR_CONFIG naming every variable that is missing or wrong, so a deploy shows all of its mistakes at once.

FieldThe variable's text
Integers (i64, i32, u8...)A whole number that fits the field
f64, f32A number: 0.5, 2e3
booltrue/false, 1/0, yes/no, on/off, in any case
An enumA member's name, in any case
StringCopied: config.free(reflect.of(s)) frees the String fields
u8[]A view of the environment's value (valid until that variable changes)
A structIts fields, with its name added: APP_DB_HOST for s.db.host

Attributes

  • @env("NAME"): the field's variable is exactly NAME, without the prefix.
  • @required: fromEnv fails when the variable isn't set.
  • @skip fields and private ones are left alone.

They sit happily with @json and @yaml on the same struct, which json and yaml read and write as before.

Rules

The rules of validate (@min, @max, @oneOf, @email, @url) work on settings too. fromEnv checks them on every field, set or left at its default, and names the variable, so the person starting the program knows what to fix.


import config, proc, reflect;

struct Settings {
  @min(1) @max(1000) i64 maxBookmarks;
  @oneOf("dev", "prod") u8[] mode;
  @url u8[] publicUrl;
};

void main()
{
  proc.setenv("SHELF_MAX_BOOKMARKS", "0");
  proc.setenv("SHELF_MODE", "staging");
  Settings s;
  s.maxBookmarks = 100;
  try {
    config.fromEnv(reflect.of(s), "SHELF_");
  } catch (Error e) {
    printf("%s\n", e.message);
  }
}

config: SHELF_MAX_BOOKMARKS: must be at least 1; SHELF_MODE: must be one of dev, prod
  • A text that isn't set (and has no default) passes its rules; add @required to make it a must.
  • @required keeps config's meaning: the variable must be set (validate's is "not 0 or empty").
  • A value that can't be read (lots for an i64) gets that error, not a rule's as well.

.env files


# .env
export APP_PORT=9000
APP_DATABASE_URL="postgres://localhost/${USER:app}"
APP_GREETING='hello ${not expanded}'
APP_NOTE=plain text  # a comment

config.loadDotenv(".env") sets those variables, except ones the real environment already has (pass true second to override them). "double quotes" take \n, \t, \" and ${NAME} / ${NAME:fallback}, and may run over lines; 'single quotes' are as written. It answers how many variables it set, or -1 when there is no such file, and a line it can't read throws config.ERR_CONFIG with its number. Call it before fromEnv.
