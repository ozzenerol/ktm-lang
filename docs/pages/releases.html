Releases

What changed in each version of ktm. Binaries for Linux x86_64, Linux arm64 and macOS are attached to each release on GitHub.

v0.1.0 (2026-10-10)

Renamed from hcc v0.19.3. The language, the standard library and their behaviour are unchanged; only names are new.

Changes you may notice

  • The compiler is ktm (was hcc). Sources are .ktm, headers .ktmh; .HC and .HH are rejected with a message, on the command line and in #include.
  • The library header is std.ktmh (was tos.HH), the library libktm (was libtos, built with -lib ktm), its sources src/std/.
  • Environment variables, macros and defines are KTM_* (was HCC_*), e.g. KTM_INSTALL_DIR, KTM_TEST_TIMEOUT, __KTM_JIT__; temporary files and the REPL's files are named ktm too (~/.ktm_rc.ktm, ~/.ktm_repl_history).
  • The --terry option is gone; the history and credits are in the README.

hcc (before the rename)

ktm was called hcc up to v0.19.3. Its release notes follow as they were written.

v0.19.3 (2026-10-10)

Fixes from building a shell and a duplicate-file finder with hcc, and stack overflow safety. Tested compiled and in the JIT on Linux x86_64, Linux arm64 and macOS arm64.

Fixes

  • On macOS a program started by ProcSpawn had no stdin, stdout or stderr when they were inherited, the default, so most programs failed there.
  • -jit -Memsafe crashed as soon as a thread allocated memory; it now tracks every thread, and leaks and double frees in threads are reported.
  • A function whose frame is bigger than a page touches each page as it reserves the frame, so a stack overflow in a thread or coroutine (whose guard page is small) crashes instead of silently writing over other memory. Frames up to a page cost nothing extra.
  • ENOENT, EACCES and ECHILD, which the process docs name, were missing. Added with them: ENFILE, EMFILE, EADDRNOTAVAIL, ENETUNREACH, EHOSTUNREACH, and the job-control signals SIGCONT, SIGSTOP, SIGTSTP, SIGTTIN and SIGTTOU, all with each platform's values.

v0.19.2 (2026-10-10)

An important code generation fix found by building a job runner with hcc, and extern function pointers. Tested compiled and in the JIT on Linux x86_64, Linux arm64 and macOS arm64.

Fixes

  • A function with more than about 64 KiB of local variables (U8 buf[65536];) got a stack frame of only the size modulo 65536, so its locals lay below the stack pointer and the next call overwrote them: silent corruption or a crash, on every platform. Frame and local sizes are now 32-bit.
  • extern I64 (*fp)(I64); declares a function-pointer global defined elsewhere, such as a library's public one; it was a syntax error.

v0.19.1 (2026-10-10)

One code generation fix, tested compiled and in the JIT on Linux x86_64, Linux arm64 and macOS arm64.

Fixes

  • A global pointer initialised with a constant address (U8 *p = &g;, &arr[2], arr + 4, &Fn) is written as data the linker relocates instead of being set when Main starts, so a -lib library's pointer globals are no longer NULL.

v0.19.0 (2026-10-10)

The last bugs found while building real programs, and the C transpiler is frozen. Tested compiled and in the JIT on Linux x86_64, Linux arm64 and macOS arm64.

Changes you may notice

  • -transpile is frozen: it stays experimental, supports the language as of this release and gets no new features, so features added later may not translate.
  • Messages, typeof, LSP hover and the REPL call a Bool Bool (they said I8), and converting a pointer to Bool no longer warns, as in C. Converting a pointer to any other integer type still does.

Fixes

  • -transpile dropped every global variable and all code at file scope, so the C didn't compile. Globals are written with their initialisers, file-scope code runs from main first, &Fn is no longer written as a GCC label address, and main's argv is a char **, which clang requires.
  • Taking the address of a parameter that has a default value (&b in F(Bool b = TRUE)) was a compile error.

v0.18.0 (2026-10-10)

Fixes for the bugs found by building two real programs with hcc, an HTTP server and a SOCKS5 proxy. Every fix has a regression test that runs compiled and in the JIT on Linux x86_64, Linux arm64 and macOS arm64, and the known-issues page is empty again.

Changes you may notice

  • Converting a value to Bool gives 0 or 1 (non-zero is TRUE), as in C, for arguments, assignments, initialisers, returns, class fields and casts. Before, only the low byte was kept, so 0x800 became FALSE. Bool is still one byte.
  • Rm and RmDir take their RM_* flags as an I64. As a Bool, RM_VERBOSE was turned into RM_RECURSE by the conversion fix above, so RmDir(dir, RM_VERBOSE) would have deleted recursively.
  • NetAccept returns a blocking socket unless non_blocking is set, on every OS. On macOS it used to inherit O_NONBLOCK from a non-blocking listening socket.
  • A file whose only file-scope code is constant global initialisers (I64 x = 3;) has nothing to run under -jit without a Main, like one with I64 x;.

Fixes

  • On arm64 an initialised global (I32 g = 7;) corrupted Main's argc and argv; on x86_64 the same happened when an initialiser called a function. Constant initialisers are now static data, and the generated main passes argc/argv on.
  • Initialised scalar globals in a library (-lib) were always 0.
  • An I64 global initialiser beyond 32 bits was written wrong in compiled x86_64 code.
  • An I8, U8 or Bool can be an array index or a pointer offset (it was a compile error), with correct sign extension, and the subscript error points at the right line.
  • JsonParse reports an invalid literal such as trux as JSON_INVALID_LITERAL.

v0.17.0 (2026-10-10)

What long-running servers need next: real signal handling with a clean shutdown, and timeouts on TCP. Tested compiled and in the JIT on Linux x86_64, Linux arm64 and macOS arm64.

New

  • SigAction and SigHandle: install a handler, SIG_IGN or SIG_DFL with flags (SA_RESTART, SA_RESETHAND, SA_NODEFER) and a mask of signals blocked while it runs (SigBit(sig)), and get the previous action back to restore it. signal keeps working and the two can be mixed.
  • Clean shutdown: SigStopInit() returns a file descriptor that becomes readable on SIGINT or SIGTERM, to put in a poll loop; SigStopRequested() and SigStopSignal() tell whether and why. A second Ctrl-C ends the program.
  • NetConnect takes an optional timeout_ms: one budget for every address the name resolves to, -1 with Errno() ETIMEDOUT when it runs out. Existing calls are unchanged.
  • NetSetSendTimeout, the counterpart of NetSetRecvTimeout (which works on TCP too): a write stuck on a peer that doesn't read gives up with EAGAIN.
  • raise, kill and the signal names SIGQUIT, SIGALRM, SIGUSR1, SIGUSR2, SIGCHLD.

v0.16.0 (2026-10-10)

Shlurp runs on the new process functions instead of a temporary file. Tested compiled and in the JIT on Linux x86_64, Linux arm64 and macOS arm64.

Changes you may notice

  • Shlurp reads the command's output through a pipe: it no longer needs a writable $TMPDIR (it used to return NULL without one) and never leaves an hcc-shlurp-* file behind.
  • Shlurp returns once the shell exits, without waiting for a background job (cmd &) that still holds its output.
  • Ctrl-C during Shlurp stops the program, as it does anywhere else; before, only the shell was stopped and the program carried on.

v0.15.0 (2026-10-10)

Running programs without a shell, and file descriptors that don't leak into them. Tested compiled and in the JIT on Linux x86_64, Linux arm64 and macOS arm64.

Changes you may notice

  • Every file descriptor the library opens is close-on-exec: FileRead, FileWrite, every Net* socket and accepted connection, and Shlurp's temporary file. Programs started with System, Sh, Shlurp or ProcSpawn no longer inherit them. O_CLOEXEC (and SOCK_CLOEXEC on Linux) are available for your own open and socket calls, which keep C's behaviour.
  • The process functions need glibc 2.34 or newer on Linux.

New

  • Processes: ProcSpawn(argv, opts) starts a program by its argument list, never through a shell, with stdin, stdout and stderr each inherited, piped, sent to /dev/null or (stderr) merged into stdout, plus a working directory, a replacement environment and its own process group. ProcWait, ProcDone, ProcKill and ProcRelease manage it; ProcCommunicate feeds stdin and collects stdout and stderr with poll, so large outputs can't deadlock; ProcRun(argv, &code) returns a program's output, like Shlurp without the shell.

Testing

  • A test still running after HCC_TEST_TIMEOUT seconds (default 60, 0 for no limit) is killed together with everything it started and reported as FAILED ... timed out, so one hanging test no longer stalls the whole suite. Ctrl-C stops a run cleanly.

v0.14.0 (2026-10-10)

The last three known issues are fixed, so the known-issues page is empty. Every fix has a regression test that runs compiled and in the JIT on Linux x86_64, Linux arm64 and macOS arm64. The echo server example added in v0.12.0 has been removed.

Changes you may notice

  • Print statements ("fmt", args;) support the HolyC conversions %Q %D %T %C %F, like StrPrint, and the argument check counts them. In a print statement %F and %C now mean what they mean in StrPrint (a file's contents, an upper-case character), not C's upper-case float and wide character.
  • FileRead reads pipes, FIFOs and /proc files to the end instead of returning NULL; on a FIFO it waits for the writer, and on an endless device such as /dev/zero it never returns.
  • Adding to or deleting from an RBTree or IntSet while iterating stops the iteration (RBIterNext/IntSetIterNext return NULL, RBTreeForEach returns after that callback) instead of overflowing the iterator. Replacing a value doesn't stop it. RBTree, RBIter and IntSetIter have new fields at the end.

New

  • Print(fmt, ...): StrPrint-style formatting straight to stdout, for formats that aren't literals.

v0.13.0 (2026-10-09)

A stricter redeclaration check and two internal fixes, tested compiled and in the JIT on Linux x86_64, Linux arm64 and macOS arm64.

Changes you may notice

  • Defining a function whose name the standard library binds with _extern (on x86_64: Exit, MAlloc, ToUpper, ...) with a different signature is a "conflicting types" error, as it already was for ordinary prototypes. Before, on x86_64 the program's function silently replaced the library's, while arm64 failed later with a confusing type error.

Fixes

  • An internal list merge corrupted memory when the appended list was empty (nothing triggers it since v0.12.0, but it no longer can).

Testing

  • The SQLite leak test no longer fails at random on macOS: the macOS allocator keeps the last freed block counted as in use per CPU, so the check now allows for that while still catching the real leak by a wide margin.

v0.12.0 (2026-10-09)

Compiler crash and warning fixes, a coroutine stack cache, an event-loop example, and SQLite and fuzzy-matcher fixes. Every change has a regression test that runs compiled and in the JIT on Linux x86_64, Linux arm64 and macOS arm64.

Changes you may notice

  • return in top-level code (outside any function) is a compile error, "return outside a function"; it used to crash hcc.
  • SqlExecPrepared returns the SQLite error (SQLITE_MISMATCH for an unknown parameter type) instead of silently running the statement with that parameter missing. SqlPreparedStmt no longer has the unused params_type field.
  • Shlurp writes its temporary file in $TMPDIR (/tmp if unset), like hcc itself.
  • The "control may reach the end of non-void function" warning points at the function name.

New

  • CoroutineRelease keeps up to 16 stacks per thread for the next CoroutineNew of the same size, so short-lived coroutines don't map and unmap a stack each time; the cache is freed when the thread ends.
  • An echo server example (docs/examples/echo): one coroutine per connection driven by a poll loop, with a built-in loopback self-test.

Fixes

  • A goto into a braced block that follows a return crashed the compiler; such blocks are now compiled.
  • A false "control may reach the end of non-void function" warning after a trailing goto, and a missed one after a label that follows a return.
  • FzF gave wrong results when called from several threads at once (the pattern was split with strtok), and allocated and freed a 200 KB buffer it never used on every call.

Testing

  • Tests use their own working directory for temporary files instead of fixed /tmp names, so two full suites can run on one machine at once.

v0.11.0 (2026-10-09)

Coroutines are a library module on Linux x86_64, Linux arm64 and macOS arm64, tested compiled and in the JIT on all three.

Changes you may notice

  • coroutines.HC was a stand-alone x86_64 demo; it is now part of the library with a new API, so code written against the demo (CoroutineInit, the fixed coroutine table, U0 coroutine functions) needs updating.

New

  • CoroutineNew(fn, arg, stack_size), CoroutineNext(c, send), CoroutineYield(value), CoroutineDone, CoroutineSelf and CoroutineRelease. A coroutine function is U0 *fn(U0 *arg); values go both ways (Yield(v) hands v to Next, Next(c, x) makes the paused Yield return x) and the function's return value comes back from the last Next.
  • Each thread has its own coroutines, each coroutine its own catch chain: a try can span a yield, and an uncaught throw in a coroutine is rethrown by the CoroutineNext that resumed it.
  • Stacks are 256 KiB by default, with a guard page the size of a real memory page (16 KiB on macOS arm64), so an overflow crashes instead of overwriting memory.

Fixes

  • A coroutine finishing entered its exit code with a misaligned stack on x86_64.

v0.10.0 (2026-10-09)

UDP and the networking basics. Every change has a regression test that runs compiled and in the JIT on Linux x86_64, Linux arm64 and macOS arm64.

Changes you may notice

  • Socket address and option lengths are U32, like C's socklen_t: accept, getsockname, getpeername, recvfrom and getsockopt take a U32 *, and connect, bind, sendto and setsockopt a U32. Passing an I64 length variable still works but gives an "Incompatible function argument" warning; declare it U32.

New

  • UDP helpers: NetCreateUdpSocket, NetSendTo, NetRecvFrom (IPv4 and IPv6, the sender's address and port as text), NetSetRecvTimeout and NetGetSocketPort.
  • Htons, Ntohs, Htonl, Ntohl.
  • Errno() and SetErrno(), with the common error names (EAGAIN, EINTR, EPIPE, ECONNREFUSED, ...) at the right values on Linux and macOS.
  • MSG_* flags (including MSG_DONTWAIT and MSG_NOSIGNAL), SHUT_*, SO_RCVTIMEO and friends, IPV6_V6ONLY, poll with pollfd, and signal with SIGPIPE, SIG_IGN and the other common signals.
  • NetSend: a send that returns -1 with Errno() EPIPE when the peer has closed, instead of a SIGPIPE that ends the program.

Fixes

  • Writing to a socket whose peer had closed killed the program, with no way around it (known issue removed): use NetSend, MSG_NOSIGNAL or signal(SIGPIPE, SIG_IGN).
  • timeval.tv_usec was 4 bytes on Linux, where C uses 8: a timeval passed to setsockopt(SO_RCVTIMEO) could carry garbage in the upper half and be rejected.

v0.9.2 (2026-10-09)

Parallel compiles and a much faster test suite.

Fixes

  • hcc wrote every compile's intermediate assembly to the same file, /tmp/holyc-asm.s, so two compiles at the same time could produce each other's program or fail. Each compile now uses its own temporary file in $TMPDIR (/tmp if unset), removed when hcc exits, also on an error or a signal. The -run binary is created there too.

Testing

  • ./build.sh --test runs the unit, JIT and LSP tests in parallel, JOBS at a time (default: one per CPU), each test in its own directory. The full suite takes about 12 seconds on Linux, down from about 30-40.

v0.9.1 (2026-10-09)

Three compiler fixes, and the SQLite bindings and fuzzy matcher fixed and documented. Every fix has a regression test that runs compiled and in the JIT on Linux x86_64, Linux arm64 and macOS arm64.

Changes you may notice

  • A goto into a try body from outside it is a compile error (it used to corrupt the exception chain). Jumping within a body, out of it, or into a catch handler is fine.
  • SqlQuery, SqlSelect and SqlPrepare reject a string with more than one statement; SqlExecRaw still runs them all. SqlPrepare returns NULL on an error, and SqlExecRaw returns the error message (a string to Free) or NULL.
  • SqlRow has a new field, owns_stmt.

Fixes

  • continue inside a switch inside a loop crashed the compiler.
  • A false "control may reach the end of non-void function" warning when both a try body and its catch end in return.
  • SQLite: text and blob parameters were bound without a copy, so freeing them before reading the rows was a use-after-free; NULL parameters were rejected; releasing a row from a prepared statement finalized the statement; column arrays, failed opens and busy closes leaked; column lengths were uninitialised. SQL_INT, SQL_TEXT and the other type constants are available to programs.
  • Fuzzy matching: exact ('foo) and inverse (!foo) terms only worked for one character, ^prefix and ^exact$ terms were wrong, FzF wrote into the caller's pattern (a crash for string literals), and parsed terms leaked.
  • The unused builtins.HC is removed.

Still open: see Known issues.

v0.9.0 (2026-10-09)

A systems and networking release. Exceptions, sockets and threads were audited and every bug found is fixed, with a regression test that runs compiled and in the JIT on Linux x86_64, Linux arm64 and macOS arm64. macOS on Intel is no longer a supported target.

Changes you may notice

  • Fs is per thread: it is now a function, HCFs *Fs(). Code that reads Fs->except_ch or Fs->catch_top compiles unchanged.
  • An uncaught throw prints to stderr, as text when every byte is printable (uncaught throw: 'Late') and as a number otherwise. The exit code is still 1.
  • throw converts its value to U64 like a normal argument, so throw(42.75) throws 42.
  • NetCreateServer honours addrfam (AF_INET, AF_INET6, AF_UNSPEC; "::*" is any IPv6 address) and its bind address must be numeric: "localhost" gives -1. NetConnect connects over IPv4 or IPv6 and tries every address a name resolves to.
  • Ports outside 0-65535 give -1 instead of being truncated.
  • NetCreateUnixServerSocket only replaces a stale socket: a file, a directory or a socket another server is listening on makes it fail.
  • ThreadPoolNew returns NULL for a count of 0 or less, or when a thread can't be created.
  • pthread_create returns an I32.

Fixes

  • Leaving a try with return, break, continue or goto left its frame on the exception chain: the next throw crashed or looped forever.
  • try/catch in two threads at once crashed ("stack smashing detected").
  • throw of an F64 passed garbage.
  • On Linux arm64 the pthread attribute types were too small, so pthread_attr_init wrote past them.
  • ThreadPoolNew ignored pthread_create failures and ThreadPoolRelease then crashed; ThreadPoolEnqueue, Wait and Stop accept a NULL pool.
  • NetCreateServer and NetConnect ignored addrfam and only did IPv4.
  • NetGetIpv4AddressFromAcceptedSocket returned garbage for IPv6 peers.
  • msghdr had the wrong layout, so sendmsg could fail.
  • NetCreateUnixServerSocket deleted whatever was at its path, including regular files and a live server's socket.
  • NetConnect gave up after the first address that refused.
  • coroutines.HC (a stand-alone x86_64 demo) crashed on first use; its stacks are aligned now and have a guard page.

Still open: see Known issues. Writing to a socket whose peer has closed still raises SIGPIPE, which ends the program; that is next.

v0.8.0 (2026-10-09)

A standard-library release. Memory, maths, sets, bit vectors, files, directories, the shell helpers, CSV and dates were audited like strings and JSON before them: the code was read against its documentation, random tests were checked against Python, plus valgrind and worst-case inputs. Every bug found is fixed and every function in these modules is documented. Every fix has a regression test that runs both compiled and in the JIT, on Linux x86_64, Linux arm64 and macOS.

Changes you may notice

  • MkDir returns 0 when the path is a directory afterwards and -1 otherwise, in both modes, like Rm and RmDir. The recursive mode used to return TRUE on success.
  • FileWrite truncates the file by default, so a shorter write no longer leaves the old tail behind. A NULL buffer or a negative size returns FALSE without creating the file.
  • FileRead reads only regular files: a directory, device or FIFO gives NULL (/dev/null used to give ""), and *_size is 0 on every failure.
  • Dir returns -1 when the path can't be opened as a directory, so an error differs from an empty directory, and lists entries it can't Stat (dangling symlinks).
  • Sh and Shlurp always format their command, also without extra arguments: %% is now % in both cases.
  • Abs returns an I64 (it was a U64, so Abs(x) > -1 was false). Abs(I64_MIN) is I64_MIN, like C's labs.
  • Pow takes an F64 exponent: Pow(4.0, 0.5) is 2.0 (the exponent used to be truncated to an integer). Integral exponents still use exact repeated squaring; one beyond 253 is rounded when it becomes an F64, so Pow(-1, I64_MAX) is now 1.0.
  • CDate uses the proleptic Gregorian calendar. Dates from 4000-03-01 on, and in year 0 and before, move by a day (4000-02-29 exists now); years 1 to 3999 keep their day numbers. A CDate of 0 prints as 01/02/0000.
  • Struct2Date carries out-of-range fields all the way: month 13 is January of the next year and hour 24 midnight of the next day.
  • Str2CDateStruct sets zone_diff to CDATE_NO_ZONE, not -1, when there is no %z, and rejects offsets with hours past 23 or minutes past 59.
  • BitVecSet returns a Bool.

New

  • Bit vectors: BitVec works and is part of the library (it was broken in every operation and couldn't be included).
  • ShQuote(s) quotes text for Sh and Shlurp.
  • M_PI, M_E and the other maths constants are available to programs.
  • CDATE_NO_ZONE.

Fixes

  • Shrinking a block with ReAlloc wrote past the new block (x86_64).
  • MAlloc, CAlloc and ReAlloc crashed when memory ran out and returned a tiny block for sizes near U64_MAX; they return NULL, and ReAlloc keeps the old block.
  • MemSet and MemCpy return dst.
  • Pow(x, I64_MIN) returned 1.0.
  • RBIter in tos.HH was bigger than what the library allocates.
  • IntSetToString was quadratic (500,000 elements: 24 s to under 0.1 s).
  • The IntSet and RBTree functions accept a NULL set or tree.
  • Rm and RmDir with RM_RECURSE followed a symlink to a directory and deleted what was inside it; they remove the link.
  • Rm with any flag didn't delete files, RM_FORCE did nothing, and Rm/RmDir printed without RM_VERBOSE and reported quiet successes as errors.
  • Recursive RmDir stopped at sockets, FIFOs and devices, and recursed forever on filesystems that don't report entry types.
  • Recursive MkDir overflowed a stack buffer on long paths.
  • FileRead on a directory crashed.
  • Free(Pwd()) aborted the program.
  • Dir sorted names starting with the same number in no order, overflowed on huge numbers and was quadratic (20,000 files: 1.6 s to 37 ms). Dir(NULL) and RmDir(NULL, RM_RECURSE) crashed.
  • Shlurp("") or a command ending in a backslash gave a shell syntax error.
  • Date2Struct gave "December 32" for some January 1sts (1904, 1908, ...).
  • Now() counted the sub-second part twice, ran up to 2 s fast and went back to the start of the day just before midnight; zone_diff is set now.
  • Struct2Date read past its month tables for months outside 1-12.
  • StrPrint and MStrPrint with an empty result returned a string without its terminating NUL, so junk could follow it (and Shlurp("") ran it on arm64).
  • On Linux arm64, cStat had the x86_64 layout, so stat results were read from the wrong offsets.

Still open: see Known issues.

v0.7.0 (2026-10-09)

A JSON release. The JSON module was audited like strings, hash tables and lists: conformance cases from the JSON specification, random documents checked against Python's json, valgrind and worst-case inputs. Every bug found is fixed and the module is fully documented. The library also stops exporting its internal helpers. Every fix has a regression test that runs both compiled and in the JIT, on Linux x86_64, Linux arm64 and macOS.

Changes you may notice

  • JsonParse follows RFC 8259 strictly. These are now errors: invalid numbers (-, 01, +1, .5, 0x1F, 1e), anything after the top-level value ([1]x, 1 2), anything but whitespace between a key and its :, raw control characters in strings, \v and \f as whitespace, and nesting deeper than 512 (JSON_MAX_DEPTH). They used to be accepted and turned into wrong values.
  • Integers outside the I64 range become F64 (JSON_FLOAT) instead of silently capping; infinity and NaN are written as null; floats are written with 15 to 17 significant digits.
  • JsonToString of a selected node writes only that node (it also wrote the node's key and every following sibling). JsonRelease only acts on a document root: on NULL or a selected node it does nothing, where it used to free the siblings and corrupt the tree.
  • Error messages give a line and column; JsonGetStrerror and JsonPrintError are NULL-safe. New error codes JSON_INVALID_LITERAL, JSON_INVALID_CONTROL_CHARACTER and JSON_NESTING_TOO_DEEP.
  • The Json class has two new fields at the end, str_len and key_len, so strings containing \u0000 keep all their bytes.
  • libtos exports exactly what tos.HH declares. A program can no longer replace a library helper by accident, but a program that called an undeclared library function must declare its own. static functions and file-scope static variables are local to their file.

New

  • JsonObjectGet(obj, key), JsonArrayGet(arr, i) and JsonLen(node), which also reach keys a selector path can't spell.

Fixes

  • Strings ending in a backslash ({"path":"C:\\"}) parse.
  • JsonParse stays within len (it read past the buffer and accepted truncated strings), and JsonParse(NULL) returns NULL.
  • JsonSelect: the * wildcard after . works (.*, .price_*); paths ending in . or [ no longer read past their end; junk like [1abc] or :ixyz is rejected; NULL arguments return NULL.
  • Writing floats is about 100 times faster (500,000 floats: 70 s to 0.7 s).
  • The JSON documentation is complete, with examples that free what they allocate.

Still open: see Known issues.

v0.6.0 (2026-10-09)

A standard-library release. Strings, hash tables, lists and vectors were audited with random tests against reference models, valgrind and worst-case inputs; every bug found is fixed, the missing basics are added and every function is documented. Plus four compiler fixes. Every fix has a regression test that runs both compiled and in the JIT, on Linux x86_64, Linux arm64 and macOS.

Changes you may notice

  • Vector Get and the new Set check the index: out of range prints the function, index and size and exits with status 1 (it returned whatever was in memory).
  • StrPrint and friends accept C's flags (-0+ #), length modifiers (l ll h hh z j, all 64-bit), %i, %o and integer precision (%.3d is 007); %.*d is a precision, as in C. An unsupported conversion is printed as written, warns on stderr and still uses its argument; the compiler's format check knows the HolyC conversions (%Q %D %T %C %F) and warns about unknown ones.
  • Str2CDateStruct and StrToCDate reject empty, partial and out-of-range input (they returned success with garbage fields); %a, %b and %p work, and missing seconds are 0.
  • StrNCpy copies at most len bytes and stops at the end of the string (like strndup); MPrintQ/%Q escape control bytes as \xNN; StrHash values changed (an empty string hashes to 0).
  • String functions, maps and lists accept NULL instead of crashing (NULL compares before every string).

New

  • StrNPrint(dst, size, fmt, ...): bounded formatting with snprintf semantics.
  • Maps: an optional Bool *_ok on IntMapGet/StrMapGet to tell a missing key from a stored 0, IntMapClear and StrMapClear.
  • Lists: ListClear, ListRemove, ListFirst, ListLast. Vectors: IntVecSet/FloatVecSet/PtrVecSet and ...VecLast; the ok flag of Pop is optional.
  • strncasecmp and atol are declared for programs.

Fixes

  • Strings: a trailing % read past the format; an unsupported conversion shifted the later arguments (and could crash); StrTrimEnd wrote before an empty or blank string; CatLenPrint leaked and overflowed by one byte; WildMatch got simple globs wrong; SPutChar and StrNCpy memory errors. StrLen is about 5x faster and StrPrint output grows 2x instead of 10x.
  • Hash tables: "" as a key, StrMapGetLen/HasLen on part of a string, integer keys sharing their low bits (quadratic), similar string keys clustering, IntMapNew(-1) corrupting the heap, a key that is also its value freed twice.
  • Lists and vectors: IntVecNew(0) and FloatVecNew(0) overflowed on the first pushes, PtrVecNew ignored its size, FloatVecSort did nothing, sorting sorted or repeated data was quadratic and crashed at 100,000 elements, merging an empty list linked freed memory into the other.
  • JSON: JsonRelease and parse errors leaked.
  • Compiler: a narrow (I32, U16, ...) call result used directly in an expression wasn't extended (strcmp("a", "b") < 0 was false); &labs and other external function addresses failed to link; a lone ; ended a function body; an error in an if condition gave a second, bogus error on its else; sizeof() crashed; if (), switch () and while () are errors; the transpiler keeps strings pasted with macros.

Still open: see Known issues.

v0.5.0 (2026-10-09)

The C transpiler checks programs before translating them, and the last v0.4.0 known issues are fixed. Every fix has a regression test that runs both compiled and in the JIT, on Linux x86_64, Linux arm64 and macOS.

Changes you may notice

  • A class value in a local declaration of another type is an error, as it already was for assignments and globals: I64 z = p; stored the class's address, and Q q = p; between different classes copied bytes silently (reading past the source when Q is larger). To reinterpret a class on purpose, go through a pointer: Q q = *(&p)(Q *);.
  • -transpile checks the program first, like -jit: on an error it prints the diagnostics and exits 1 without writing C (it used to write C with the bad statements left out, or crash). It also prints the program's warnings, and needs the same -D defines as a compile.
  • Error messages show string and character constants as written, with their quotes ('\n', "abcd").

Fixes

  • I64 v = ; is an error instead of a crash.
  • A function pointer without a name (I64 (*)(I64 x);) gives one error, and parsing continues correctly after it.
  • The transpiler brackets casts in its C, so p(I64 *)[1] and (a + b)(F64) keep their meaning.

Still open: see Known issues.

v0.4.0 (2026-10-09)

Every known issue from v0.3.0 is fixed: two wrong-code bugs, standard-library fixes for threads, trees, processes, sockets and JSON, and diagnostics that point at the right place. The old x86 backend is gone. Every fix has a regression test that runs both compiled and in the JIT, on Linux x86_64, Linux arm64 and macOS.

Changes you may notice

  • --use-legacy-x86 is removed: the old AST-based x86_64 code generator had several wrong-code bugs, and the flag is now an error.
  • System and Sh return the command's exit code (0 to 255), or -1 if it was killed by a signal or couldn't run; they used to return the raw wait status (System("exit 3") was 768). System(NULL) returns -1.
  • NetSetSocketNoDelay returns TRUE on success; it returned the opposite.
  • A definition keeps its prototype's default arguments; giving the same parameter a different default in both is an error.
  • JsonParse honours JSON_STRNUM_FLAG: numbers are kept as their source text.
  • A function pointer can be called through *: (*fp)(), as in C.
  • RBTree is 8 bytes larger (each tree has its own sentinel node).

Fixes

  • Classes of any size from 1 to 16 bytes are passed and returned by value correctly. Odd sizes (3, 5 to 7, 9 to 15 bytes) overwrote neighbouring memory on x86_64 and didn't compile on arm64.
  • A class item in a local initialiser list (L l = {1, p0, 4};) is copied; it was garbage.
  • ThreadPoolRelease no longer hangs; queued jobs still run before it returns.
  • RBTreeRelease frees the tree and calls the key and value free functions; replacing a value frees the old one. Trees used on different threads no longer corrupt each other.
  • An asm {} block no longer breaks the parsing of the code after it, depending on where it sat in the file.
  • The C transpiler writes array members with their element count and indexing as a[i].
  • Cross-compiling for macOS from Linux (--target=*-apple-darwin) assembles.
  • Diagnostics at the right place: a wrong argument type at the argument, a class initialiser warning at its item, a missing name after a comma at the bad token. A class assigned to an integer is reported once, the underline under strings includes the quotes, and the U0 return warning prints the expression as written.

Still open: see Known issues.

v0.3.0 (2026-10-09)

A wrong-code fix in the optimiser, library functions you can redefine, new warnings for mistakes hcc used to accept silently, and three fewer ways to crash the compiler. Every fix has a regression test that runs both compiled and in the JIT.

Changes you may notice

  • Conflicting declarations of a function are an error ("conflicting types"), also against the standard library's prototypes. Programs that declared a library function with a different signature used to compile and now don't.
  • New warnings: a number with a leading zero (0644 is decimal 644, not octal), a pointer converted to one of a different scalar type (I64 *q = &f with F64 f), and a pointer difference stored back into a pointer (q -= q). -Werror makes them errors.
  • Redefining a library function (your own Now()) works in compiled programs too; it used to fail to link. Library functions are now weak symbols in libtos.

Fixes

  • Copying a pointer and then reassigning the original no longer changes the copy (I64 *z = v; v = &x; made *z read x, or crash once v was NULL).
  • A U0 * compares with a function pointer using == and !=.
  • No more crashes on I64 a[; or on * applied to something that isn't a pointer (1 +* 2); both are normal errors.
  • A stray ; at the top level (I64 x = 1;;) is accepted instead of swallowing the next declaration; in the REPL it also no longer breaks later results.
  • The C transpiler writes classes and unions after the types they contain and turns F32 into float.
  • The standard library's own prototypes now match their definitions (ListDeque, ListPop, StrMapSet, FzFGetScore).
  • The LSP tests take seconds instead of over a minute.

Still open: see Known issues.

v0.2.0 (2026-10-09)

Networking and parser fixes: sockets now work the same on Linux and macOS, and five more compiler bugs are gone, each with a regression test.

Changes you may notice

  • NetAccept returns an I32: the new socket, or -1 on failure (it used to return a value you couldn't check).
  • \x in strings and character constants takes at most two hex digits, as in C, so "\x01b" is the bytes 1 and 'b', the same in AOT and the JIT.
  • sizeof of a string literal always counts its terminating NUL (sizeof("\xa3\xFF") is 3).

Fixes

  • Socket address layouts and constants follow the platform: sockaddr layouts, the Linux TCP_* options, AI_NUMERICSERV; IPPROTO_* are exported.
  • The arm64 JIT sign-extends I32 locals at large frame offsets (negative values read back as large positive ones).
  • A modulo or division by a variable inside an array subscript no longer crashes hcc; division or modulo by a constant 0 is reported as an error.
  • Two bad statements in a row no longer crash hcc; error recovery skips a stray } at the top level.
  • Brace elision works for class-typed and array fields of initialiser lists (Q q = {1, 2, 3}; where the last field is a class).
  • String escapes are emitted so the assembler can't misread them, so AOT and JIT strings are byte-for-byte the same.
  • Character constants accept every escape strings do: '\b' is 8, not 92.
  • make build works, and make no longer copies build.sh over the build directory.
  • The test suite runs on macOS, which has no timeout command.

Still open: see Known issues.

v0.1.0 (2026-10-09)

The first release of this fork, which is developed independently of Jamesbarford/holyc-lang (it continues from upstream v0.0.15-beta). It is mostly about correctness: 120 fixes, each with a regression test that runs both compiled and in the JIT.

Highlights

  • Wrong code fixed: loads through pointer arrays, global initialisers laid out at their field offsets and zero-filled, int/float conversions on return, assignment and intrinsic classes, return f(); in U0 functions no longer dropped, &&/||/! on floats and pointers, comparisons with the pointer on the right, register clobbering in indexed loads on arm64 and x86_64, stack-passed parameters.

  • Language: nested #if handled properly, #undef applied in order, #define line continuation and float typing, function-pointer arrays and file-scope function pointers, nested/union/string initialisers, calling a function without parentheses anywhere in an expression, C precedence for prefix operators.
  • Diagnostics at the right place: macro uses, directives, tabs and non-ASCII text, argument counts; clear messages for malformed numbers and unknown characters.
  • Standard library: JSON \u escapes, top-level values and round-tripping; IntSet, CatPrint, FileRead, RBTreeDelete and %d of the smallest I64 fixed.
  • Building and testing: ./build.sh builds into a local prefix and runs the suites; docker/test.sh tests x86_64 and arm64 Linux; documentation with checked examples, published at ozzenerol.github.io/holyc-lang.
