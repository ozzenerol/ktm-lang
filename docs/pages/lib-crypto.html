Cryptography

crypto has what applications need, built on mbedTLS's vetted code (inside ktm, as for TLS): secure random bytes, hashes and MACs, key derivation, authenticated encryption, and ECDSA, RSA and Ed25519 signatures. Only programs that import it carry it.

Random bytes


u8 key[32];
crypto.random(key[0:]);                  // keys, nonces, salts
String token = crypto.randomBytes(24);   // a session token's bytes (base64.encodeUrl for text)

Hashes, MACs, keys from secrets

Encrypting

seal encrypts and authenticates: open refuses anything altered, and anything sealed with another key, nonce or aad (data sent in the clear but bound to it, as a header). A key is 32 bytes, a nonce 12: never use one nonce twice with a key, so make it with crypto.random and send it along.


u8 key[32], nonce[12];
crypto.random(key[0:]);
crypto.random(nonce[0:]);
String box = crypto.seal(crypto.Aead.aesGcm, key[0:], nonce[0:], "attack at dawn", "msg-7");
String plain;
if (!crypto.open(crypto.Aead.aesGcm, key[0:], nonce[0:], box, &plain, "msg-7")) {
  // altered, or not ours
}

Aead.aesGcm is AES-256-GCM (fastest where the CPU has AES instructions), Aead.chacha20Poly1305 is ChaCha20-Poly1305 (fast everywhere). seal adds crypto.TAG_SIZE (16) bytes.

Signatures


crypto.Key *k = crypto.generateKey();             // ECDSA P-256
String sig = k.sign("payload");                   // 64 bytes r||s (JWT's ES256), deterministic
bool ok = k.verify("payload", sig);              // also takes a DER signature
String pem = k.publicPem();                       // to share; privatePem() to keep
crypto.Key *other = crypto.publicKey(pem);        // and back (privateKey(pem) for a private one)

RSA keys (2048 bits or more) work the same way: crypto.generateRsaKey() makes one, and privateKey and publicKey read either kind from PEM. signWith and verifyWith pick the digest:


crypto.Key *rk = crypto.privateKey(rsaPem);
String rs = rk.signWith(crypto.Hash.sha384, "payload");   // PKCS#1 v1.5 (JWT's RS384)
bool good = rk.verifyWith(crypto.Hash.sha384, "payload", rs);
if (rk.kind() == crypto.KeyKind.rsa) { printf("%d bits\n", rk.bits()); }

Ed25519 keys (RFC 8032) sign with sign and check with verify: the algorithm hashes the data itself.


crypto.Key *ek = crypto.generateKey(crypto.KeyKind.ed25519);
String es = ek.sign("payload");                  // 64 bytes, deterministic (JWT's EdDSA)
bool fine = ek.verify("payload", es);
  • sign and verify are signWith and verifyWith with crypto.Hash.sha256: ES256 for a P-256 key, RS256 for an RSA one. For an Ed25519 key they are Ed25519 itself, and signWith/verifyWith throw.
  • P-384 and P-521 keys (crypto.generateKey(crypto.KeyKind.ec384), ec521, or from PEM) sign with signWith, usually over Hash.sha384 and Hash.sha512 (JWT's ES384, ES512).
  • An RSA key also signs with RSA-PSS: signPss(h, data) and verifyPss(h, data, sig), MGF1 with the same hash and a salt as long as the digest (JWT's PS256, PS384, PS512). PSS is randomised: two signatures of the same data differ, and both verify.
  • An EC signature is r||s: 64 bytes for P-256, 96 for P-384, 132 for P-521; an RSA one is the key's size (256 bytes for 2048 bits). verifyWith also takes the DER form.
  • A public key also comes from its parts, as a JWK has them (base64url-decoded): crypto.ecPublicKey(x, y) (32, 48 or 66 bytes each: the curve follows), crypto.rsaPublicKey(n, e) (big-endian) and crypto.ed25519PublicKey(x) (32 bytes). k.ecPoint(&x, &y) gives an EC key's back.
  • Keys are readable and writable as PEM, so they work with OpenSSL and other languages; an Ed25519 key is read only in the exact form RFC 8410 gives (PKCS#8, or SubjectPublicKeyInfo). Other kinds of key (secp256k1, P-224, RSA under 2048 bits) are refused.
  • Ed25519 is Monocypher's (mbedTLS 3.6 has none), inside ktm as mbedTLS is.

Passwords


import crypto;

void main()
{
  String stored = crypto.hashPassword("hunter2");   /* save this whole string */
  printf("%.31s...\n", stored.ptr);
  printf("%d %d\n", crypto.verifyPassword("hunter2", stored), crypto.verifyPassword("hunter3", stored));
  printf("%d\n", crypto.needsRehash(stored));
  stored.free();
}

hashPassword is Argon2id with a random salt, at OWASP's cost (19 MiB, 2 passes, about 20 ms), written as a PHC string that carries its own cost and salt, so other languages' libraries read it too. verifyPassword also reads bcrypt hashes ($2a$, $2b$, $2y$), so users moved from another system keep their passwords; needsRehash says when a hash that just verified should be replaced by a new one.

CallWhat it does
crypto.hashPassword(pw)Argon2id at the default cost, a new String
crypto.argon2id(pw, memoryKiB, iterations, parallelism)The same at a cost of your own
crypto.bcrypt(pw, cost)$2b$, cost 12 unless given; throws for a password over 72 bytes
crypto.verifyPassword(pw, hash)Either kind; false for a wrong password or a hash it can't read
crypto.needsRehash(hash)true for bcrypt and Argon2id at another cost
crypto.argon2idKey(pw, salt, memoryKiB, iterations, parallelism, out)Argon2id as a key derivation, into out
crypto.blake2b(data, out)BLAKE2b, a 1 to 64 byte digest

Hashing a password takes the time and memory it does on purpose. Inside a coroutine (a net.http handler, say) the hashing calls run on coro.offload's worker threads, so the loop goes on serving other requests meanwhile.

Notes

  • What randomBytes, seal, sign and the PEM calls return is yours to free; open replaces what plain held. Free keys with k.free().
  • Errors (a key of the wrong size, a bad PEM) throw crypto.ERR_CRYPTO; a failed open or verify is just false.
