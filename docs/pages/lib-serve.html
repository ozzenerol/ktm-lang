Serving on every core

coro.serve is a whole TCP server in one call: one coroutine loop per core, and your handler runs as a coroutine for each client.

At a glance

void handle(i32 fd, void *arg) { ... coro.read(fd, ...); coro.write(fd, ...); }

coro.serve(8080, &handle);                         // every IPv4 address, one loop per CPU
coro.serve(8080, &handle, arg, 4, "127.0.0.1");    // 4 loops, loopback only
coro.serveStop();                                  // from any thread or coroutine

A complete server

Here the clients run as a coroutine in the calling thread's loop, then stop the server.


import atomic, coro, cstr;

i64 gServed = 0;

void handle(i32 fd, void *arg)
{
  u8 buf[256];
  i64 n = coro.read(fd, buf, 5000);
  if (n <= 0) { return; }
  for (i64 i = 0; i < n; i++) {
    if (buf[i] >= 'a' && buf[i] <= 'z') { buf[i] -= 32; }
  }
  coro.write(fd, buf[0:n]);
  atomic.add(&gServed, 1);
}

void *clients(void *unused)
{
  u8 *words[] = {"ping", "hello", "ktm"};
  for (auto w : words) {
    i32 fd = coro.dial("127.0.0.1", 18631, 5000);
    coro.write(fd, cstr.view(w));
    u8 buf[64];
    i64 n = coro.read(fd, buf, 5000);
    printf("%s -> %s\n", w, buf[0:n]);
    coro.close(fd);
  }
  coro.serveStop();
  return null;
}

void main()
{
  coro.go(&clients);                       // runs in this thread's loop
  i32 r = coro.serve(18631, &handle, null, 2, "127.0.0.1");
  printf("serve returned %d, served %d\n", r, atomic.load(&gServed));
}

ping -> PING
hello -> HELLO
ktm -> KTM
serve returned 0, served 3

Arguments

ArgumentDefaultMeans
portThe TCP port
handlervoid handler(i32 fd, void *arg), run once per client
argnullPassed to every handler
threads0The number of loops; 0 is one per CPU the process may use
bindaddr"*""*", "::*" or a numeric address, as for net.listen
  • The calling thread runs one of the loops, so serve returns only when the server has stopped. Call it from a thread, not a coroutine.
  • It returns 0 once stopped and every handler has finished, or -1 with os.errno() when it can't listen (port in use, bad address).
  • The client's fd is non-blocking with TCP_NODELAY. Use coro.read and coro.write, and don't close it: serve does when the handler returns.
  • A handler that throws is reported on stderr and the server goes on.

Handlers run on several threads at once. A global they share (a counter, a cache, a map) needs the atomic module or a lock, as gServed above. The coroutines of one loop never run at the same time.

Stopping

  • coro.serveStop() stops every running serve, from any thread or coroutine (not from a signal handler).
  • A coro.stop() in one of its loops stops the whole server the same way.
  • Each loop stops taking clients, the handlers in flight finish, then serve returns 0.

For Ctrl-C, start the signal coroutine with coro.go before calling serve.

How clients are spread

On Linux each loop has its own listener on the port (SO_REUSEPORT) and the kernel shares the connections out. On macOS the loops share one listener, and each takes the clients it wins the accept for.
