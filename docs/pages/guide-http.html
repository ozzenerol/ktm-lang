HTTP programming

One project, from a ten-line server to an API you could run in production: Shelf, a bookmarks service. People save links, tag them, search them and share collections. Each chapter adds one thing and ends with a program that runs.

What you build

RequestWhat it does
POST /bookmarksSave a link
GET /bookmarksYour links, newest first, a page at a time; ?tag=, ?q= to filter and search
GET /bookmarks/{id}, PATCH, DELETEOne link
POST /users, POST /sessionsSign up, log in
GET /collections/{id}A shared collection, readable by anyone with the link

The chapters

  1. Hello, Shelf: a project, a mux, a handler, curl.
  2. JSON in and out: @json structs, routes with parameters, status codes.
  3. Validation and errors: rules on fields, 400, 409, 422.
  4. Configuration: flags, environment variables, .env, logging.
  5. PostgreSQL: ktm-pg, a connection pool, queries.
  6. Migrations: the schema in versioned files.
  7. Tags, search and pages: transactions, full-text search, cursors.
  8. Users and sessions: passwords, tokens, each user's own bookmarks.
  9. Sharing: collections anyone with the link can read, permissions in SQL.
  10. Middleware: request IDs, CORS, rate limits (coming).
  11. Testing: ktm test (coming).
  12. Production: HTTPS, deployment, graceful shutdown (coming).

Before you start

  • ktm 0.21 or newer (Getting started) and curl.
  • From chapter 5: PostgreSQL. Any recent version; with Docker, docker run -d -p 5432:5432 -e POSTGRES_PASSWORD=shelf postgres:17.
  • You know some C or another C-like language. The guide explains the ktm parts as they come.
