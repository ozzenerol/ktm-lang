HTTP servers

net.http serves REST APIs the way Go's net/http does: a Mux sends each request to a handler by method and path, and a handler writes the reply. It runs on coro.serve, a coroutine per connection on every core.

A first API


import json, net.http, reflect, str;

@json struct User { i64 id; String name; };

void getUser(http.Writer *w, http.Request *r)
{
  User u = {7, str.from(r.param("id"))};
  defer u.name.free();
  w.json(200, reflect.of(u));
}

void createUser(http.Writer *w, http.Request *r)
{
  User u = http.decode(r);    // bad JSON: the server answers 400 itself
  u.id = 42;
  w.json(201, reflect.of(u));        // u is freed when the handler returns
}

i32 main()
{
  http.Mux mux;
  mux.handle("GET /users/{id}", &getUser);
  mux.handle("POST /users", &createUser);
  return http.listen(8080, &mux);    // Ctrl-C: finishes the requests in progress, returns 0
}

$ curl -d '{"name":"Ada"}' localhost:8080/users
{"id":42,"name":"Ada"}
$ curl -d '{"name":' localhost:8080/users
{"error":"1:9: name: expected a string, got the end of the input"}

Routing

An http.Mux sends each request to the handler of the pattern that matches it, the way Go 1.22's ServeMux does. Declare one (http.Mux mux;: no setup call) and add routes with mux.handle(pattern, &handler). A pattern is [METHOD ]/path:

PatternMatches
/health/health, any method
GET /users/{id}/users/7 by GET or HEAD; r.param("id") is "7"
/files/{path...}/files/a/b.txt: path is the rest, "a/b.txt" (it may be empty)
/static/a trailing slash: /static/ and everything under it
/{$}only / (/ alone matches every path)

import net.http;

void user(http.Writer *w, http.Request *r)  { w.text(200, "user %s", r.param("id")); }
void me(http.Writer *w, http.Request *r)    { w.text(200, "it's you"); }
void file(http.Writer *w, http.Request *r)  { w.text(200, "file %s", r.param("path")); }
void create(http.Writer *w, http.Request *r) { w.text(201, "created"); }
void home(http.Writer *w, http.Request *r)  { w.text(200, "home"); }

void show(http.Mux *mux, u8[] method, u8[] target)
{
  http.Request r = http.testRequest(method, target);
  http.Writer w = http.recorder();
  mux.serve(&w, &r);
  printf("%-6s %-18s %d %s%s\n", method, target, w.code, w.body, w.getHeader("Location"));
  w.free();
  r.free();
}

void main()
{
  http.Mux mux;
  mux.handle("GET /users/{id}", &user);
  mux.handle("GET /users/me", &me);       // more specific: wins for /users/me
  mux.handle("POST /users", &create);
  mux.handle("/files/{path...}", &file);
  mux.handle("/{$}", &home);

  show(&mux, "GET", "/users/42");
  show(&mux, "GET", "/users/me");
  show(&mux, "GET", "/files/a%20b/c.txt");
  show(&mux, "GET", "/");
  show(&mux, "GET", "/files");
  show(&mux, "DELETE", "/users/42");
  show(&mux, "GET", "/nope");
  mux.free();
}

GET    /users/42          200 user 42
GET    /users/me          200 it's you
GET    /files/a%20b/c.txt 200 file a b/c.txt
GET    /                  200 home
GET    /files             301 /files/
DELETE /users/42          405 {"error":"method not allowed"}
GET    /nope              404 {"error":"not found"}

Which pattern wins

When several patterns match, the most specific one wins, whatever order they were added in: one pattern is more specific than another when it matches a strict subset of its requests. So a literal segment beats {name}, {name} beats {name...}, a longer subtree beats a shorter one, and GET /x beats /x.

Two patterns that both match some request where neither is more specific are refused at handle(), and so is the same pattern twice: it throws http.ERR_PATTERN with both patterns in the message. For example /users/{id} and /{kind}/new both match /users/new, and GET / and /health both match GET /health (the first takes fewer methods, the second fewer paths). A pattern that isn't one (no leading /, a host, { inside a segment, {name...} or {$} not at the end, a name used twice) throws the same.


import net.http;

void h(http.Writer *w, http.Request *r) { }

void main()
{
  http.Mux mux;
  mux.handle("/users/{id}", &h);
  try {
    mux.handle("/{kind}/new", &h);
  } catch (Error e) {
    printf("%d: %s\n", e.code == http.ERR_PATTERN, e.message);
  }
  mux.free();
}

1: http.Mux.handle: pattern "/{kind}/new" conflicts with pattern "/users/{id}": some requests match both and neither is more specific

The details

  • Methods: a pattern without one takes every method; GET takes HEAD too (the server sends no body for HEAD). HEAD /x is more specific than GET /x.
  • No route: 404 {"error":"not found"}. A path that a route for other methods matches gets 405 {"error":"method not allowed"} with an Allow header listing them (DELETE, GET, HEAD).
  • Escapes: the path is split at its /s first, then each segment is unescaped, so /a%2Fb is one segment, a/b. Literal segments of a pattern are unescaped too, and r.param gives values unescaped (a segment with a bad % escape is used as it is).
  • Redirects (301, the query kept): /dir goes to /dir/ when it doesn't match a route itself but /dir/ matches a subtree /dir/ (or /dir/{rest...}); a path with //, /./ or /../ goes to its clean form (/a/../b to /b).
  • Speed: patterns are parsed once, at handle(). Matching allocates nothing (a parameter that needs unescaping is copied into the request's arena) and rejects most routes by their segment count and first byte.
  • mux.free() frees the routes and leaves the Mux empty; http.listen calls it when it returns.

Middleware and groups

A middleware is a bool fn(http.Writer *w, http.Request *r) that runs before the handler: return true to go on, or write a reply and return false to stop there. mux.use(&fn) adds one; they run in the order they were added, for every request the mux serves, 404s and 405s included.

mux.group(prefix) gives a http.Mux * whose patterns get the prefix in front ("GET /users" in group "/api" is "GET /api/users"). A pattern with no path is the prefix itself: "GET" in group "/bookmarks" is "GET /bookmarks", so a whole resource can sit behind the group's middleware. A group's own use() runs only for its routes, after the middlewares of the mux (and of the groups) it was made from. Groups can have groups. A group belongs to its mux: mux.free() frees it, and so does http.listen.


import net.http, str;

bool logged(http.Writer *w, http.Request *r)
{
  printf("  -> %s %s\n", r.method, r.path);
  return true;
}

bool auth(http.Writer *w, http.Request *r)
{
  if (str.equals(r.header("Authorization"), "Bearer secret")) { return true; }
  w.error(401, "unauthorized");
  return false;                     // the handler doesn't run
}

void health(http.Writer *w, http.Request *r) { w.text(200, "ok"); }
void user(http.Writer *w, http.Request *r)   { w.text(200, "user %s", r.param("id")); }

void show(http.Mux *mux, u8[] target, u8[] token)
{
  http.Request r = http.testRequest("GET", target);
  if (token.len) { r.addHeader("Authorization", token); }
  http.Writer w = http.recorder();
  mux.serve(&w, &r);
  printf("%s: %d %s\n", target, w.code, w.body);
  w.free();
  r.free();
}

void main()
{
  http.Mux mux;
  mux.use(&logged);                 // every request
  mux.handle("GET /health", &health);

  http.Mux *api = mux.group("/api");
  api.use(&auth);                   // only /api routes
  api.handle("GET /users/{id}", &user);

  show(&mux, "/health", "");
  show(&mux, "/api/users/7", "");
  show(&mux, "/api/users/7", "Bearer secret");
  mux.free();
}

  -> GET /health
/health: 200 ok
  -> GET /api/users/7
/api/users/7: 401 {"error":"unauthorized"}
  -> GET /api/users/7
/api/users/7: 200 user 7

Middleware hands a handler what it found with r.set(key, ptr) and r.setInt(key, n); the handler reads them with r.get(key), r.getInt(key) and r.has(key). They last until the reply, and every request starts with none:


bool auth(http.Writer *w, http.Request *r)
{
  User *u = r.alloc(sizeof(User));      // freed with the request
  if (!findUser(r.header("Authorization"), u)) {
    w.error(401, "unauthorized");
    return false;
  }
  r.set("user", u);
  return true;
}

{
  User *u = r.get("user");
  ...
}

Ready-made middleware (CORS, request IDs, rate limiting, bearer tokens, the real client address) is in net.http.middleware.

Static files

mux.files(prefix, dir) serves the files under dir at prefix, which must end in /: it adds the route GET prefix{path...} (on a group, under the group's prefix).


http.Mux mux;
mux.files("/static/", "./public");   // GET /static/css/site.css -> ./public/css/site.css
mux.handle("GET /api/items", &items);
return http.listen(8080, &mux);
  • A directory serves its index.html (no listings: without one it is a 404); /static/docs redirects to /static/docs/.
  • The Content-Type comes from the extension (http.contentType(name): html, css, js, json, svg, png, jpeg, woff2, wasm, pdf and more; anything else is application/octet-stream).
  • Last-Modified is the file's time; a request with If-Modified-Since at or after it gets 304 and no body.
  • Nothing outside dir: the mux already sends /../ to the clean path, and an escaped .. (%2e%2e) or a NUL gets 400. Symlinks inside dir are followed.
  • A missing file is 404, one that can't be read 403. The file is read whole for each request: it is meant for a site's assets, not for large downloads.

Handlers

A handler is void name(http.Writer *w, http.Request *r) (the type http.Handler). What the request hands it is valid until it returns, and the module frees it then: the path, headers, query values, path parameters, the body and what http.decode made. Copy what must live longer (str.from). Only what the handler allocates itself is its own to free.

  • A handler that throws gets a 500 reply with {"error":"internal server error"}, and the error goes to the log with its file and line. The server carries on.
  • A json.ERR_DECODE (bad JSON in http.decode) gets a 400 with the decode message.
  • A body http.decodeValid rejects gets a 422 with the field errors as JSON.
  • A Mux answers these itself, so a test through mux.serve with http.testRequest and http.recorder() sees the same 400, 422 and 500 as a client.
  • Handlers run on several threads at once: what they share needs the atomic module or a lock.

The reply

The reply is sent in one piece when the handler returns, with Date and Content-Length. A handler that writes nothing sends 200 with an empty body.

MethodWhat it does

Cookies


u8[] token = r.cookie("session");      // "" when the client sent none; r.hasCookie("session")

http.Cookie c;
c.name = "session";
c.value = token;                       // no spaces, quotes, commas, semicolons: encode (base64url) first
c.maxAge = 30 * 24 * 3600;             // seconds; 0 until the browser closes
c.httpOnly = true;                     // JavaScript can't read it
c.secure = true;                       // sent over HTTPS only
c.sameSite = http.SameSite.lax;        // .strict, .none (which adds Secure)
w.setCookie(&c);                      // one Set-Cookie header per call; Path defaults to "/"

w.deleteCookie("session");             // Max-Age=0

setCookie throws http.ERR_HTTP for a name or value a browser would refuse, rather than send one it would drop.

Background work

A handler can start work that goes on after the reply (an email, a webhook, a cache refresh) with coro.go: the coroutine runs on the handler's loop, beside the requests, and the reply doesn't wait for it.


void *sendWelcome(void *arg)
{
  Welcome *m = arg;
  ...                                    // slow: coro.sleep, the http client, ktm-pg all wait without blocking the loop
  m.email.free();
  mem.free(m);
  return null;
}

void signup(http.Writer *w, http.Request *r)
{
  Welcome *m = mem.allocZero(sizeof(Welcome));
  m.email = str.from(r.query("email"));  // a copy: the request's memory is gone after the reply
  coro.go(&sendWelcome, m);
  w.text(202, "welcome!");
}

Give the work memory of its own, never pointers into the request. http.shutdown() (and SIGTERM) waits for work in flight before listen returns. For CPU-heavy work (hashing, compressing) use coro.offload instead, so the loop stays free.

Running the server

http.listen(port, &mux, app, &opts) serves until SIGINT or SIGTERM (or http.shutdown()), lets the requests in progress finish, frees the mux and returns 0; -1 with os.errno() set when the port can't be used. app and opts are optional. Every http.Options field left 0 means its default:

FieldDefault
threadsa coroutine loop per CPU
bindaddrevery IPv4 address ("::*" for IPv6, or a numeric address)
maxHeaderBytes64 KiB for the request line and headers, else 431
maxBodyBytes10 MiB, else 413
readTimeoutMs, idleTimeoutMs30 s for a request that started, 120 s idle between requests
noSignalsfalse: SIGINT and SIGTERM stop the server
accessLogfalse; true: a log.info line per request, GET /users/7?full=1 200 41 0.120ms (method, target, status, body bytes, time)

HTTP/1.1 with keep-alive and pipelining, chunked request bodies, Expect: 100-continue, and HTTP/1.0. A request with both Content-Length and chunked encoding is refused (400). For HTTPS, see below, or put the server behind a proxy such as nginx or Caddy.

HTTPS

net.https serves the same mux over TLS (net.tls, mbedTLS inside ktm):


import net.http, net.https;
...
return https.listen(8443, &mux, "server.pem", "server.key");   // app and opts as for http.listen

The certificate chain and the private key are PEM files; a key that doesn't belong to the certificate throws tls.ERR_TLS at start. https.listenConfig(port, &mux, &cfg) takes a whole tls.Config instead (client certificates through caFile, a key password). Only programs that import net.https carry TLS. A server behind a proxy that ends TLS (nginx, Caddy) needs neither: use http.listen.

The client

Calling other APIs, as Go's http.Get:


import net.http;
import _ = net.https;            // https:// URLs (a blank import: for what it does)

@json struct User { i64 id; String name; };

void main()
{
  http.Response r = http.get("https://api.example.com/users/7");
  defer r.free();
  if (r.status != 200) { printf("%d: %s\n", r.status, r.body); return; }
  User u = http.decodeResponse(&r);
  defer u.freeDecoded();

  http.Response c = http.postJson("https://api.example.com/users", reflect.of(u));
  c.free();
}
CallWhat it does
http.get(url, &opts)A GET; the answer whatever its status
http.post(url, contentType, body), http.postJson(url, reflect.of(x))A POST of bytes, or of a value as JSON
http.request(method, url, body, &headers, &opts)Any method, with http.Headers (h.add(name, value))
r.status, r.body, r.header(name), r.urlThe answer: its status, its whole body, a header (any case), where it came from after redirects
http.decodeResponse<T>(&r)The body as JSON in a T (json.decode's rules)
  • Connections are kept alive and reused, per host and thread; one the server closed meanwhile is retried on a new one. http.closeIdle() closes the thread's idle ones.
  • Redirects are followed as browsers do: a 303, and a 301 or 302 of a POST, become a GET; 307 and 308 keep the method and the body. http.ClientOptions: timeoutMs (the whole request, 30 s), maxRedirects (10; -1 returns the 3xx itself), maxBodyBytes (64 MiB).
  • An answer with any status (404, 500) is a Response; no answer (a bad URL, no connection, the time limit) throws http.ERR_HTTP.
  • In a handler or another loop coroutine a request pauses only that coroutine, so a server can call other services freely.
  • https:// needs net.https imported somewhere in the program (it carries TLS); its certificates are checked against the system's CAs, or https.setClientConfig(&cfg)'s.

Testing handlers

http.testRequest and http.recorder() run a handler or a whole mux without a socket.


import net.http;

void hello(http.Writer *w, http.Request *r)
{
  w.text(200, "hello %s", r.query("name"));
}

void main()
{
  http.Mux mux;
  defer mux.free();
  mux.handle("GET /hello", &hello);

  http.Request r = http.testRequest("GET", "/hello?name=Ada%20L");
  defer r.free();
  http.Writer w = http.recorder();
  defer w.free();
  mux.serve(&w, &r);
  printf("%d %s: %s\n", w.code, w.getHeader("Content-Type"), w.body);
}

200 text/plain; charset=utf-8: hello Ada L
