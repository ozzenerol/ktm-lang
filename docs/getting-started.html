    Getting started

    Build ktm from source, then compile and run your first programs.

    Requirements#

    • Linux on x86_64 or arm64, or macOS on Apple Silicon (arm64); macOS on Intel is not supported. On Windows, use WSL2.
    • A C compiler (gcc or clang), make and cmake. ktm uses the C compiler to assemble and link the code it generates.
    • Optional: the SQLite development package, for the SQLite bindings.

    Build#

    From the repository root, run as your normal user (not with sudo):

    ./build.sh

    This builds the compiler as ./ktm and the standard library into build/prefix. Useful options:

    CommandWhat it does
    ./build.sh --testBuild, then run the unit, JIT and LSP test suites
    ./build.sh --installAlso install ktm and the library to /usr/local (asks for sudo only for the copy)
    ./build.sh --sqliteInclude the SQLite bindings
    ./build.sh --debugDebug build with AddressSanitizer
    ./build.sh --cleanStart from scratch

    Set INSTALL_PREFIX=$HOME/.local to install somewhere else, and CC=clang to choose the C compiler, and JOBS=4 to build and run the tests 4 at a time instead of one per CPU. A test that runs longer than KTM_TEST_TIMEOUT seconds (default 60, 0 for no limit) is stopped and reported as failed. The classic route also works: make && sudo make install.

    Without installing. A program needs the standard library to compile. If you haven't installed ktm, point it at the local build with --install-dir:

    ./ktm --install-dir=build/prefix hello.ktm -o hello

    The rest of these docs assume ktm is installed and on your PATH.

    Your first program#

    Create hello.ktm:

    void main()
{
  printf("Hello, %s!\n", "world");
}

    Hello, world!

    Compile and run it:

    ktm hello.ktm -o hello
./hello

    Without -o the binary is called a.out.

    Run without compiling a binary#

    The JIT compiles into memory and runs immediately, which is handy while developing:

    ktm -jit hello.ktm

    Make a file executable as a script with a shebang line. ktm skips a first line that starts with #!:

    #!/usr/bin/env -S ktm -jit
void main() { printf("Hello from a script\n"); }
    chmod +x hello.ktm
./hello.ktm

    How a program runs#

    A program starts at main. The file scope holds declarations (types, functions, globals, constants, imports); globals with an initialiser that runs code are set up in order before main.

    Return a value from main to set the exit code:

    i32 main()
{
  return 3;   // ./a.out; echo $? prints 3
}

    The standard library#

    The standard library is a set of modules: import the ones a file uses and call their names with the module in front (import str, fs; then str.format(...), fs.readAll(path)). C's own functions are in libc. The compiler links libktm automatically. See the library guide.

    Text#

    A String is text you own: make it, free it where you made it with defer, and change it with its methods. Text you only read is a u8[], a slice: a literal, part of a String or of a buffer, with its length, so nothing is copied.

    import str;

void main()
{
  String greeting = str.format("Hello, %s", "world");
  defer greeting.free();
  greeting.append("!");
  u8[] word = greeting[7:12];
  printf("%s (%d bytes), the word is %s\n", greeting, greeting.len, word);
}

    Hello, world! (13 bytes), the word is world

    Several files#

    Put related code in a module: a directory whose files start with module and the directory's name. Mark what other code may use with pub:

    // geometry/area.ktm
module geometry;

pub i64 area(i64 w, i64 h)
{
    return w * h;
}
    // main.ktm
import geometry;

void main()
{
    printf("%d\n", geometry.area(3, 4));
}
    ktm main.ktm -o shapes

    See Modules for the rest.
