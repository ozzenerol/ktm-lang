    Releases

    What changed in each version of ktm. Binaries for Linux x86_64, Linux arm64 and macOS are attached to each release on GitHub.

    v0.20.0 (2026-10-14)#

    Packages, as Go has them, and the libraries a web service needs: TLS, HTTPS, an HTTP client, cryptography and password hashing, URLs, UUIDs, base64, command-line flags and settings from the environment.

    • Packages: import "github.com/ozzenerol/ktm-pg";, a ktm.mod with one major version per package, ktm.sum hashes, ktm get, ktm mod init/tidy/download/verify/why/list, minimal version selection, a module cache, ktm build and ktm run for a project; warnings from a dependency's code aren't shown. See Packages. The first package is ktm-pg v0.1.0, a PostgreSQL client written in ktm (no libpq).
    • net.tls: TLS clients and servers (mbedTLS 3.6 inside, built into libktmtls, so programs need nothing installed). net.https serves a net.http mux over TLS and gives the client https://. See TLS.
    • An HTTP client in net.http: http.get, http.post, http.postJson, http.request, http.decodeResponse<T>; kept-alive connections per host, redirects, time limits, a size limit, a retry when a kept-alive connection was closed. See HTTP.
    • crypto: secure random bytes, SHA-256/512, BLAKE2b, HMAC, HKDF, PBKDF2, a constant-time compare, AES-256-GCM and ChaCha20-Poly1305, ECDSA P-256 keys and signatures; passwords with crypto.hashPassword (Argon2id, PHC strings), crypto.bcrypt, crypto.verifyPassword (both kinds) and crypto.needsRehash, as fast as Go's. See Cryptography.
    • coro.offload(fn, arg) runs heavy work on worker threads while the coroutine waits, so its loop keeps serving; password hashing uses it by itself (a /ping during logins: 0.3 ms, not 100 ms). Also coro.park and coro.unpark (from any thread), and coro.inLoop().
    • net.url (parse, build, query strings, RFC 3986 resolving), uuid (v4 and time-ordered v7), encoding.base64 and encoding.hex.
    • flag: command-line flags as Go's, with GNU's forms (--port=80, -p 80, -vq), subcommands and a help text. config: environment variables and .env files into a struct, with the new field attributes @env("NAME") and @required.
    • The language: any ...args parameters (each argument a reflect.Value); a blank import import _ = m; for a module's side effects; @json takes pointers to scalars (i64 *: the value or null).
    • Fixes: (i32) of a u32 widened to i64 didn't sign-extend; overloads of a generic that differed only in a pointer parameter all called the last one; a store to a global with a long name was cut short on x86_64; an error on a module-qualified name underlined too much; a coro.unpark that came as a park's time limit ran out was lost; ./build.sh --install rewrote libktm.so in place, so ktm and JIT programs running at the time could crash (it now installs new files and renames them over the old ones).

    v0.19.0 (2026-10-14)#

    HTTP servers: net.http, Go's net/http and ServeMux for ktm, about 3 times as fast.

    • import net.http;: http.Mux routes by Go 1.22 patterns ("GET /users/{id}", {rest...}, {$}, subtrees; the most specific wins, conflicting patterns are refused, 404 and 405 with Allow). A handler is void h(http.Writer *w, http.Request *r): r.param, r.query, r.header, r.body, http.decode<T>(r); w.json, w.text, w.error. What a request hands a handler is freed when it returns. A throw is a 500 (and a log line), bad JSON a 400. http.listen(port, &mux, app) serves on every core until Ctrl-C or SIGTERM and finishes the requests in progress.
    • Middleware (mux.use), groups with a prefix (mux.group), static files (mux.files), an access log (http.Options.accessLog), and http.testRequest / http.recorder() to test handlers without a socket. See HTTP servers.
    • Measured against Go 1.27 net/http on the same 2 cores: 2.7 to 3.75 times the requests per second with 16 or more connections, 2.2 to 2.6 times the requests per CPU-second, lower median and p99 latency everywhere (p99 at 1024 connections: 4.5 to 6 ms against Go's 21 to 25 ms), a quarter of the memory.
    • try and defer cost less: 5 ns and 9 ns, from 12 and 13.
    • json.encodeTo(&s, v) and json.quoteTo(&s, text) add JSON to a String you have.
    • Fixes: a type alias to a function type in a module (pub type H = fn(...) void;) was "already defined"; b.len of a parameter with a default (u8[] b = "") stopped the compiler; a library's generic that calls a static function of its module didn't link in programs.

    v0.18.0 (2026-10-14)#

    Memory that frees itself where it should, clearer -Memsafe reports, switch on strings, and a round of stdlib additions.

    • vec.Vec, list.List, map.Map and map.Tree free the Strings they hold: free() and clear() free them, as do a Map or Tree delete and a set that replaces one. pop, removeAt, shift and remove hand the String back to you. map.keys() and values() give copies of their own.
    • -Memsafe: a leak is a block nothing points to any more. What globals or live variables still hold at exit is listed apart as still in use at exit ... not leaks. Every report names the file and line in your code and the public library call it went through (at cli/cli.ktm:16 in cli's globals, via vec.new<String>; under -Memsafe library functions are not inlined into your code, so the name is the one you called), and a program that ends with exit() gets its report too.
    • A warning when a function changes a Vec, List, Map, Tree, Set or String it got by value (push, removeAt, append...): only its copy changes. Take a pointer.
    • switch on a u8[] or String with string cases: case "init":. Case-sensitive; a duplicate case is an error.
    • Every local starts zeroed, not only Strings (Config c; no longer holds garbage). Large plain arrays (over 4 KiB, no Strings or slices in them) are left as they are.
    • T[] s = {a, b, c}; makes a slice of a hidden array; it compiled with warnings and crashed before. {ptr, len} still sets the slice's own fields.
    • A function of your own with u8 *fmt, ...args takes Strings for %s as printf does.
    • A String variable or field converts to u8 * where one is expected (its bytes always end in a NUL): cstr.len(s) and C calls without .cstr().
    • str.join(parts, sep) from a slice or a vec.Vec; vec.Vec.contains(x); str.toInt, str.toUint and str.toFloat read a whole u8[] as a number; proc.expandEnv(text) fills in ${NAME} and ${NAME:default}.
    • Logging: the messages line up in one column (the level and the file:line part are padded); lines logged after log.shutdown() keep the level and output they had and say once where they came from; log.info and the others take Strings and u8[] for %s.
    • The language server completes every method of a generic instance (vec.Vec<String>), not only the ones already called, and a module's own globals.
    • Fixes: a statement that is only a field (self.port;) stopped the compiler; code inlined from another file was reported at a line of the wrong file; overloads with a generic parameter gave an assembler error.

    Changes you may notice#

    • Freeing a String through a copy and then freeing its container is now a double free: v.get(i).free(), or freeing a value from map.next(), before v.free() or m.free(). v.at(i).free() is still safe (it clears the String in place). fs.freeList(&names) is now the same as names.free().
    • fs.makeDir, makeDirAll, remove, removeDir, rename, move, copyFile and changeDir return a bool, true when it worked (false with os.errno() set), as fs.writeAll and fs.exists already did. They returned 0 on success, so if (!fs.makeDir(d)) failed when it worked. A check written as fs.remove(p) == 0 now means it failed: write if (fs.remove(p)).
    • Log lines have more spaces: the level and the file:line part are padded.
    • -Memsafe no longer calls what a global holds at exit a leak.

    v0.17.2 (2026-10-13)#

    One logging fix.

    • log.Options.toStdout with a path writes each line to the file and to stdout. Before, the file won and toStdout was ignored without a word.

    v0.17.1 (2026-10-13)#

    Program arguments, and a flaky test.

    • With -run or -jit, everything after the source file goes to the program, even words that look like ktm's options: ktm -run app.ktm -v gives the program -v (ktm took it before). -- ends ktm's options and is no longer passed on.
    • The coro.serve test could end itself with SIGTERM when its signal coroutine ran late; it now installs the handler first, as signal.stopInit asks.

    v0.17.0 (2026-10-13)#

    C's stdio in libc, and logging to stdout.

    • libc.fprintf(stream, fmt, ...) with libc.stdin, libc.stdout and libc.stderr, and libc.EXIT_SUCCESS / libc.EXIT_FAILURE for libc.exit. fprintf(libc.stdout, ...) stays in order with printf.
    • log.Options.toStdout: with no path, a Logger or the default logger writes to stdout instead of stderr, in order with printf.
    • _extern binds C data by its symbol too: _extern ___stderrp FILE *stderr;, and in a module it has the module's name.

    Changes you may notice#

    • The format strings of libc.printf, libc.snprintf and libc.fprintf are now checked against their arguments, as printf's always was, so a wrong count is now a compile error. A bare snprintf or sprintf declared with extern "c" is checked too (its format was looked for in the wrong argument before).

    v0.16.0 (2026-10-13)#

    A default logger, so a program logs from anywhere without passing a Logger around.

    • log.setup(&o) once in main, then log.info(...), log.debug, log.warn and log.error from any function in any module. The file, line and function are still the caller's.
    • Until log.setup is called they write to stderr at INFO, so a small program needs no setup. log.setLevel changes the level, log.shutdown closes the file and log.logger() is the default Logger itself.
    • log.open and log.Logger are unchanged.

    v0.15.2 (2026-10-13)#

    One fix for the language server.

    • The language server could send a semantic-tokens reply with stray bytes in it when a file had nothing to highlight (a file that is only module cli;, say). Neovim then reported INVALID_SERVER_JSON: Expected value but found invalid token. The reply is now an empty list. The cause was in the compiler's string buffers, which now always start empty.

    v0.15.1 (2026-10-13)#

    Two fixes for compile errors.

    • A range-for with nothing to range over crashed the compiler. An array literal, for (auto name : ["a", "b"]), now says ktm has no array literals and shows how to declare the array first; for (auto x : ) says what is missing.
    • A type or name from a module the file doesn't import, as in ad vec.Vec<i64> v = m.values(); or vec.Vec<i64> v; without import vec, says module `vec` is not imported: add `import vec;`. An ad declaration with an unknown type names that type instead of "Type `ad` has not been declared".

    v0.15.0 (2026-10-13)#

    Logging, and functions that know where they were called from.

    • A new log module: lg.debug, info, warn and error write one short line each, to stderr or a file: 2026-10-13T14:02:11.482Z INFO listening on :8080. showFile and showFunc add the call's main.ktm:42 and function. A file rotates by size (maxBytes, keep), and threadSafe lets several threads share one Logger without their lines mixing. See Logging.
    • @caller("file"), @caller("line") and @caller("func") before a parameter: every call fills it with where the call is written, and callers never pass it. They work in methods, before ...args, next to defaults and through auto function pointers. Signature help in the language server skips them. See Where a call comes from.
    • Known issues lists two bugs found along the way, both planned for v0.15.1: a range-for over an array literal crashes the compiler, and a confusing error for an ad declaration whose module isn't imported.

    v0.14.0 (2026-10-13)#

    JSON and YAML without reflection. Mark a struct @json or @yaml and the compiler writes its encoder and decoder.

    • Attributes: @json and @yaml before a struct, and @key("e-mail"), @skip and @omitEmpty before its fields. An unknown or misplaced one is a compile error, reflect shows them, and hover in the language server shows them too.
    • A @json struct gets toJson, fromJson and freeDecoded methods; @yaml adds toYaml and fromYaml. A field type that can't be written is a compile error at that field. ktm --expand prints the generated code.
    • json.encode, json.decode and json.free use those methods by themselves, at any depth, so existing code gets faster by adding @json. On a 1 KB order, decode takes 6.6 us instead of 20.6 us and encode 10.5 us instead of 15.4 us.
    • json.decode reads the text with the new json.Reader and builds no tree, which also makes it about twice as fast for structs without @json.
    • json.Reader, a streaming reader for JSON text, and json.Writer gains rawKey and uint.
    • A new yaml module: yaml.Reader and yaml.Writer for block and flow mappings and sequences, plain and quoted scalars, block scalars and comments. Anchors, tags, merge keys and more than one document are reported as not supported.

    Changes you may notice#

    • Decode errors start with the line and column in the text: 1:22: tags[0].weight: expected an integer, got a string. The rest of each message is the same as before.
    • JSON text that ends too early says expected a value, got the end of the input instead of not JSON: ....
    • With json.STRICT, an unknown key is reported before a missing one, since the text is read in order.
    • @ outside an asm block starts an attribute, so it is no longer an "unexpected character".

    v0.13.3 (2026-10-13)#

    Fixes for struct values passed by value, and clearer errors.

    • Passing *p (a struct, by value) to a function no longer breaks the other uses of p in the same function. Calls like f(p) elsewhere in it got a copy of the struct instead of the pointer, even when the *p call never ran.
    • Reading a String field straight off a call result works: mk().name, v.get(0).name, (a = b).name. The compiler used to stop with "Slice AST_CLASS_REF assign: unsupported cls kind AST_FUNCALL", and (a = b).name passed to a function crashed at run time.
    • Calling a field as if it were a method (s.len() where len is a field) is a compile error, "`len` is a field, not a method: read it without `()`". The compiler used to crash. Function-pointer fields are still called as before.
    • ad on a struct field says that ad goes on a local variable, and errors inside a struct or union body say "struct" or "union" instead of "class".
    • Hover in the language server shows a null default parameter as null, not 0(void *).

    v0.13.2 (2026-10-13)#

    A vec.Vec is a JSON array.

    • json.decode fills a vec.Vec<T> field (or a top-level vec.Vec<T>) from a JSON array, the same way it fills a T[] slice. It used to throw "expected an object, got an array". The Vec it makes is an ordinary one: push grows it and json.free frees its items and its block.
    • json.encode writes a vec.Vec<T> as an array of its items. It used to write the Vec's own fields, {"data":5,"len":2,"cap":8}.
    • A vec.Vec<u8> is a string both ways, as a u8[] is, so what encode writes decodes back. A struct of your own with data, len and cap fields is still an object: a Vec is known by its type.

    v0.13.1 (2026-10-13)#

    A clean build and a tidier library reference.

    • Building ktm prints no C compiler warnings. One was a real risk: a loop counter that was live across a setjmp could come back stale after an error inside a generic instance.
    • Building the standard library prints no warnings either. "module rt is imported but not used" was wrong for files whose only use of rt is a throw with a message, and the imports that really were unused are gone.
    • fs no longer has its own opendir and readdir declarations, which repeated libc's and showed up in the library reference as fs.opendir, fs.readdir and fs.libc.*.
    • The Neovim setup in Tools covers lazy.nvim, which resets the runtime path: list ktm's vim directory in performance.rtp.paths.

    v0.13.0 (2026-10-13)#

    Ahead of Go on every load. On Linux the coroutine loop now runs on io_uring, and a coroutine-per-connection server written the plain way (coro.serve, coro.read, coro.write) does more work per CPU-second than Go 1.27's goroutine-per-connection server in every scenario of the echo benchmark, with less memory (server on 2 cores, client on 6, so the client is never the limit):

    ScenarioktmGoper server CPU-second
    64 B request/response, 64 clients368k req/s168k req/s+45%
    64 B request/response, 1024 clients379k req/s133k req/s+54%
    4 KiB request/response, 64 clients267k req/s157k req/s+45%
    64 KiB streams, 16 connections7.5 GB/s6.6 GB/s+12%
    64 KiB streams, 64 connections7.4 GB/s6.5 GB/s+9%

    Coroutines and networking#

    • The coroutine loop runs on io_uring on Linux 6.1 and later: reads, writes and accepts go to the kernel directly, all of a turn in one system call. It falls back to epoll (an older kernel, a container that forbids io_uring) and then to poll; macOS uses kqueue. coro.backend() says which one a thread runs, and KTM_CORO_BACKEND=uring|epoll|kqueue|poll picks one.
    • coro.read keeps reading a busy stream for up to 4 ms before it lets the loop's other coroutines run, instead of 32 reads: bulk transfers over many connections move about a third more per CPU-second, and another coroutine on the same loop waits at most about 8 ms (Go preempts a busy goroutine every 10 ms).
    • coro.dial(addr, port, ms): connect from a loop coroutine without blocking the loop's thread. net.dial waits in connect and stops every coroutine of its loop meanwhile; its docs now say so.

    Changes you may notice#

    • On Linux, programs using the coroutine loop run on io_uring by default. Set KTM_CORO_BACKEND=epoll to keep the previous loop.

    v0.12.0 (2026-10-12)#

    Memory. A coroutine-per-connection server now uses less memory than Go's goroutine-per-connection server at every load of the echo benchmark: with 1024 clients, 10.7 MB against Go's 11.6 MB (ktm v0.11.0 took 72 MB), and it keeps v0.11.0's speed (request/response 3% to 35% ahead of Go, a quarter of Go's p99 latency at 64 clients).

    Big stack frames#

    • A function whose stack frame is bigger than a page used to touch every page of it on the way in, so that a stack overflow couldn't jump over the guard page. That made every page of a big local buffer real memory, used or not: a handler with u8 buf[65536] cost 64 KiB per connection. Now such a function asks the runtime whether the frame fits on its stack, and touches nothing: the buffer costs only the pages it uses. AOT and JIT, x86_64 and arm64.

    Coroutines#

    • Released coroutine stacks kept for reuse give their memory back once they are older than the four most recently released ones (madvise on Linux, a fresh mapping on macOS), so a burst of connections that ends doesn't leave its memory behind. Starting and releasing short coroutines costs the same as before.

    Changes you may notice#

    • Running off the end of a stack (deep recursion, a frame too big for a thread's stack) now prints stack overflow and ends the program with SIGABRT, instead of a bare SIGSEGV (SIGBUS on macOS).
    • The last 64 KiB of a thread's own stack count as overflow: a thread can use a little less stack than before before it is stopped.

    v0.11.0 (2026-10-12)#

    Networking that is fast by default. A TCP server written the plain way, a coroutine per connection with coro.serve, now uses every core and the kernel's event queue, and beats Go 1.27's goroutine-per-connection server on request/response traffic (an echo benchmark on one Linux machine, both servers untuned):

    64-byte request/responsektmGo
    16 clients325k req/s281k req/s
    64 clients379k req/s, p99 0.54 ms282k req/s, p99 2.63 ms
    256 clients365k req/s294k req/s
    1024 clients333k req/s321k req/s

    With 4 KiB messages ktm serves 32% more requests with a fifth of Go's p99. A single bulk stream runs 22% faster; with 16 and 64 streams at once ktm and Go are about even (within 3% either way, run to run).

    Coroutines and networking#

    • coro.serve(port, &handler, arg, threads, bindaddr): a whole TCP server in one call. It runs handler(fd, arg) as a coroutine for each client on one loop per CPU (SO_REUSEPORT on Linux; on macOS the loops share one listener). coro.serveStop() stops it from any thread or coroutine, and the SIGINT/SIGTERM coroutine of the docs works unchanged. Handlers run on several threads at once: shared globals need the atomic module or a lock.
    • coro.read(fd, buf, ms) and coro.write(fd, data, ms): read what is there and write all of it, pausing the coroutine instead of the thread, on sockets and pipes. A read goes straight on while a stream keeps filling the buffer and waits first otherwise, so a connection costs no more system calls than it must.
    • The coroutine loop waits on epoll (Linux) and kqueue (macOS) instead of poll: a turn costs the fds that are ready, not every fd that is open. Nothing to change in existing programs; a program that has run out of fds when its loop starts gets poll as before.

    Changes you may notice#

    • An fd waited on with coro.wait stays registered with the kernel between waits, so close it with coro.close, as the docs already said for connections: a plain close(2) of a waited-on fd whose number is then reused for an fd that is not from coro.accept can leave a wait on the new fd unanswered.
    • coro.waitChild closes its exit fd with coro.close.

    v0.10.1 (2026-10-12)#

    Editor support, fixed and made rich: the language server understands the whole current language and gains the features editors expect, and the Vim syntax is rewritten for today's ktm. Also: directories and file operations in fs.

    The language server#

    • Fixed: only the first module of an import list (import mem, str, json;) was seen, so hover, definition and completion failed on every stdlib call after it.
    • Fixed: opening one of a module's files (the standard library's too) showed a false "not part of a module" error and more after it. A module's file is now checked as its module, with the unsaved text of its other files.
    • Fixed: enums had no hover (it failed), no definition and no completion; now Color, Color.green and geo.Kind.rect show their members and values, jump to their declaration, and Color. completes the members.
    • Fixed: module names (in imports and as prefixes, aliases too) and fields at their declaration had no hover or definition; a module's name jumps to its files.
    • Fixed: completion gave keywords the "operator" kind and offered internal names (_K3geo4area, Vec<i64>).
    • New: hover shows a declaration's doc comment, the standard library's included.
    • New: signature help in calls (the parameter you are on, every overload), the document outline, workspace symbol search, semantic highlighting (modules, types, enum members, functions and methods, fields, parameters, locals, constants, macros, the stdlib's marked), folding ranges, inlay hints with the type of each auto variable, and completion of the modules an import can name.

    Vim and Neovim#

    • The syntax file is rewritten for the current language: lowercase types, fn, module and import lists, pub, defer, ad, type, enums, generics, String, true/false/null, digit separators, ktm's escapes and format conversions. It comes with filetype detection (Neovim took .ktm for another language) and an ftplugin, and installs into <prefix>/share/ktm/vim (see Tools).

    The standard library#

    • fs.openDir(path) and d.next() read a directory: each entry's name, kind (a symlink is a link) and joined path, without . and ..; close it with defer d.close(); or ad.
    • fs.list(path) gives the sorted names as a vec.Vec<String> (fs.freeList frees them), and fs.walk(root, &visit, arg) visits every entry at any depth without following symlinks.
    • fs.join, fs.exists, fs.makeDirAll, fs.copyFile (with the permission bits), fs.rename, and fs.move, which copies and removes across filesystems. See the library guide.
    • libc's constants passed its C-only check in a normal build but not in the REPL; fixed.

    v0.10.0 (2026-10-12)#

    The standard library's containers, rebuilt on generics. vec.Vec<T>, map.Map<K, V>, map.Tree<K, V>, set.Set<T> and list.List<T> hold any type with no void * and no casts, are values (made with mod.new<T>(), freed with free(), so ad works), and replace IntVec, PtrVec, FloatVec, IntMap, StrMap, RBTree, IntSet and the void * list, which are gone. New: module sort and json.decode<T>.

    import json, list, map, set, vec;

struct Point { i64 x; i64 y; };

i64 byX(Point *a, Point *b) { return a.x - b.x; }

void main()
{
  ad vec.Vec<Point> pts = vec.new<Point>();
  Point a = {3, 1}, b = {1, 2};
  pts.push(a);
  pts.push(b);
  pts.sort(&byX);
  for (auto p : pts) { printf("(%d,%d) ", p.x, p.y); }
  printf("\n");

  ad map.Map<u8[], i64> counts = map.new<u8[], i64>();
  u8[] words[] = {"to", "be", "or", "not", "to", "be"};
  for (auto w : words) { counts.set(w, counts.getOr(w, 0) + 1); }
  i64 it = 0, n;
  u8[] word;
  while (counts.next(&it, &word, &n)) { printf("%s=%d ", word, n); }
  printf("\n");

  ad set.Set<i64> seen = set.new<i64>();
  printf("%d %d\n", seen.add(4), seen.add(4));

    The standard library#

    • vec.Vec<T>: vec.new<T>(cap), push, pop, get, at (a pointer to an item), set, last, insert, removeAt, reserve, items() (a T[] view), sort(cmp), sortAsc(), clear, free, and the len field. A range for walks it directly: for (auto x : v).

    v0.9.0 (2026-10-12)#

    Generics and type aliases. A struct, its methods and a function can take type parameters, and each use with other types is compiled for those types: the same code you would write by hand, with no void * and no casts.

    import mem;

struct Stack<T> { T *items; i64 len; i64 cap; };

void Stack<T>.push(T x)
{
  if (self.len == self.cap) {
    self.cap = self.cap ? self.cap * 2 : 4;
    self.items = mem.realloc(self.items, sizeof(T) * self.cap);
  }
  self.items[self.len++] = x;
}

T Stack<T>.pop() { return self.items[--self.len]; }
void Stack<T>.free() { mem.free(self.items); }

T max<T>(T a, T b) { return a > b ? a : b; }

type Ints = Stack<i64>;

void main()
{
  ad Ints nums = {null, 0, 0};
  nums.push(1);
  nums.push(2);
  ad Stack<u8 *> words = {null, 0, 0};
  words.push("hello");
  printf("%d %s %d %.1f\n", nums.pop(), words.pop(), max(3, 7), max(1.5, 0.5));
}

    The language#

    • Generics: struct Stack<T>, its methods T Stack<T>.pop(), and functions T max<T>(T a, T b), with any number of parameters. A type is written with its arguments (Stack<i64>, Stack<Stack<i64>>); a call works them out from the arguments (through pointers, slices, fn types and generic structs) or takes them written (max<f64>(1, 2.5)). Generic bases, self-referencing structs, ad, modules (coll.Vec<i64>, pub as for any declaration) and -lib libraries work with them. An error in an instance names it and the use that asked for it. The language server shows instances and goes to the generic's definition. A generic Vec<i64> ran faster than vec.IntVec in our measurements. See Generics.
    • Type aliases: type Name = T; gives any type a second name (slices, pointers, fn types, fixed arrays, structs, generic instances, other aliases). An alias is its type, so values pass between them with no conversion; in a module pub type is used as mod.Name and aliases may come in any order. The language server shows, completes and jumps to them.

    Fixes#

    • pub or private on an enum, struct or union applied to the next declaration of a module as well: a private function after a pub enum could be called from outside, and a pub declaration after a private enum was an error.

    v0.8.0 (2026-10-12)#

    Autodefer, one-instruction bit operations, pipelines and process groups in proc, and UDP with binary addresses in net.

    import math, str;

void main()
{
  ad String text = str.from("one two three");
  ad u8[][] words = str.split(text, " ");     // freed at the end of main
  u32 h = 0x811C9DC5;
  for (auto w : words) { h = math.rotl((u32)(h ^ w.len), 5); }
  printf("%d words, hash %x\n", words.len, h);
}

    The language#

    • ad (autodefer): ad T name = value; frees name at the end of its scope, as if defer name.free(); followed, on every way out. It takes a String, any slice, or a struct with a free() method (or a pointer to one). Returning an ad variable is an error, and so is a type with no free(). ad is not reserved: a variable can still be named ad. See ad (autodefer).

    The standard library#

    • math.rotl, math.rotr, math.bswap, math.clz and math.ctz on a u32 or u64 (bswap also on a u16) compile to one instruction where they are called, on x86_64 and arm64, AOT and JIT; math.popcount counts the one bits. hash's SHA-256 uses them and runs about 17% faster.
    • proc can build pipelines: proc.FD gives a program an fd of yours as its stdin, stdout or stderr (Opts inFd/outFd/errFd), Opts.pgid joins an existing process group, Opts.dups maps more fds in order, proc.pipe makes the connecting pipes and proc.disown frees a Proc you reap yourself; proc.kill reaches the group a process joined.
    • net.Addr keeps an IPv4 or IPv6 address in binary: net.recvFromAddr and net.sendToAddr let a UDP server answer each datagram without turning the sender into text and back; net.makeAddr builds one from a numeric address, and Addr.ip(), port(), family(), equals() and sameIp() read it. net.localAddr, net.remoteAddr and net.setBlocking are public.

    Fixes#

    • macOS: a string literal with a NUL byte inside ("\x00\x08\x00\x00") lost bytes in a compiled program: the linker splits the section literals went in at each NUL and merges the pieces. Such literals now go in a section it leaves alone.
    • Docs: the sockets section showed a bare signal(SIGPIPE, SIG_IGN), which doesn't compile; it is signal.handle(libc.SIGPIPE, libc.SIG_IGN) or libc.signal(...), now with a runnable example (it reads errno right after the failed write, which macOS needs).

    v0.7.0 (2026-10-12)#

    Code generation: the compiler inlines small functions, and a new module atomic shares counters and flags between threads without a mutex. Locals are now always at their type's alignment, which atomics and C code need.

    import atomic, libc;

i64 gHits = 0;

i64 next(i64 i) { return i + 1; }   // small: compiled into its callers

void *worker(void *unused)
{
  for (i64 i = 0; i < 100000; i = next(i)) { atomic.add(&gHits, 1); }
  return null;
}

void main()
{
  libc.pthread_t *th[4];
  for (i64 i = 0; i < 4; i++) { libc.pthread_create(&th[i], null, &worker, null); }
  for (i64 i = 0; i < 4; i++) { libc.pthread_join(th[i]); }
  printf("%d hits\n", atomic.load(&gHits));
}

    The compiler#

    • Inlining: a call to a short function of the program whose parameters and result are numbers or pointers is compiled as the function's body in the caller, which saves the call. It behaves exactly like the call (arguments convert to the parameter types, a result to the return type, recursion is never inlined), and the function is still compiled on its own. Loops calling small helpers ran 1.2 to 1.8 times as fast in our measurements.
    • Every local is at its type's natural alignment in the frame: an i64, f64 or pointer declared after a narrower local was 4-aligned, which atomic instructions fault on (arm64) or split (x86_64), and C code may not expect.

    The standard library#

    • New module atomic: load, store, add, sub, swap, and, or, xor and cas on i64, i32, u64 and u32 (the pointer type picks the width), pointer versions (loadPtr, storePtr, swapPtr, casPtr) and fence(), all sequentially consistent. See Atomics.

    Changes you may notice#

    • atomic is no longer a keyword: it was accepted and ignored, so atomic i64 n; made an ordinary variable. It is now an error that points to the module.

    Fixes#

    • An unknown name followed by another word (foo bar;) is reported at the name; as a block's first statement it used to point at the block's {.

    v0.5.0 (2026-10-12)#

    A systems library: what the example servers and tools used to write by hand. A coroutine loop for servers, a byte buffer, monotonic clocks and HTTP dates, the OS calls shells and daemons need, and small helpers. Nothing that compiled before changes meaning.

    import bytes, coro, date, libc, net;

void *client(void *arg)
{// reads 4-byte big-endian lengths and their messages, answers with the time
  i32 fd = (i32)(i64)arg;
  bytes.Buffer in = bytes.bufferNew();
  defer in.free();
  while (coro.waitIdle(fd, libc.POLLIN, 5000) > 0 && in.readFrom(fd) > 0) {
    while (in.len >= 4 && in.len >= 4 + bytes.be32(in.data())) {
      in.consume(4 + bytes.be32(in.data()));
      String now = date.httpDate(date.unixNow());
      net.send(fd, now);
      now.free();
    }
  }
  coro.close(fd);
  return null;
}

void *acceptor(void *arg)
{
  i32 lfd = (i32)(i64)arg, fd;
  while ((fd = coro.accept(lfd)) != -1) { coro.go(&client, (void *)(i64)fd); }
  return null;
}

void main()
{
  coro.go(&acceptor, (void *)(i64)net.listen(9000, "*", 64));
  coro.run();
}

    The standard library#

    • A coroutine loop in coro: coro.go starts a coroutine in the thread's loop and coro.run runs them all over one poll per turn. Inside them coro.wait(fd, events, ms), coro.waitIdle, coro.sleep and coro.accept pause the coroutine instead of the thread. coro.stop() winds the loop down gracefully, and an accept that runs out of fds neither spins nor drops clients: it rests until coro.close frees one, and for a while after it only accepts when two fds are free (on macOS a failed accept resets the client it took off the queue). Misuse throws coro.ERR_LOOP.
    • Module bytes: a bytes.Buffer that grows at the end and is consumed from the front (append, consume, room/commit, readFrom/writeTo, appendBe32 and the other byte orders), and bytes.be16/32/64, le16/32/64 and putBe*/putLe* on any u8[], bounds-checked.
    • date.monoMs() and date.monoNs(), a clock that only goes forward, for timeouts; date.sleepMs, date.unixNow; date.formatUnix(t, fmt) (strftime, UTC or local); date.httpDate and date.parseHttpDate (RFC 9110, all three forms).
    • The environment and the process: proc.getenv, hasEnv, setenv, unsetenv; proc.selfPath(), proc.cpuCount(); proc.exited, exitCode, signaled, termSignal, stopped, stopSignal and proc.statusCode (as $?) for wait statuses.
    • libc declares dup, dup2, getpid, getppid, getpgrp, setpgid, setsid, tcgetpgrp, tcsetpgrp, pread, pwrite, fsync, ftruncate, readlink, symlink, rename, access, realpath, sysconf, setenv, getrlimit/setrlimit and more errno codes (EEXIST, ENOTEMPTY, ENOSPC, ELOOP, ...), each with its platform's value.
    • os.eprintf (printf to stderr, format-checked) and os.flush; math.min, math.max, math.clamp; removeAt(i) on PtrVec, IntVec and FloatVec; json.Writer.cstr(u8 *) for C strings (a null pointer is null).

    Fixes#

    • arm64: a struct of 32 KB or more passed or returned by value failed to assemble (AOT) or used wrong addresses (JIT). Structs from 256 bytes up are now copied by a loop, which also keeps the code small.

    v0.4.0 (2026-10-12)#

    Reflection. A program can ask the compiler about its types at run time, and the json module uses that to turn any struct into JSON and back without hand-written code. Plus a JSON writer, enum names at run time, and typed comparators and callbacks.

    import json, mem, reflect;

enum Role { guest, admin };
struct User { i64 id; String name; Role role; u8[][] tags; };

void main()
{
    User u;
    mem.set(&u, 0, sizeof(User));
    json.decode("{\"id\": 7, \"name\": \"Ada\", \"role\": \"admin\", \"tags\": [\"math\"]}",
                reflect.of(u));
    defer json.free(reflect.of(u));
    u.id++;
    String text = json.encode(reflect.of(u));
    defer text.free();
    printf("%s\n", text);   // {"id":8,"name":"Ada","role":"admin","tags":["math"]}
}

    The language#

    • reflect.typeOf(T) (a type or any expression) gives a reflect.Type: kind, name, size, signedness, element and length, a struct's fields (name, type, offset, private or not; inherited ones first) and an enum's members. reflect.of(x) gives a reflect.Value, x's address and type, so one function can take any value; reflect.field, getInt/setInt and getFloat/setFloat read and write through it. A description is made at compile time, only for the types a program asks about; compare two with reflect.same.
    • Enum names at run time: reflect.name(Role.admin) is "admin", reflect.enumValue(t, "admin", &v) goes the other way. printf of an enum still prints its number.
    • A function whose parameters are typed pointers now converts to a function pointer whose matching parameters are void *, so comparators and callbacks are written with their real types and no casts (i64 byAge(User *a, User *b) goes straight to PtrVec.sort); the return type and every other parameter must still match.

    The standard library#

    • json.encode(reflect.of(x), indent) writes any value as JSON; json.decode(text, reflect.of(x), flags) fills it in and json.free frees what decode allocated. Fields by name, private ones skipped, enums by name, Strings, slices, arrays, nested structs and pointers. Unknown keys are ignored and missing fields kept, unless json.STRICT. A value that doesn't fit throws json.ERR_DECODE with where it is (items[2].price: expected a number, got a string).
    • json.Writer builds JSON into a String: beginObject, key, int/float/bool/str/nil, beginArray, end, raw, take; escapes, commas and an optional indent done for you, and misuse throws json.ERR_WRITER.

    • %s takes a slice or a String directly in printf, str.format and throw.
    • Named varargs are real slices (i64 ...nums is an i64[]), and ...x spreads any slice.
    • -Memsafe and the REPL see every allocation, the library's own included: a double free through a copied String is reported with all three lines.

    • net: addresses and names are u8[] (empty means any), net.send/sendTo take a u8[], net.recvFrom reads into a u8[] and gives the sender as a String, net.peerAddr and net.addrToStr return Strings.
    • date: format, formatDate, formatTime, timestampNow and isoFromTimespec return Strings; date.parse and parseParts take a u8[].
    • map: a StrMap key is a u8[] matched on all its bytes, and the map copies and frees its keys itself (setFreeKey, getLen and hasLen are gone: look up part of a buffer with buf[0:n]); node.key and keyIter give views of the map's copy. toStr and keysToStr of StrMap, IntMap and set.IntSet return Strings.
    • proc, csv and sql keep their u8 * functions in this release; they move to u8[] and String in v0.3.1.

    Watch out#

    • An array becomes a slice of its full length: a u8 buf[64] passed where a u8[] is expected is all 64 bytes, not the text up to its NUL. Pass cstr.view(buf) for the C string in it.

    Fixes#

    • The format engine never checked its argument count: a format asking for more arguments than it got now throws instead of reading past them.
    • A module can call its own global function pointer by name.
    • A method can be called on a call's result (fs.readAll(p).take()).
    • return f(); of a function returning a struct crashed the compiler; c ? a : b of structs works, and mixing a struct with a pointer in a conditional is an error (it compiled to garbage); a field named like an imported module (v.str) is a field.
    • A vector's index error names the method: IntVec.get: index 5 out of range (size 3) (it said IntVecGet).
    • A slice in an initialiser list takes one item (Path p = {"name", points};), in locals, globals, structs and arrays.

    Known issue#

    • A write through a slice of a string literal is not caught at compile time yet (planned for v0.3.1): copy the literal with str.from before changing it.

    v0.2.1 (2026-10-11)#

    A cleanup release: the macOS JIT fork crash, module libraries with run-time initialisers, readable names in every message, and a set of smaller fixes.

    Fixes#

    • On macOS, a child forked by a program run with -jit no longer crashes now and then right after fork() (its thread came back with Apple's JIT write protection off). The known issue is gone.
    • A library that reads or writes another prebuilt library's globals links (they are reached through the GOT).
    • Messages name functions, not their symbols: the JIT's unresolved-symbol errors, the linker's errors and notes, and the REPL say geo.useHelper, never _K3geo9useHelper.
    • A module global whose type doesn't exist is reported once, not twice.
    • #define KTM_NO_REPL_HELLO in ~/.ktm_rc.ktm hides the REPL greeting, as documented.
    • A program's own global named like a C one (environ, errno) no longer replaces it: program globals get their own symbols, as functions did in v0.2.0. A child started by proc.run from a program that had its own environ got an empty environment.
    • In the JIT, a global declared with extern and never defined is an error instead of a crash at address 0.
    • auto s = "x"; no longer warns "u8[2] is not assignable to u8[2]".
    • & of something without an address (&5, &E.a, &f()) is a parse error instead of a code generator failure.
    • Duplicate case values are reported by value (duplicate case value Color.red), including a value inside an earlier range; integer duplicates were not reported at all.
    • argc/argv outside main's parameters are an error (they were silently 0 and null).
    • json.parse rejects invalid UTF-8 in strings (stray continuation bytes, cut-off and overlong sequences, surrogates, values past U+10FFFF) with the new json.INVALID_UTF8 and the position of the bad byte.

    Changes you may notice#

    • extern "c" T x; declares C data (extern "c" u8 **environ;); a plain extern T x; is a ktm global defined elsewhere.
    • A for init can declare several variables (for (i64 i = 0, j = 10; i < j; i++, j--)), and its step can be several expressions.
    • A module built with ktm -lib can have globals with run-time initialisers: each module gets an init function that runs once, its imports first, before the program's own initialisers.
    • All REPL builtins are camelCase: replListFn, replFindFn, replReloadRc, replListGVars, replClassRep, replEval, replHeap (and replDisasm/replDel from v0.2.0).

    v0.2.0 (2026-10-11)#

    A new language. ktm now has its own C-like syntax, modules, methods and a standard library organised into modules. The old HolyC syntax is gone: every program, test, doc page and example in the repository was converted once with an internal tool, which was then deleted. Code written for v0.1.0 does not compile with v0.2.0.

    
enum Kind { circle, rect };

struct Shape { Kind kind; f64 w, h; };

f64 Shape.area() {
    switch (self.kind) {
        case Kind.circle: return 3.14159 * self.w * self.w;
        case Kind.rect:   return self.w * self.h;
    }
    throw(1, "unknown kind %d", self.kind);
    return 0;
}

i32 main(i32 argc, u8 **argv) {
    defer printf("bye\n");
    Shape s = {Kind.rect, 2, 3};
    printf("%.1f\n", s.area());
    return 0;
}

    The language#

    • C types and literals: void, i8 to u64, f32, f64, bool, true/false/null; digit separators (1_000_000); a character literal holds one character.
    • struct, C prefix casts (T)x, printf, i32 main(...), calls always with parentheses, file scope holds declarations only.
    • Typed constants: const i64 MAX = 4; (compile-time constants when the value is).
    • Scoped enums: enum Color { red, green }; used as Color.red, with an optional integer type (enum Status : u16 { ... }); converting an integer to an enum needs a cast.
    • Function types: fn(i64) i64, fn(u8 *) u8 *, (fn(i64) i64) * for a pointer to one. A function pointer only takes a function with the same signature.
    • Named varargs: i64 sum(i64 ...nums) with nums.len, indexing, range-for and spreading (sum(...nums)).
    • defer: block-scoped, runs on every exit (return, break, continue, goto, exceptions).
    • Errors: throw(code) or throw(code, "format", ...), caught as catch (Error e) with e.code, e.message, e.file and e.line; throw(e) rethrows. try and defer no longer make a system call each (7 to 12 times faster).
    • switch cases end at the next label; fallthrough; continues into the next one.
    • Braces are required on if/else/for/while/do bodies.
    • Methods: f64 Shape.area() { ... self ... }, called s.area(); derived structs inherit methods, a same-named method hides the base one, no virtual dispatch. . works on a value or a pointer (p.x is p->x).
    • Modules: a directory is a module (module net; in every file), import net, h = net.http;, pub exports, names private by default, private struct fields hidden outside their module, files of a module see each other in any order. ktm -lib builds a module or a tree of modules into a library that importers link automatically. A local may shadow a module name.

    The standard library#

    • Organised into modules: str, mem, fs, os, proc, signal, net, json, csv, sql, date, coro, thread, map, set, vec, list, math, fzf, plus libc for the C and POSIX functions under their C names. Names are camelCase: StrLen(s) is now cstr.len(s), StrMapSet(m, k, v) is m.set(k, v).
    • A prelude every file sees without an import: Error, the integer limits (I8_MIN to U64_MAX), EXIT_OK/EXIT_FAIL.
    • Dates are formatted with date.format(d, "%Y-%m-%d"); printf's %D, %T and %F are gone.
    • The TempleOS leftovers are gone (Dir, the directory printer, the verbose remove, the Fs task block).

    Removed#

    • The HolyC syntax: U0/I64/F64/Bool, class/public, postfix casts, print statements, calls without parentheses, Main, code at file scope, (...) with implicit argc/argv, C function-pointer declarators, multi-character literals.
    • std.ktmh and defs.ktmh (the library is imported as modules).
    • -transpile (it could not read the new syntax).
    • The REPL builtins Uf and ReplDel: they are replDisasm("name") and replDel("name").

    Fixes#

    • A program's own function named like a C library symbol (read, environ, free) no longer replaces it: program symbols are now named like module symbols.
    • Variadic C calls through a module's extern "c" pass their extra arguments correctly on Apple arm64 (open's mode was garbage).
    • A struct holding a not-yet-complete struct by value is an error (it compiled with size 0).
    • Statements after a { } block inside a switch case were dropped.
    • Global = null initialisers are constant data; a field of the compiler state was read uninitialised; narrow literals in untyped varargs filled only one byte; #undef took the next line's first word; several test races on macOS and the LSP debounce test.

    Known issue#

    On macOS, a child forked by a program run with -jit can crash right after fork(), rarely and under load. Compiled programs are fine; see Known issues for the workaround.

    v0.1.0 (2026-10-10)#

    Renamed from hcc v0.19.3. The language, the standard library and their behaviour are unchanged; only names are new.

    Changes you may notice#

    • The compiler is ktm (was hcc). Sources are .ktm, headers .ktmh; .HC and .HH are rejected with a message, on the command line and in #include.
    • The library header is std.ktmh (was tos.HH), the library libktm (was libtos, built with -lib ktm), its sources src/std/.
    • Environment variables, macros and defines are KTM_* (was HCC_*), e.g. KTM_INSTALL_DIR, KTM_TEST_TIMEOUT, __KTM_JIT__; temporary files and the REPL's files are named ktm too (~/.ktm_rc.ktm, ~/.ktm_repl_history).
    • The --terry option is gone; the history and credits are in the README.
