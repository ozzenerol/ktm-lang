    Modules

    A module is a directory of .ktm files. You import it and use its pub names with the module's name in front.

    At a glance

    // geo/shapes.ktm             // main.ktm
module geo;                   import geo;
pub i64 area(i64 s) {...}     geo.area(5);

import fs, str;               // several at once
import h = net.http;          // the directory net/http, named h
pub   private                 // exported; a field only the module sees

    A first module#

    Each file of the module starts with module and the directory's name.

    shapes/
├── main.ktm
└── geo/
    ├── shapes.ktm
    └── helpers.ktm
    // geo/shapes.ktm
module geo;

pub struct Point { i64 x, y; };
pub enum Kind { square, circle };
pub const i64 SIZE = 4;

pub i64 area(Kind k, i64 side)
{
  if (k == Kind.square) { return square(side); }   // in another file of geo
  return 3 * square(side);
}
    // geo/helpers.ktm
module geo;

i64 square(i64 n) { return n * n; }   // not pub: private to geo
    // main.ktm
import geo;

void main()
{
  geo.Point p = {1, 2};
  i64 cells[geo.SIZE];               // a module's const works in constant expressions
  printf("%d %d %d\n", geo.area(geo.Kind.square, 5), p.y, sizeof(cells));
}
    $ ktm main.ktm -o shapes && ./shapes
25 2 32

    Using a private name from outside is an error: `square` is private to module geo.

    Methods across modules#

    Only the module that defines a type can define its methods. Outside, its pub methods are called on the object with no prefix.

    // bank/account.ktm
module bank;

import mem;

pub struct Account { u8 *owner; i64 balance; };

pub Account *open(u8 *owner)
{
  Account *a = mem.allocZero(sizeof(Account));
  a.owner = owner;
  return a;
}

pub void Account.deposit(i64 x) { self.balance += x; self.audit(); }
void Account.audit() { }                 // private to bank
pub void Account.close() { mem.free(self); }
    // main.ktm
import bank;

void main()
{
  bank.Account *a = bank.open("ann");
  a.deposit(5);                          // no prefix on a method
  printf("%s %d\n", a.owner, a.balance);
  a.close();
}

    &bank.Account.deposit is the method as a function pointer.

    Private fields#

    A field marked private can only be used inside the module that defines the struct.

    // chat/conn.ktm
module chat;

pub struct Conn {
  i32 fd;              // public, as in C
  private u8 *buf;     // only chat uses it
};

pub void reset(Conn *c) { c.buf = null; }
    // main.ktm
import chat;

void main()
{
  chat.Conn c;
  c.fd = 3;                // fine
  chat.Conn copy = c;      // fine: only the name is hidden
  c.buf = null;            // error: `buf` is a private field of chat.Conn
}
    • Outside the module, reading, writing or taking the address of a private field is an error, and so is an initialiser list or a for that reaches it, or a struct inheriting it.
    • sizeof, copying and passing by value still work: the layout isn't hidden.
    • private fields exist only in modules. In the main program they are an error.
    • pub on a field is an error (fields are public unless marked).
    • The editor's completion leaves private fields out.

    Imports#

    WriteLoadsUse as
    import geo;the directory geogeo.area
    import fs, str;two modulesfs.readAll, str.from
    import net.http;the directory net/http (its files say module http;)http.get
    import h = net.http;the sameh.get
    • Imports come first in a file, before any declaration.
    • A module is looked for next to the main file, then in the standard library, then in each directory of KTM_PATH (separated by :).
    • A package from another repository is imported by its path in quotes, as in Go: import "github.com/user/repo"; (import p = "github.com/user/repo/sub"; for an alias). Its name is its module line. The project's ktm.mod says which version, and replace github.com/user/repo => ../repo uses a local copy. See Packages.
    • Found in two places is an error: name your modules differently from the standard library's.
    • An import that is never used is a warning, except import _ = m;: a blank import, for what the module does when the program starts (import _ = net.https; gives the HTTP client https://).

    Order of start-up#

    Each module is compiled once, before the code that imports it. A module's globals are set up before its importers' globals and before main; a module's files in name order.

    Two special modules#

    The prelude#

    Its pub names are seen by every file with no import and no prefix:

    • Error, the struct a catch binds;
    • EXIT_OK and EXIT_FAIL;
    • the integer limits I8_MIN, I8_MAX, U8_MAX ... I64_MIN, I64_MAX, U64_MAX;
    • ERR_BOUNDS, the code of an out-of-range index.
    void main()
{
  printf("%d %d %u\n", I32_MAX, I8_MIN, U16_MAX);
  printf("%d %d\n", EXIT_OK, EXIT_FAIL);
}

    2147483647 -128 65535
0 1

    The runtime#

    rt is part of every program but is internal: import rt; outside the standard library is an error.

    Shadowing a module#

    A local or a parameter may have an import's name; for its scope the name is the local.

    import str;

i64 count(u8[] str)          // the parameter hides the module here
{
  return str.len;
}

void main()
{
  ad String s = str.from("module again");   // and here it's the module
  printf("%d %s\n", count("four"), s);
}

    4 module again

    A member the local doesn't have is an error that says so: u8 * has no member `len` (note: the local `str` hides the module str).

    Errors#

    • Using a name that isn't pub from outside its module.
    • A module not found, or found twice.
    • An import cycle: the message shows it, a -> b -> a.
    • A file whose module line is missing or doesn't match its directory.
    • A global with an import's name (i64 geo; would hide the module).
    • A cycle of structs that hold each other by value: one of them needs a pointer.

    Symbols#

    A module's names get symbols of their own (geo.area is _K3geo4area), so they never clash with C functions or the program's names. A C function a module declares with extern "c" keeps its C symbol.

    To compile a module once and link it as a library, see Building libraries.
