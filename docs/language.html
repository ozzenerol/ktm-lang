    The ktm language

    A complete tour of the ktm language. If you know C, most of it will look familiar. The differences are where ktm gets interesting.

    Program structure#

    A program is one or more .ktm files. Its entry point is main, as in C: i32 main(), i32 main(i32 argc, u8 **argv) or void main(); the value it returns is the exit code (0 for void main). The older name Main still works for now; a program can't have both. Code at the top level runs in order before main (top-level code can't return: that is a compile error). A program can be a single line:

    "Hello\n";

    Hello

    Comments are the same as in C: // to the end of the line and /* across lines */. Block comments don't nest, and one still open at the end of a file is an error (unterminated comment). Statements end with ; and blocks use { }. Header files conventionally end in .ktmh.

    Printing#

    printf(fmt, ...) prints, as in C:

    U0 Main()
{
  printf("plain text\n");
  printf("%s is %d years old\n", "Ada", 36);
  printf("%5d|%-5d|%05d\n", 42, 42, 42);
  printf("%x %X %c %.3f\n", 255, 255, 'A', 3.14159);
}

    plain text
Ada is 36 years old
   42|42   |00042
ff FF A 3.142

    The conversions are the ones StrPrint knows (see the library guide), ktm's own included: %Q prints a string escaped as a C literal, %C a character in upper case, %D and %T the date and time of a CDate, and %F the contents of a file. The compiler checks the number of arguments against them.

    U0 Main()
{
  printf("%Q\n", "say \"hi\"\n");
  printf("%C%c\n", 'h', 'i');
}

    say \"hi\"\n
Hi

    The string is always a format, even without arguments, so write %% for a literal percent sign: printf("100%%\n"); prints 100%. The older print statement, a string on its own with the arguments after a comma ("%d\n", x;), does the same and still works for now.

    %d, %i, %u, %x, %X and %o print the full 64-bit value, so there is no need for C's %ld (which also works):

    U0 Main()
{
  I64 big = 5000000000;
  "%d vs %ld\n", big, big;
}

    5000000000 vs 5000000000

    Types#

    TypeSizeMeaning
    void0Nothing
    bool1TRUE (1) or FALSE (0): any other value converted to it is 1 if it isn't 0
    i8 / u81Signed / unsigned byte; u8 is the character type
    i16 / u16216-bit integers
    i32 / u32432-bit integers
    i64 / u64864-bit integers, the default integer type
    f648Double-precision float
    f324Single-precision float

    The older names U0, Bool, I8 ... U64, F32 and F64 still work for now and mean the same types. The new names are type names, not keywords, so a struct field can still be called i64 or f64; a variable can't.

    Pointers are written as in C (U8 *s, I64 **pp) and are 8 bytes. null is the null pointer: 0 as a U0 *, so it can be assigned to any pointer or function pointer. true and false are Bool values, 1 and 0. The older NULL, TRUE and FALSE (plain 0, 1 and 0) still work for now.

    As in C, a value becomes a Bool by comparing it with 0: an integer, float or pointer that isn't 0 (or NULL) is TRUE, whether it is assigned, passed as an argument, returned, stored in a field or cast with x(Bool). Only the low byte is never kept, so 0x100 and 0.5 are TRUE. A pointer needs no cast to become a Bool (other integer types warn without one), and messages and typeof call the type bool.

    Bool IsSet(I64 flags, I64 bit) { return flags & bit; }

U0 Main()
{
  Bool b = 0x100;
  "%d %d %d %d\n", b, IsSet(0x800, 0x800), 0.5(Bool), (-1)(Bool);
}

    1 1 1 1

    U0 Main()
{
  "%d %d %d %d %d\n", sizeof(U8), sizeof(I16), sizeof(I32), sizeof(I64), sizeof(F32);
  "%d %d\n", sizeof(U8 *), sizeof(Bool);
}

    Literals#

    U0 Main()
{
  I64 dec = 42, hex = 0xFF, bin = 0b1010;
  F64 f = 1.5e3, g = 2e-3;
  "%d %d %d %.1f %.3f\n", dec, hex, bin, f, g;

  // Character constants hold up to 8 characters, packed into an integer
  // (the first in the low byte), and take the same escapes as strings.
  I64 one = 'A', many = 'Hi';
  "%d %d %c\n", one, many, one;

  "tab:[\t] quote:[\"] backslash:[\\]\n";
}

    42 255 10 1500.0 0.002
65 26952 A
tab:[	] quote:["] backslash:[\]

    Integers can be written in decimal, hex (0x) or binary (0b). A number with a . or an exponent (1e3, 2e-3) is an F64. Multi-character constants are a ktm idiom for short tags, such as the values thrown by exceptions. String literals are U8 *.

    Strings take the C escapes \n \t \r \b \f \v \a \\ \' \", and \d for $. \x takes at most two hex digits, so "\x01b" is the bytes 1 and 'b', and \0 to \7 start an octal escape of up to three digits ("\033" is ESC). Every string literal ends in a NUL that sizeof counts: sizeof("\x42") is 2.

    An integer literal too big for I64 is a U64. A malformed number is a compile error that says what is wrong with it: 0x or 0b with no digits, a digit that doesn't fit the base (0b102), a letter after a decimal number (12ab) or an exponent with no digits (1e).

    ktm has no octal literals: leading zeros don't change the base, so 0644 is the decimal number 644 (C reads it as octal 420). Because code copied from C would silently change value, ktm warns at such a literal and suggests the hex spelling (0x1A4 for octal 0644). Literals that mean the same in both, like 00 or 07, and floats like 00.5 are not warned about.

    _ may appear between two digits of a number literal and is ignored, to group long ones for reading: 1_000_000, 0xFF_FF, 0b1010_0101, 1_000.25. It is only valid between two digits of the literal's own base, so misplaced at the start or end, next to . or the exponent, or doubled, it is a compile error. A leading _ is still an identifier (_100 is a name, not a number).

    U0 Main()
{
  I64 million = 1_000_000;
  I64 word = 0xFF_FF;
  F64 price = 1_000.25;
  "%d %d %.2f\n", million, word, price;
}

    1000000 65535 1000.25

    Variables#

    Declare variables anywhere in a block, or at file scope for globals. Several can share one declaration, inside a function or at global scope; each * belongs to the name after it:

    I64 g_total = 100, g_count; // globals, visible to everything below them

U0 Main()
{
  I64 a = 1, b = 2, c;
  c = a + b;
  F64 ratio = 0.25;
  U8 *name = "ktm", letter = 'h';
  "%d %d %d %.2f %s %c\n", c, g_total, g_count, ratio, name, letter;
}

    3 100 0 0.25 ktm h

    auto#

    auto takes its type from the initialiser:

    U0 Main()
{
  auto count = 3;
  auto price = 9.99;
  auto label = "total";
  "%s %s %s\n", typeof(count), typeof(price), typeof(label);
}

    i64 f64 u8[6]

    static#

    A static local keeps its value between calls:

    I64 NextId()
{
  static I64 id = 0;
  id++;
  return id;
}

U0 Main()
{
  NextId;
  NextId;
  "%d\n", NextId;
}

    const#

    const marks a declaration read-only; it is not a type qualifier like C's. An initializer is required (except on a function parameter). A const of integer type whose initializer is itself a constant expression is a compile-time constant: usable in an array size, a case label, or another const's initializer. Assigning to a const (=, a compound assignment, ++/--), including a const parameter, is a compile error, and so is writing const anywhere but a declaration (a cast, a struct field, a return type, or after the type).

    const I64 MAX_USERS = 4;
const I64 DOUBLE_MAX = MAX_USERS * 2;   // built from another const
I64 g_users[MAX_USERS];                 // a const works as an array size

I64 Classify(I64 n)
{
  switch (n) {
    case MAX_USERS: return 1;           // and as a case label
    default:        return 0;
  }
}

I64 Twice(const I64 n)                  // n cannot be assigned inside Twice
{
  return n * 2;
}

U0 Main()
{
  "%d %d %d %d\n", MAX_USERS, DOUBLE_MAX, Classify(4), Twice(21);
}

    4 8 1 42

    Operators#

    The C operators work as expected: + - * / %, & | ^ ~ << >>, && || !, == != < <= > >=, compound assignment (+=, <<=, …) and ++ / --.

    U0 Main()
{
  I64 a = 7, b = 2;
  "%d %d %d %d %d\n", a + b, a - b, a * b, a / b, a % b;
  "%d %d %d %d %d\n", a & b, a | b, a ^ b, a << 2, a >> 1;
  a += 3;
  a++;
  "%d\n", a;
}

    9 5 14 3 1
2 7 5 28 3
11

    &&, ||, ! and the comparisons always give 0 or 1. A float operand of &&, || or ! is true when it isn't 0.0, and a pointer when it isn't NULL. Comparing an integer with a float compares them as floats. On U64 values, >>, /, % and the comparisons are unsigned. An assignment used as a value has the type of its left side, so the value is truncated to fit:

    U0 Main()
{
  F64 half = 0.5;
  U8 *none = NULL;
  "%d %d %d %d\n", half && 1, !half, none || 0, !none;
  "%d\n", 2 < 2.5;

  U64 big = 0xFFFFFFFFFFFFFFFF;
  "%d %d\n", big > 1, big >> 60;

  U8 c;
  I64 v = (c = 300);
  "%d\n", v;
}

    1 0 0 1
1
1 15
44

    Unary - and + need a number and ~ needs an integer: -p on a pointer or ~f on an F64 is a compile error. A narrower integer operand is widened to I64 first.

    Comparisons can be chained, as in maths: lo < x < hi means lo < x && x < hi.

    U0 Main()
{
  I64 x = 5;
  "%d %d\n", 1 < x < 10, 1 < x < 3;
}

    1 0

    There is no ?: operator. Use if/else.

    typeof is an ktm addition. It becomes a string naming the type at compile time, and its operand is never evaluated.

    Type casts#

    Casts are written as in C, (T)x: the type in parentheses before the value. A cast is a unary operator, so it binds tighter than any binary operator ((F64)a / b divides as floats) and applies to the whole postfix expression after it ((I64)p->n casts p->n). Any type works, including pointers, classes and function pointers ((I64 (*)(I64))p). A variable hides a type of the same name, so (x) stays a value in parentheses.

    U0 Main()
{
  F64 f = 3.9;
  I64 i = (I64)f;            // truncates
  "%d\n", i;
  "%.1f %.1f\n", (F64)(7 / 2), (F64)7 / 2;
  "%.1f\n", (F64)-i / 2;     // ((F64)-i) / 2

  U8 *s = "hey";
  I64 address = (I64)s;
  "%c\n", *(U8 *)address;
}

    3
3.0 3.5
-1.5
h

    The older postfix form, x(F64), still works for now.

    Control flow#

    if and else#

    U0 Main()
{
  I64 n = 15;
  if (n % 15 == 0) {
    "FizzBuzz\n";
  } else if (n % 3 == 0) {
    "Fizz\n";
  } else {
    "%d\n", n;
  }

  // An initialiser can come before the condition, scoped to the if.
  if (I64 half = n / 2; half > 5) {
    "half is %d\n", half;
  }
}

    switch#

    case takes a value or a range lo ... hi. Cases fall through without break, as in C.

    U0 Grade(I64 score)
{
  switch (score) {
    case 90 ... 100: "A\n"; break;
    case 80 ... 89:  "B\n"; break;
    case 0:          "no score\n"; break;
    default:         "C or below\n";
  }
}

U0 Main()
{
  Grade(95);
  Grade(83);
  Grade(0);
  Grade(42);
}

B
no score
C or below

    Two extras over C: a bare case: takes the previous case's value plus one (starting from 0), and switch [x] skips the range check on x, for speed when you know it's in range.

    U0 Main()
{
  for (I64 i = 0; i < 6; i++) {
    switch [i] {
      case 0: "zero "; break;
      case:   "one "; break;      // 1
      case:   "two "; break;      // 2
      case 4...5: "four-five "; break;
      default: "other "; break;
    }
  }
  "\n";
}

    zero one two other four-five four-five

    fallthrough; (ktm syntax v0.2) marks a case that goes on into the next one. Cases fall through anyway for now, so it changes nothing yet; it is an error outside a switch and as the last statement of the last case, where there is no next case. A variable called fallthrough still works.

    U0 Main()
{
  for (I64 i = 1; i <= 3; i++) {
    switch (i) {
      case 1: "one, "; fallthrough;
      case 2: "two or after one\n"; break;
      default: "three\n";
    }
  }
}

    one, two or after one
two or after one
three

    Loops#

    U0 Main()
{
  I64 i = 0;
  while (i < 3) {

    Range-based for#

    An ktm addition. Loop over a fixed-size array, or over any class with an entries field and a size field, such as the library's IntVec and PtrVec:

    U0 Main()
{
  I64 primes[] = {2, 3, 5, 7, 11};
  I64 sum = 0;
  for (auto p : primes) {
    sum += p;
  }
  "sum = %d\n", sum;

  IntVec *v = IntVecNew();
  IntVecPush(v, 10);
  IntVecPush(v, 20);
  for (I64 x : v) "%d\n", x;
  IntVecRelease(v);
}

    Functions#

    I64 Square(I64 n)
{
  return n * n;
}

U0 Main()
{
  "%d\n", Square(12);
}

    144

    Declare a prototype to call a function before its definition: I64 Later(I64 x); Every prototype and the definition must agree on the return and parameter types; a mismatch is an error ("conflicting types") at the later one. That includes the standard library's functions, whether std.ktmh declares them as prototypes or as _extern bindings: a function of your own named Exit or MAlloc must have the library's signature. Default arguments carry over: after I64 Later(I64 x=1); the definition can be written I64 Later(I64 x) { ... } and Later() still passes 1 (this includes the prototypes in std.ktmh). Repeating a default is allowed if it is the same value; a different value is an error.

    A program may define its own version of a standard-library function, with the same signature as in std.ktmh (CDate Now(), say): the program's calls go to its own version, in the JIT and in a compiled binary. The library's own internal calls are not redirected under the JIT; in a compiled binary, which links the static libktm.a, they may go to your version too, so keep its behaviour compatible.

    A returned value is converted to the function's return type, as in C: an integer returned from an F64 function becomes a float. In a U0 function, return expr; is a warning ("unexpected return value"), but the expression is still evaluated for its side effects.

    inline is accepted as a hint only: an inline function is compiled as an ordinary function, so it can recurse, take default arguments and have its address taken.

    inline I64 Twice(I64 x)
{
  return x * 2;
}

U0 Main()
{
  I64 (*fp)(I64 x) = &Twice;
  "%d %d\n", Twice(21), fp(4);
}

    42 8

    Default arguments#

    Any parameter can have a default, not just trailing ones. Leave an argument empty to use its default:

    U0 Box(I64 w = 2, I64 h = 3, U8 *fill = "#")
{
  "%dx%d of %s\n", w, h, fill;
}

U0 Main()
{
  Box(5, 1, "*");
  Box(5);
  Box(, 9);
  Box(, , "@");
}

    Calling without parentheses#

    A function that needs no arguments can be called by name alone, anywhere in an expression. Use &Name for the function's address:

    U0 Greet()
{
  "hi\n";
}

I64 Answer()
{
  return 42;
}

U0 Main()
{
  Greet;
  "%d\n", Answer;
  "%d\n", Answer + 1;
}

    Variable arguments#

    The last parameter can take any number of extra arguments, zero included: T ...name takes them as values of type T, each checked and converted like an argument to a T parameter (a wrong type is an error). Inside the function name.len is how many there are, name[i] is one of them (&name[i] works too) and for (auto v : name) goes through them; name itself can't be assigned. Fixed and default parameters can come before it.

    I64 Sum(I64 ...nums)
{
  I64 total = 0;
  for (auto n : nums) total += n;
  return total;
}

F64 Avg(F64 ...xs)
{
  if (!xs.len) return 0;
  F64 total = 0;
  for (I64 i = 0; i < xs.len; i++) total += xs[i];   // 1 and 2 become 1.0, 2.0
  return total / xs.len;
}

I64 Total(I64 ...nums)
{
  return Sum(...nums);   // pass them all on
}

U0 Main()
{
  "%d %d %d\n", Sum(), Sum(1, 2, 3, 4), Total(5, 6);
  "%.2f\n", Avg(1, 2, 4);
}

    0 10 11
2.33

    ...name as the last argument of a call passes the extras of a variadic parameter on, to a function that takes the same kind (it must be the only extra argument). Without a type, ...name takes the extras as 64-bit slots, the way format functions want them: a number as is, a float as its bits (read it back with name[i](F64)), a pointer as its address:

    U0 Log(U8 *fmt, ...args)
{
  U8 *msg = StrPrintJoin(NULL, fmt, args.len, args);   // format the extras
  "[log] %s\n", msg;
  Free(msg);
}

U0 Main()
{
  Log("%d files in %s, %.1f%% full", 3, "/tmp", 42.5);
}

    [log] 3 files in /tmp, 42.5% full

    The extras are passed as their count and a pointer to an array the caller builds, so spreading them on costs nothing. The older ... with no name, which gives the function hidden argc and argv variables, still works until the conversion.

    Function pointers#

    I64 Add(I64 a, I64 b) { return a + b; }
I64 Mul(I64 a, I64 b) { return a * b; }

I64 Fold(I64 (*op)(I64 a, I64 b), I64 *nums, I64 n)
{
  I64 acc = nums[0];
  for (I64 i = 1; i < n; i++) {
    acc = op(acc, nums[i]);
  }
  return acc;
}

U0 Main()
{
  I64 nums[] = {1, 2, 3, 4};
  I64 (*f)(I64 a, I64 b) = &Mul;
  "%d %d\n", Fold(&Add, nums, 4), Fold(f, nums, 4);
}

    As in C, * on a function pointer gives the function pointer back, so (*f)(acc, x), (*c.op)(5) and (*ops[i])(5) call it just like f(acc, x).

    Any expression whose type is a function pointer can be called: a cast to a function pointer type (((I64 (*)(I64))p)(5), or p(I64 (*)(I64))(5) as a postfix cast), the result of a call that returns one, or of an assignment ((f = &Mul)(2, 3)). The arguments are checked against the pointer's parameters, as for a named function:

    I64 Add(I64 a, I64 b) { return a + b; }
I64 Mul(I64 a, I64 b) { return a * b; }

U0 *Lookup(U8 *name)
{
  if (!StrCmp(name, "add")) return &Add;
  return &Mul;
}

U0 Main()
{
  I64 (*f)(I64 a, I64 b);
  "%d\n", ((I64 (*)(I64, I64))Lookup("add"))(2, 3);
  "%d\n", Lookup("mul")(I64 (*)(I64, I64))(2, 3);
  "%d\n", (f = &Mul)(4, 5);
}

    A default in a function pointer's parameter list fills a left-out argument when you call through it, for variables and class fields alike. A U0 * converts to and from a function pointer without a cast, and compares (==, !=) with one:

    I64 Dbl(I64 x) { return x * 2; }

class Calc { I64 (*op)(I64 x = 21); };

U0 Main()
{
  Calc c;
  c.op = &Dbl;
  "%d %d\n", c.op(5), c.op();

  U0 *raw = &Dbl;
  I64 (*back)(I64 x) = raw;
  "%d %d\n", back(4), raw == &Dbl;
}

    A function pointer only takes a function, or a function pointer, with the same signature: the same return type, the same parameter types and the same .... Anything else is an error naming both types, wherever the conversion happens (an assignment, an initialiser, an argument, a return or a conditional), so i64 (*op)(u8 *) = &t; with a t taking an i64 gives cannot convert fn(i64) i64 to fn(u8*) i64. A U0 * and null still convert without a cast. A function whose parameters are typed pointers, passed where one taking U0 * is expected (a comparator, a thread function), needs a cast, which makes the mismatch visible:

    class Item { I64 key; };

I64 ItemLess(Item *a, Item *b) { return a->key < b->key; }

U0 Main()
{
  Item a, b;
  a.key = 1;
  b.key = 2;
  I64 (*cmp)(U0 *, U0 *) = (&ItemLess)(fn(U0 *, U0 *) I64);
  "%d\n", cmp(&a, &b);
}

    The other C declarator forms work too: a function returning a function pointer is written T (*Name(params))(fn_params), and a pointer to a function pointer is T (**pp)(params), for locals, globals, class fields and parameters alike.

    I64 Dbl(I64 x) { return x * 2; }
I64 Sq(I64 x) { return x * x; }

I64 (*Choose(Bool square))(I64 x)
{
  if (square) return &Sq;
  return &Dbl;
}

U0 Main()
{
  I64 (*f)(I64 x) = Choose(TRUE);
  I64 (**pf)(I64 x) = &f;
  printf("%d ", f(5));
  *pf = Choose(FALSE);        // changes f through the pointer
  printf("%d\n", f(5));
}

    fn(...) types#

    ktm syntax v0.2 adds fn ( types ) RetType as a way to write a function pointer type: fn(i64) i64 is exactly i64 (*)(i64), with the same size, the same calls, and the same argument checks. Parameter names are optional and ignored. RetType can itself be another fn(...) type:

    i64 twice(i64 x) { return x * 2; }
i64 addOne(i64 x) { return x + 1; }

fn(i64) i64 op = &twice;
fn(i64) i64 pick(bool sq) { if (sq) return &twice; return &addOne; }
void apply(fn(i64) i64 f, i64 x) { "%d\n", f(x); }

i32 main()
{
  apply(op, 5);
  fn(i64) i64 g = pick(true);
  "%d\n", g(5);
  return 0;
}

10

    A * after the return type is part of it: fn(u8 *) u8 * returns a u8 *. A pointer to a function pointer puts the fn type in parentheses, (fn(i64) i64) *slot, in declarations, parameters, fields, casts, sizeof and typeof, and typeof prints it that way. Parameters can have defaults, filled in when a call through the pointer leaves them out, and take varargs in every form a function does (..., ...args, i64 ...nums):

    u8 *skip(u8 *s) { return s + 1; }
i64 add(i64 a, i64 b) { return a + b; }
i64 count(...args) { return args.len; }

i32 main()
{
  fn(u8 *) u8 * f = &skip;
  fn(i64 a, i64 b = 10) i64 k = &add;
  fn(...args) i64 c = &count;
  (fn(u8 *) u8 *) *pf = &f;
  "%s %d %d %d %s\n", f("xyz"), k(1), k(1, 2), c(4, 5, 6), (*pf)("ab");
  return 0;
}

    yz 11 3 3 b

    fn is a contextual keyword: old code that uses it as a plain identifier (fn(x), fn = &f) keeps working, since a bare fn only starts a type where a type can start and only when a real parameter list and a return type follow it. The old C declarator form (i64 (*)(i64), an array of them, a function returning one, a pointer to one) is documented above and keeps working; it is converted to fn(...) everywhere in a later pass.

    Pointers and arrays#

    U0 Main()
{
  I64 x = 5;
  I64 *p = &x;
  *p = 10;
  "%d\n", x;

  I64 squares[5];
  for (I64 i = 0; i < 5; i++) {
    squares[i] = i * i;
  }
  I64 *q = squares;              // arrays decay to pointers
  "%d %d %d\n", q[3], *(q + 4), &squares[4] - &squares[1];

  I64 grid[3][4];
  grid[2][3] = 7;
  "%d %d\n", grid[2][3], sizeof(grid);
}

9 16 3
7 96

    As in C, n + p is the same as p + n, a pointer can be compared with an integer on either side, and n - p is a compile error. An array can't be assigned as a whole (a = b; is an error): assign its elements or copy it with MemCpy.

    Storing one pointer type in another is a warning, as in C: I64 *q = &f; with F64 f (also when assigning, passing or returning it), and q -= q, which stores a pointer difference (an integer) back into the pointer. U0 * and byte pointers (U8 *, I8 *, Bool *) convert to and from any pointer without one; otherwise cast: (&f)(I64 *).

    Call arguments are checked against the parameter types as in C, for functions, function pointers and extern functions alike. Numbers convert silently (an I64 passed for an F64 becomes a float), 0 and null pass as any pointer, U0 * converts both ways, and a pointer to a derived class is a pointer to its base class. A pointer passed for an integer, an integer for a pointer (other than 0) and a pointer to an incompatible type are warnings (Twice("str"): "makes an integer from a pointer without a cast"); a class passed where another class or a number is expected, or a number or pointer where a class or a float is, is an error. Extra arguments of a ... function are not checked.

    An initialiser list may be shorter than the array or class it initialises; as in C, everything it leaves out is zero, for locals and globals alike:

    class Point { I64 x, y, z; };

I64 counts[4] = {1, 2};

U0 Main()
{
  I64 grid[2][3] = {{1}, {4, 5}};
  Point p = {7};
  "%d %d %d %d\n", counts[0], counts[1], counts[2], counts[3];
  "%d %d %d | %d %d %d\n", grid[0][0], grid[0][1], grid[0][2],
                           grid[1][0], grid[1][1], grid[1][2];
  "%d %d %d\n", p.x, p.y, p.z;
}

    Unlike C, braces only go around an array, class or union: a scalar can't be initialised from a list (I64 x = {1};), and neither can a scalar element or field (I64 a[2] = {1, {2}};). Both are compile errors.

    As in C, the braces of an inner array or class can be left out: its items are then taken from the list in order, as many as it has, and a list that ends early zero-fills the rest. A string still initialises a whole U8 array, and a value of the class itself a whole class field.

    class Point { I64 x, y; };
class Line { I64 id; Point a, b; };

Line ln = {1, 2, 3, 4, 5};
Point pts[] = {1, 2, 3};

U0 Main()
{
  I64 m[2][2] = {1, 2, 3};
  "%d (%d %d) (%d %d)\n", ln.id, ln.a.x, ln.a.y, ln.b.x, ln.b.y;
  "%d: (%d %d) (%d %d)\n", sizeof(pts) / sizeof(Point), pts[0].x, pts[0].y,
                           pts[1].x, pts[1].y;
  "%d %d %d %d\n", m[0][0], m[0][1], m[1][0], m[1][1];
}

    The items of a global array or class initialiser need not be constants: an item such as another global's value or the address of a function or a global is stored when the program starts, in order with the other file-scope statements, the way I64 g = other; is.

    I64 Dbl(I64 v) { return v * 2; }
I64 Sq(I64 v) { return v * v; }

class Op { U8 *name; I64 (*fn)(I64 v); };

    MAlloc allocates, CAlloc allocates zeroed memory, ReAlloc resizes and Free releases. Nothing is garbage collected.

    Strings#

    Strings are NUL-terminated U8 arrays, as in C. The library has the usual helpers (more in the library guide):

    U0 Main()
{
  U8 *copy = StrNew("hello");
  "%s %d %d\n", copy, StrLen(copy), StrCmp(copy, "hello");

  U8 *msg = StrPrint(NULL, "%s has %d letters", copy, StrLen(copy));
  "%s\n", msg;

  I64 vowels = 0;
  for (U8 *c = copy; *c; c++) {
    if (*c == 'e' || *c == 'o') vowels++;
  }
  "%d vowels\n", vowels;
  Free(copy);
  Free(msg);
}

    A U8 array initialised from a string gets its own writable copy. With an explicit size, the rest is zero-filled:

    U0 Main()
{
  U8 buf[] = "abc";               // 4 bytes: a, b, c, NUL
  U8 name[8] = "hi";              // the 6 bytes after "hi" are zero
  buf[0] = 'X';
  "%s %d %s %d\n", buf, sizeof(buf), name, sizeof(name);

    Classes#

    A struct (or class, the same thing) is a C struct, and its name is a type straight away, with no typedef needed. Several fields can share a line. pub (or public) marks what a library exports.

    class Point
{
  I64 x, y;
};

Point Make(I64 x, I64 y)          // classes can be returned by value
{
  Point r;
  r.x = x;
  r.y = y;
  return r;
}

I64 Sum(Point p)                  // and passed by value
{
  return p.x + p.y;
}

U0 Main()
{
  Point a = {1, 2};               // initialise fields in order
  Point c = Make(11, 22);
  "%d %d %d\n", c.x, c.y, Sum(a);

  Point copy = c;                 // assignment copies
  copy.x = 0;
  "%d %d\n", c.x, copy.x;

  Point *p = MAlloc(sizeof(Point));
  p->x = 5;                       // -> through a pointer
  p.y = 6;                        // . works through one pointer too
  "%d %d\n", p->x, p.y;
  Free(p);
}

11 0
5 6

    p.x on a pointer to a class is p->x. It goes through one pointer only: on a Point **pp, pp.x is an error and (*pp).x or pp[0].x is what you write.

    A field that is itself a class or an array takes a nested list:

    class Point { I64 x, y; };
class Line  { Point from, to; I64 tags[2]; };

Line l = {{0, 0}, {3, 4}, {7, 8}};

U0 Main()
{
  Line m = {{1, 2}, {5, 6}, {9, 10}};

    A class declared ahead with class Node; can be pointed to straight away, but a field can hold it by value only once its definition has been seen, since until then its size isn't known: class B; class A { B b; }; is the error field `b` of A holds a B, which is not complete here: use a pointer, as is a class holding itself. Define B first, or use a B * field.

    A string for a U8 array field or row is copied in the same way, and must fit with its NUL. A U8 * field points at the string instead:

    Inheritance#

    A class can extend one other class. It starts with all of the base class's fields, so a pointer to it can be used wherever the base class is expected:

    class Shape
{
  U8 *name;
  F64 (*area)(Shape *s);
};

class Circle : Shape
{
  F64 r;
};

class Rect : Shape
{
  F64 w, h;
};

F64 CircleArea(Shape *s) { Circle *c = s; return 3.14159 * c->r * c->r; }
F64 RectArea(Shape *s)   { Rect *r = s; return r->w * r->h; }

U0 Main()
{
  Circle c;
  c.name = "circle";
  c.area = &CircleArea;
  c.r = 1.0;

  Rect r;
  r.name = "rect";
  r.area = &RectArea;
  r.w = 2.0;
  r.h = 3.0;

  Shape *shapes[2];
  shapes[0] = &c;
  shapes[1] = &r;
  for (I64 i = 0; i < 2; i++) {
    "%s: %.2f\n", shapes[i]->name, shapes[i]->area(shapes[i]);
  }
}

    circle: 3.14
rect: 6.00

    Methods#

    A method is written outside its struct, as a function named Type.name. Inside, self is a pointer to the object it was called on (a User * here), and it can't be assigned. A method is called on a value or on a pointer, with . or ->:

    struct User
{
  u8 *name;
  i64 age;
};

struct Admin : User
{
  i64 level;
};

void User.describe()
{
  "%s is %d\n", self.name, self.age;
}

i64 User.older(i64 years = 1)    // default arguments and `T ...name` work as usual
{
  self.age += years;             // self points at the caller's object
  return self.age;
}

void Admin.describe()            // hides User.describe for an Admin
{
  "admin %d: ", self.level;
  User.describe(self);           // the base's, called explicitly
}

void main()
{
  User u = {"ann", 30};
  User *p = &u;
  u.describe();
  p.older(5);                    // the same as p->older(5)
  p.describe();

  Admin a;
  a.name = "bob";
  a.age = 40;
  a.level = 2;
  a.older();                     // inherited from User
  a.describe();

  User *as_user = &a;
  as_user.describe();            // no virtual dispatch: the pointer's type decides

  fn(User *) void f = &User.describe;   // a method is a function taking self first
  f(p);
}

    ann is 30
ann is 35
admin 2: bob is 41
bob is 41
ann is 35

    A derived struct has its base's methods; a method of the same name on it hides the base's, which Base.name(self) still calls. Which method runs is decided by the type the compiler sees, never at run time. &User.describe is an ordinary function pointer whose first parameter is self, so it works as a callback; u.describe without () is an error (there are no bound methods). A prototype, void User.describe();, declares a method defined later, and static keeps one to its file. A union can have methods too.

    These are compile errors: a method with the name of a field (inherited ones included), the same method defined twice, a method of something that isn't a struct or union, a method added to a type of the standard library or of another module, and a parameter named self. Methods are not supported with -transpile.

    All fields of a union share the same memory:

    union Bits

U0 Main()

    An initialiser list gives a union one item, for its first field. A union can also be anonymous inside a class: its fields are used as the class's own, and it still takes one item:

    union Num { I32 i; F32 f; };
class Token { U8 kind; union { I32 ival; F32 fval; }; I64 line; };

Num n = {7};

U0 Main()

    A class or union defined inside a class can also have a tag. Without a field name its fields are still the class's own, and the tag can be used as a type elsewhere; with a field name it is the type of that field:

    class Shape

    Enums#

    An enum is a scoped set of named integer constants, at file scope only. The first member is 0, then each next one is the previous plus 1, unless it has its own = constexpr; an earlier member can be used unqualified inside the braces. The underlying type defaults to i32; : Type picks any other integer type, and sizeof/alignof follow it. Outside the braces a member is only reachable as Name.member, which is itself an integer constant expression (an array size, a case label, another const's initialiser):

    enum Color { red, green, blue };
enum Status : u16 { ok = 200, notFound = 404, gone };
pub enum Mode { read = 1, write = 2, both = read | write };

i32 main()
{
  Color c = Color.green;
  i64 sizes[Color.blue + 1];
  switch (c) {
    case Color.red:   "red\n"; break;
    case Color.green: "green\n"; break;
    case Color.blue:  "blue\n"; break;
  }
  "%d %d %d\n", sizeof(sizes), Status.gone, Mode.both;
  return 0;
}

    green
24 405 3

    An enum value converts to any integer type implicitly, as arithmetic and comparisons with integers do; an integer, or a different enum, needs a cast to become one ((Color)2). Two different enums never mix without a cast either.

    Modules#

    A module is a directory of .ktm files. Each file in it starts with module and the directory's name, and a program uses it with import; its names are then written with the module's name in front:

    // geo/shapes.ktm
module geo;

pub struct Point { i64 x; i64 y; };
pub enum Kind { square, circle };
pub const i64 SIZE = 4;

pub i64 area(Kind k, i64 side) {
  if (k == Kind.square) return square(side);   // square() is in another file of geo
  return 3 * side * side;
}

// geo/helpers.ktm
module geo;

i64 square(i64 n) { return n * n; }             // private to geo

// main.ktm
import geo;

i32 main() {
  geo.Point p;
  i64 cells[geo.SIZE];
  printf("%d\n", geo.area(geo.Kind.square, 5));
  return 0;
}

    Inside a module every name of every one of its files is visible, in any order: a function can call one defined in a later file, and a struct can hold a later file's struct (by value too), enum or const (as an array size). Only a cycle of structs that hold each other by value is an error: one of them needs a pointer. Outside it, only the names marked pub are, and always through the prefix (geo.area, the type geo.Point, geo.Kind.square, geo.SIZE, which works in constant expressions too). A module can't use the names its program defines: a library doesn't depend on whoever uses it. The C functions it declares with extern "c" are its own names as well, private unless pub.

    Only the module that defines a type can define its methods. Outside it, the pub methods are called on the object with no prefix (a.deposit(5) on a bank.Account *a), and &bank.Account.deposit is one as a function pointer; a method that isn't pub is private to the module:

    // bank/account.ktm
module bank;

pub struct Account { u8 *owner; i64 balance; };

pub Account *open(u8 *owner) {
  Account *a = MAlloc(sizeof(Account));
  a.owner = owner;
  a.balance = 0;
  return a;
}

pub void Account.deposit(i64 x) { self.balance += x; self.audit(); }
void Account.audit() { }                         // private to bank

// main.ktm
import bank;

i32 main() {
  bank.Account *a = bank.open("ann");
  a.deposit(5);
  return 0;
}

    A field marked private can be used only inside the module that defines its struct: in any of the module's files, its functions and its methods. Outside, reading or writing it, taking its address, an initialiser list that reaches it, a range-based for over it and a struct that inherits it all say `buf` is a private field of net.Conn. The rest of the struct stays usable: its public fields, sizeof, copying it and passing it by value, since only the names are hidden, not the layout:

    // net/conn.ktm
module net;

pub struct Conn {
  i32 fd;              // public, as in C
  private u8 *buf;     // only net uses it
};

pub u8 *peek(Conn *c) { return c.buf; }

// main.ktm
import net;

i32 main() {
  net.Conn c;
  c.fd = 3;            // fine
  net.Conn copy = c;   // fine
  c.buf = NULL;        // error: `buf` is a private field of net.Conn
  return 0;
}

    private fields are only for a module's structs: in the main program, where there is nothing outside to hide them from, they are an error, and so is public on a field (fields are public unless marked). On a function, a method or a type, private just says what leaving out pub already means; pub private together is an error. The editor's completion leaves out the private fields outside their module.

    import net.http; loads the directory net/http (its files start with module http;) and its names are http.get; import h = net.http; names it h instead. The imports come first in a file, before any declaration. A module is looked for under the main file's directory, then in the standard library's module directory, then in each directory of KTM_PATH (separated by :); found in two places is an error. Each module is compiled once, before the code that imports it, so its globals are set up before its importers' (the files of a module in name order).

    One module needs no import: the prelude, the standard library's modules/prelude. Its pub names are seen by every file, the program's and every module's, with no prefix: Error (what a catch binds), EXIT_OK and EXIT_FAIL, and the integer limits I64_MIN, I64_MAX, U64_MAX, I8_MIN, I8_MAX and U8_MAX. import prelude; is an error, and a directory of the program called prelude is not it.

    These are compile errors: using a name that isn't pub from outside its module, a module that isn't found or is found twice, an import cycle (the message shows it, a -> b -> a), a file whose module line is missing or doesn't match its directory, and a variable or parameter named like an import's prefix (i64 geo; would hide the module). An import that is never used is a warning.

    A module can be built into a library once and used from there: ktm -lib geo lib/geo writes libgeo.a and its shared object into lib/geo, with a .ktmlib file naming them. A program importing geo then reads only its declarations (the sources stay, as headers would) and links the library: the archive when compiled, the shared object in the JIT. A library has no code that runs before main, so in a module built this way a global needs a constant initialiser.

    A module's names are emitted as symbols of their own (geo.area is _K3geo4area, the method Account.deposit of bank _K4bank7Account7deposit), so they never clash with C functions or with the program's names. #include still pastes a file in, for C-style headers and the preprocessor.

    The preprocessor#

    #define#

    Macros name a single value: a number, a float, a string, or an expression that evaluates to one. Function-like macros (#define F(x) ..., no space before the () are not supported: they are a compile error ("function-like macros are not supported"), so write a function instead. With a space, #define CALC (2 * 21) is an ordinary macro whose value is the expression in brackets. Names in a macro's value must be other macros. A numeric macro has the type of its value, as in C: if any operand is a float the macro is an F64 (#define AREA (1.5 * SIDE) and (SIDE * 1.5) both are), otherwise an I64. A comparison or a logical operator (&&, ||, !) is an I64 0 or 1 even with float operands, and a float counts as true when it isn't 0.0, as at run time: #define ON (0.5 && 1) is 1. A postfix cast to a built-in type works and gives the macro that type: #define BIG (5(U64) % 3) is a U64, #define HALF (5(F64) / 2) an F64 (2.5). Classes are not known to the preprocessor, so 0(MyClass*) is an error in a macro. A long value can go on over several lines: end each line but the last with a \, as in C.

    #define MAX_USERS 64
#define APP_NAME  "demo"
#define RATE      0.5
#define BUFFER    (MAX_USERS * 16)
#define BUDGET    (MAX_USERS * RATE)

U0 Main()
{
  "%s %d %.1f %d\n", APP_NAME, MAX_USERS, RATE, BUFFER;
  "%.1f %s\n", BUDGET, typeof(BUDGET);
}

    demo 64 0.5 1024
32.0 f64

    Conditional compilation#

    #if, #ifdef, #ifndef, #elif, #else, #endif, #undef and #error work as in C. Define a macro from the command line with -D:

    U0 Main()
{
#ifdef VERBOSE
  "verbose mode\n";
#else
  "quiet mode\n";
#endif
}

    verbose mode

    That example was built with ktm -DVERBOSE. #if and #elif take a constant expression of macros, which can use defined(NAME), and they nest:

    #define LEVEL 2

U0 Main()
{
#if LEVEL > 2
  "high\n";
#elif LEVEL == 2 && !defined(QUIET)
  "level two\n";
#else
  "low\n";
#endif
}

    level two

    A conditional directive without its partner (#else or #endif without #if, a second #else, an #if never closed) and extra tokens after an #if condition are compile errors. #error stops the build and prints the rest of its line. #undef takes effect where it appears: code above it keeps the old value. These macros are always predefined:

    U0 Main()

  "running as a compiled binary\n";

    #include and #link#

    #include "file.ktm" is relative to the including file; #include <file.ktmh> searches the installed include directory. A file that can't be opened or read (a directory, say) is reported as an error at the #include, and the rest of the file is still checked. #link records a library dependency in the source itself (see calling C).

    Exceptions#

    A throw carries an Error, a struct every program has:

    struct Error { i64 code; u8 *message; u8 *file; i32 line; };

    The code is usually an enum member. throw(code) throws one with an empty message, throw(code, fmt, ...) formats the message like printf (the format and its arguments are checked at compile time the same way), and the compiler fills in the file and line of the throw. A try block catches it in the nearest enclosing catch; catch (Error e) gets the error in e. Throws unwind through any number of function calls, running the defers on the way.

    enum BankError { funds, locked };

U0 Withdraw(I64 balance, I64 amount)
{
  if (amount > balance) throw(BankError.funds, "need %d, have %d", amount, balance);
  "withdrew %d\n", amount;
}

U0 Main()
{
  try {
    Withdraw(100, 30);
    Withdraw(100, 500);
    "never printed\n";
  } catch (Error e) {
    if (e.code == BankError.funds) {
      "insufficient funds: %s\n", e.message;
    }
  }
  "carrying on\n";
}

    withdrew 30
insufficient funds: need 500, have 100
carrying on

    e.message is never NULL (it is "" without a message) and is freed when the catch block is left: copy it (StrNew(e.message)) to keep it. throw(e) throws the same error again, with its original message, file and line, so a handler can look at an error and pass it on. A catch without a binding still works and finds the code in Fs->except_ch; until the old code is converted, throw('Funds') with a character constant also still works (the constant is the code).

    The code is converted like an argument to an integer parameter: throw(42.75) throws 42. The catch handler runs after its try has ended, so a throw inside it goes to the next enclosing try.

    A return, break, continue or goto may leave a try body (or a catch handler) at any depth of nesting; the tries it leaves stop catching:

    I64 Find(I64 *items, I64 n, I64 want)
{
  I64 i;
  for (i = 0; i < n; i++) {
    try {
      if (items[i] == want) return i;
      if (items[i] < 0) break;
    } catch {
    }
  }
  return -1;
}

U0 Main()
{
  I64 items[4] = {3, 7, -1, 9};
  try {
    "%d %d\n", Find(items, 4, 7), Find(items, 4, 9);
    throw('Late');
  } catch {
    "caught here, not in Find\n";
  }
}

    1 -1
caught here, not in Find

    Each thread has its own Fs: a throw is caught only by a try of the thread that threw, so threads can use try/catch at the same time. Fs is a function returning the calling thread's state, so Fs->except_ch reads that thread's last thrown value.

    An error that no try catches, in any thread, is printed on stderr (after what the program printed so far) and ends the program with exit code 1. A code that is a character constant with all bytes printable is shown as text, anything else as a number:

    uncaught error 0: need 500, have 100 (bank.ktm:5)
uncaught error 'Funds' (old.ktm:12)

    Each try and each defer reached saves the registers but not the signal mask, so they cost no system call; the flip side is that a throw out of a signal handler leaves that signal blocked.

    defer#

    defer followed by a statement (or a { } block) runs that statement when control leaves the enclosing block, however it leaves: at the end of the block, through return, break, continue or a goto out of it, or because a throw is passing through it on its way to a catch (after the deferred statements have run, the throw carries on to that catch). It keeps clean-up next to the code that needs it:

    U0 Copy(I64 n)
{
  U8 *buf = MAlloc(64);
  defer { Free(buf); "freed\n"; }
  if (n < 0) throw('Neg');
  "copied %d\n", n;
}

U0 Main()
{
  {
    defer "1st registered, runs last\n";
    defer "2nd registered, runs first\n";
  }
  for (I64 i = 0; i < 3; i++) {
    defer "end of iteration %d\n", i;
    if (i == 1) continue;
  }
  Copy(5);
  try {
    Copy(-1);
  } catch {
    "caught\n";
  }
}

    2nd registered, runs first
1st registered, runs last
end of iteration 0
end of iteration 1
end of iteration 2
copied 5
freed
freed
caught

    The rules:

    • The scope is the block the defer is written in (not the whole function): in a loop body it runs at the end of every iteration. It must be a statement of a { } block, so if (x) defer f(); or a defer directly after a case label needs braces.
    • Several defers in a block run in reverse order, the last one first; inner blocks finish before outer ones.
    • A defer only runs if it was reached: one written after an early return does not run on that return.
    • The statement runs as written when the block is left, so it sees the values variables have then. return evaluates its value first: return buf[0]; with defer Free(buf); returns the right value.
    • A throw from a deferred statement goes on like any other throw.
    • A deferred statement can't be left by return, break, continue or goto (a loop inside it keeps its own break and continue), can't contain a label, and a goto can't jump past a defer into the rest of its block. These, and defer outside a function, are compile errors.
    • Returning from Main runs its defers, but Exit(), exit() and a crash end the program without running any. Switching coroutines doesn't leave a block either, so it runs no defers.

    Only functions that use defer pay for it (each one reached sets up a frame like a try does); code without it compiles exactly as before.

    Calling C#

    Declare any C function with extern "c" and call it directly. libc is always linked:

    extern "c" I32 abs(I32 x);
extern "c" U8 *getenv(U8 *name);

U0 Main()
{
  "%d %d\n", abs(-5), getenv("PATH") != NULL;
}

    5 1

    Use F32 for C float, I32 for int and U8 * for char *. To use another library, link it from the source and it works in compiled programs, the JIT and the REPL alike:

    #link &lt;sqlite3&gt;          // like -lsqlite3
#link "./libmine.so"     // a path, relative to the working directory

extern "c" I32 sqlite3_libversion_number();

    Inline assembly#

    An asm block defines labelled routines. _extern binds one to a ktm prototype. Arguments arrive in the platform's C calling convention:

    #ifdef IS_X86_64
asm {
_ADD_ONE::
  MOV RAX, RDI
  INC RAX
  RET
}
#endif

#ifdef IS_ARM_64
asm {
_ADD_ONE::
  ADD X0, X0, 1
  RET
}
#endif

_extern _ADD_ONE I64 AddOne(I64 x);

U0 Main()
{
  "%d\n", AddOne(41);
}

    42

    Differences from its origins#

    ktm grew from a language made for its own operating system (see History and credits); ktm runs on a normal operating system instead. The differences:

    Featurektm
    F32Added, for C libraries that use float
    auto, typeof, range-based for, if (init; cond)Added
    extern "c", #link, #ifjit / #ifaotAdded, for working with the host system
    ?:Not supported
    Sub-integer access (x.u8[1])Not supported
    Exponent operator `Not supported; use Pow or pow
    FsExists for exceptions (Fs->except_ch), one per thread; there are no tasks
    DolDoc, graphics, the system shellNot available; use the C library through extern "c"
