    The ktm language

    A complete tour of the ktm language. If you know C, most of it will look familiar. The differences are where ktm gets interesting.

    Program structure#

    A program is one or more .ktm files. Its entry point is main, as in C: i32 main(), i32 main(i32 argc, u8 **argv) or void main(); the value it returns is the exit code (0 for void main). The file scope holds declarations: types, functions, globals (whose initialisers may call functions and run before main, in order), constants and imports; statements go in functions. The smallest program:

    void main()
{
  printf("Hello\n");
}

    Hello

    Comments are the same as in C: // to the end of the line and /* across lines */. Block comments don't nest, and one still open at the end of a file is an error (unterminated comment). Statements end with ; and blocks use { }. Header files conventionally end in .ktmh.

    Printing#

    printf(fmt, ...) prints, as in C:

    void main()
{
  printf("plain text\n");
  printf("%s is %d years old\n", "Ada", 36);
  printf("%5d|%-5d|%05d\n", 42, 42, 42);
  printf("%x %X %c %.3f\n", 255, 255, 'A', 3.14159);
}

    plain text
Ada is 36 years old
   42|42   |00042
ff FF A 3.142

    The conversions are the ones str.format knows (see the library guide), ktm's own included: %Q prints a string escaped as a C literal and %C a character in upper case. A date is formatted with date.format(d, "%m/%d/%Y %H:%M:%S") and printed with %s. The compiler checks the number of arguments against the format.

    void main()
{
  printf("%Q\n", "say \"hi\"\n");
  printf("%C%c\n", 'h', 'i');
}

    say \"hi\"\n
Hi

    The string is always a format, even without arguments, so write %% for a literal percent sign: printf("100%%\n"); prints 100%.

    %d, %i, %u, %x, %X and %o print the full 64-bit value, so there is no need for C's %ld (which also works):

    void main()
{
  i64 big = 5000000000;
  printf("%d vs %ld\n", big, big);
}

    5000000000 vs 5000000000

    Types#

    TypeSizeMeaning
    void0Nothing
    bool1true (1) or false (0): any other value converted to it is 1 if it isn't 0
    i8 / u81Signed / unsigned byte; u8 is the character type
    i16 / u16216-bit integers
    i32 / u32432-bit integers
    i64 / u64864-bit integers, the default integer type
    f648Double-precision float

    The type names are not keywords, so a struct field can still be called i64 or f64; a variable can't.

    Pointers are written as in C (u8 *s, i64 **pp) and are 8 bytes. null is the null pointer: 0 as a void *, so it can be assigned to any pointer or function pointer. true and false are bool values, 1 and 0.

    As in C, a value becomes a bool by comparing it with 0: an integer, float or pointer that isn't 0 (or null) is true, whether it is assigned, passed as an argument, returned, stored in a field or cast with (bool)x. Only the low byte is never kept, so 0x100 and 0.5 are true. A pointer needs no cast to become a bool (other integer types warn without one), and messages and typeof call the type bool.

    bool isSet(i64 flags, i64 bit) { return flags & bit; }

void main()
{
  bool b = 0x100;
  printf("%d %d %d %d\n", b, isSet(0x800, 0x800), (bool)0.5, (bool)(-1));
}

    1 1 1 1

    void main()
{
  printf("%d %d %d %d %d\n", sizeof(u8), sizeof(i16), sizeof(i32), sizeof(i64), sizeof(f32));
  printf("%d %d\n", sizeof(u8 *), sizeof(bool));
}

    Literals#

    void main()
{
  i64 dec = 42, hex = 0xFF, bin = 0b1010;
  f64 f = 1.5e3, g = 2e-3;
  printf("%d %d %d %.1f %.3f\n", dec, hex, bin, f, g);

  // A character constant is one character (an escape counts as one),
  // an integer, and takes the same escapes as strings.
  i64 one = 'A', nl = '\n';
  printf("%d %d %c\n", one, nl, one);

  printf("tab:[\t] quote:[\"] backslash:[\\]\n");
}

    42 255 10 1500.0 0.002
65 10 A
tab:[	] quote:["] backslash:[\]

    Integers can be written in decimal, hex (0x) or binary (0b). A number with a . or an exponent (1e3, 2e-3) is an f64. A character constant holds exactly one character: 'ab' is an error (use a string, or an enum for a set of tags). String literals are u8 *.

    Strings take the C escapes \n \t \r \b \f \v \a \\ \' \", and \d for $. \x takes at most two hex digits, so "\x01b" is the bytes 1 and 'b', and \0 to \7 start an octal escape of up to three digits ("\033" is ESC). Every string literal ends in a NUL that sizeof counts: sizeof("\x42") is 2.

    An integer literal too big for i64 is a u64. A malformed number is a compile error that says what is wrong with it: 0x or 0b with no digits, a digit that doesn't fit the base (0b102), a letter after a decimal number (12ab) or an exponent with no digits (1e).

    ktm has no octal literals: leading zeros don't change the base, so 0644 is the decimal number 644 (C reads it as octal 420). Because code copied from C would silently change value, ktm warns at such a literal and suggests the hex spelling (0x1A4 for octal 0644). Literals that mean the same in both, like 00 or 07, and floats like 00.5 are not warned about.

    _ may appear between two digits of a number literal and is ignored, to group long ones for reading: 1_000_000, 0xFF_FF, 0b1010_0101, 1_000.25. It is only valid between two digits of the literal's own base, so misplaced at the start or end, next to . or the exponent, or doubled, it is a compile error. A leading _ is still an identifier (_100 is a name, not a number).

    void main()
{
  i64 million = 1_000_000;
  i64 word = 0xFF_FF;
  f64 price = 1_000.25;
  printf("%d %d %.2f\n", million, word, price);
}

    1000000 65535 1000.25

    Variables#

    Declare variables anywhere in a block, or at file scope for globals. Several can share one declaration, inside a function or at global scope; each * belongs to the name after it:

    i64 gTotal = 100, gCount; // globals, visible to everything below them

void main()
{
  i64 a = 1, b = 2, c;
  c = a + b;
  f64 ratio = 0.25;
  u8 *name = "ktm", letter = 'h';
  printf("%d %d %d %.2f %s %c\n", c, gTotal, gCount, ratio, name, letter);
}

    3 100 0 0.25 ktm h

    auto#

    auto takes its type from the initialiser:

    void main()
{
  auto count = 3;
  auto price = 9.99;
  auto label = "total";
  printf("%s %s %s\n", typeof(count), typeof(price), typeof(label));
}

    i64 f64 u8[6]

    static#

    A static local keeps its value between calls:

    i64 nextId()
{
  static i64 id = 0;
  id++;
  return id;
}

void main()
{
  nextId();
  nextId();
  printf("%d\n", nextId());
}

    3

    const#

    const marks a declaration read-only; it is not a type qualifier like C's. An initializer is required (except on a function parameter). A const of integer type whose initializer is itself a constant expression is a compile-time constant: usable in an array size, a case label, or another const's initializer. Assigning to a const (=, a compound assignment, ++/--), including a const parameter, is a compile error, and so is writing const anywhere but a declaration (a cast, a struct field, a return type, or after the type).

    const i64 MAX_USERS = 4;
const i64 DOUBLE_MAX = MAX_USERS * 2;   // built from another const
i64 gUsers[MAX_USERS];                 // a const works as an array size

i64 classify(i64 n)
{
  switch (n) {
    case MAX_USERS: return 1;           // and as a case label
    default:        return 0;
  }
}

i64 twice(const i64 n)                  // n cannot be assigned inside Twice
{
  return n * 2;
}

void main()
{
  printf("%d %d %d %d\n", MAX_USERS, DOUBLE_MAX, classify(4), twice(21));
}

    Operators#

    The C operators work as expected: + - * / %, & | ^ ~ << >>, && || !, == != < <= > >=, compound assignment (+=, <<=, …) and ++ / --.

    void main()
{
  i64 a = 7, b = 2;
  printf("%d %d %d %d %d\n", a + b, a - b, a * b, a / b, a % b);
  printf("%d %d %d %d %d\n", a & b, a | b, a ^ b, a << 2, a >> 1);
  a += 3;
  a++;
  printf("%d\n", a);
}

    9 5 14 3 1
2 7 5 28 3
11

    &&, ||, ! and the comparisons always give 0 or 1. A float operand of &&, || or ! is true when it isn't 0.0, and a pointer when it isn't null. Comparing an integer with a float compares them as floats. On u64 values, >>, /, % and the comparisons are unsigned. An assignment used as a value has the type of its left side, so the value is truncated to fit:

    void main()
{
  f64 half = 0.5;
  u8 *none = null;
  printf("%d %d %d %d\n", half && 1, !half, none || 0, !none);
  printf("%d\n", 2 < 2.5);

  u64 big = 0xFFFFFFFFFFFFFFFF;
  printf("%d %d\n", big > 1, big >> 60);

  u8 c;
  i64 v = (c = 300);
  printf("%d\n", v);
}

    1 0 0 1
1
1 15
44

    Unary - and + need a number and ~ needs an integer: -p on a pointer or ~f on an f64 is a compile error. A narrower integer operand is widened to i64 first.

    Comparisons can be chained, as in maths: lo < x < hi means lo < x && x < hi.

    void main()
{
  i64 x = 5;
  printf("%d %d\n", 1 < x < 10, 1 < x < 3);
}

    1 0

    There is no ?: operator. Use if/else.

    typeof is an ktm addition. It becomes a string naming the type at compile time, and its operand is never evaluated.

    Type casts#

    Casts are written as in C, (T)x: the type in parentheses before the value. A cast is a unary operator, so it binds tighter than any binary operator ((f64)a / b divides as floats) and applies to the whole postfix expression after it ((i64)p->n casts p->n). Any type works, including pointers, structs and function pointers ((fn(i64) i64)p). A variable hides a type of the same name, so (x) stays a value in parentheses.

    void main()
{
  f64 f = 3.9;
  i64 i = (i64)f;            // truncates
  printf("%d\n", i);
  printf("%.1f %.1f\n", (f64)(7 / 2), (f64)7 / 2);
  printf("%.1f\n", (f64)-i / 2);     // ((f64)-i) / 2

  u8 *s = "hey";
  i64 address = (i64)s;
  printf("%c\n", *(u8 *)address);
}

    Control flow#

    if and else#

    The body of an if, else, for, while or do is always a { ... } block (else if aside): if (x) y = 1; is an error, "braces required".

    void main()
{
  i64 n = 15;
  if (n % 15 == 0) {
    printf("FizzBuzz\n");
  } else if (n % 3 == 0) {
    printf("Fizz\n");
  } else {
    printf("%d\n", n);
  }

  // An initialiser can come before the condition, scoped to the if.
  if (i64 half = n / 2; half > 5) {
    printf("half is %d\n", half);
  }
}

    FizzBuzz
half is 7

    switch#

    case takes a value or a range lo ... hi. A case ends at the next one: unlike C it doesn't fall through, so no break is needed (one still leaves the switch early). Labels stacked with nothing between them share the code that follows.

    void grade(i64 score)
{
  switch (score) {
    case 90 ... 100: printf("A\n");
    case 80 ... 89:  printf("B\n");
    case 0:          printf("no score\n");
    default:         printf("C or below\n");
  }
}

void main()
{
  grade(95);
  grade(83);
  grade(0);
  grade(42);
}

    A
B
no score
C or below

    Two extras over C: a bare case: takes the previous case's value plus one (starting from 0), and switch [x] skips the range check on x, for speed when you know it's in range.

    void main()
{
  for (i64 i = 0; i < 6; i++) {
    switch [i] {
      case 0: printf("zero ");
      case:   printf("one ");      // 1
      case:   printf("two ");      // 2
      case 4...5: printf("four-five ");
      default: printf("other ");
    }
  }
  printf("\n");
}

    zero one two other four-five four-five

    fallthrough; as the last statement of a case (or of its { ... }) runs on into the next case. It is an error anywhere else: outside a switch, before other statements of its case, under an if or a loop, in the last case where there is no next one, and into or out of a default that isn't the last label (default runs after the cases). fallthrough is a keyword.

    void main()
{
  for (i64 i = 1; i <= 3; i++) {
    switch (i) {
      case 1: printf("one, "); fallthrough;
      case 2: printf("two or after one\n");
      default: printf("three\n");
    }
  }
}

    one, two or after one
two or after one
three

    Loops#

    void main()
{
  i64 i = 0;
  while (i < 3) {
    printf("w%d ", i);
    i++;
  }
  do {
    printf("d%d ", i);
    i--;
  } while (i > 0);
  for (i64 j = 0; j < 10; j++) {
    if (j == 2) { continue; }
    if (j == 5) { break; }
    printf("f%d ", j);
  }
  printf("end\n");
}

    Range-based for#

    An ktm addition. Loop over a fixed-size array, or over any struct with an entries field and a size field, such as the library's vec.IntVec and vec.PtrVec:

    import vec;

void main()
{
  i64 primes[] = {2, 3, 5, 7, 11};
  i64 sum = 0;
  for (auto p : primes) {
    sum += p;
  }
  printf("sum = %d\n", sum);

  vec.IntVec *v = vec.intNew();
  v.push(10);
  v.push(20);
  for (i64 x : v) { printf("%d\n", x); }
  v.release();
}

    Functions#

    i64 square(i64 n)
{
  return n * n;
}

void main()
{
  printf("%d\n", square(12));
}

    144

    Declare a prototype to call a function before its definition: i64 later(i64 x); Every prototype and the definition must agree on the return and parameter types; a mismatch is an error ("conflicting types") at the later one. Default arguments carry over: after i64 later(i64 x=1); the definition can be written i64 later(i64 x) { ... } and later() still passes 1. Repeating a default is allowed if it is the same value; a different value is an error.

    The standard library lives in modules, so a function of your own may have the same name as a library one: your now() or exit() is yours, and date.now() and os.exit() stay the library's. The same holds for the C library: a program's functions have symbols of their own, so your read() or free() doesn't replace C's, which the standard library keeps calling. A C function you call is declared with extern "c"; a prototype without a body and without extern "c" is a ktm function that must be defined somewhere.

    A returned value is converted to the function's return type, as in C: an integer returned from an f64 function becomes a float. In a void function, return expr; is a warning ("unexpected return value"), but the expression is still evaluated for its side effects.

    inline is accepted as a hint only: an inline function is compiled as an ordinary function, so it can recurse, take default arguments and have its address taken.

    inline i64 twice(i64 x)
{
  return x * 2;
}

void main()
{
  fn(i64 x) i64 fp = &twice;
  printf("%d %d\n", twice(21), fp(4));
}

    42 8

    Default arguments#

    Any parameter can have a default, not just trailing ones. Leave an argument empty to use its default:

    void box(i64 w = 2, i64 h = 3, u8 *fill = "#")
{
  printf("%dx%d of %s\n", w, h, fill);
}

void main()
{
  box(5, 1, "*");
  box(5);
  box(, 9);
  box(, , "@");
}

    Variable arguments#

    The last parameter can take any number of extra arguments, zero included: T ...name takes them as values of type T, each checked and converted like an argument to a T parameter (a wrong type is an error). Inside the function name.len is how many there are, name[i] is one of them (&name[i] works too) and for (auto v : name) goes through them; name itself can't be assigned. Fixed and default parameters can come before it.

    i64 sum(i64 ...nums)
{
  i64 total = 0;
  for (auto n : nums) { total += n; }
  return total;
}

f64 avg(f64 ...xs)
{
  if (!xs.len) { return 0; }
  f64 total = 0;
  for (i64 i = 0; i < xs.len; i++) { total += xs[i]; }   // 1 and 2 become 1.0, 2.0
  return total / xs.len;
}

i64 Total(i64 ...nums)
{
  return sum(...nums);   // pass them all on
}

void main()
{
  printf("%d %d %d\n", sum(), sum(1, 2, 3, 4), Total(5, 6));
  printf("%.2f\n", avg(1, 2, 4));
}

    0 10 11
2.33

    ...name as the last argument of a call passes the extras of a variadic parameter on, to a function that takes the same kind (it must be the only extra argument). Without a type, ...name takes the extras as 64-bit slots, the way format functions want them: a number as is, a float as its bits (read it back with name[i](f64)), a pointer as its address:

    import mem, str;

void Log(u8 *fmt, ...args)
{
  u8 *msg = str.formatArgs(null, fmt, args.len, args);   // format the extras
  printf("[log] %s\n", msg);
  mem.free(msg);
}

void main()
{
  Log("%d files in %s, %.1f%% full", 3, "/tmp", 42.5);
}

    [log] 3 files in /tmp, 42.5% full

    The extras are passed as their count and a pointer to an array the caller builds, so spreading them on costs nothing.

    Function pointers#

    i64 add(i64 a, i64 b) { return a + b; }
i64 mul(i64 a, i64 b) { return a * b; }

i64 fold(fn(i64 a, i64 b) i64 op, i64 *nums, i64 n)
{
  i64 acc = nums[0];
  for (i64 i = 1; i < n; i++) {
    acc = op(acc, nums[i]);
  }
  return acc;
}

void main()
{
  i64 nums[] = {1, 2, 3, 4};
  fn(i64 a, i64 b) i64 f = &mul;
  printf("%d %d\n", fold(&add, nums, 4), fold(f, nums, 4));
}

    As in C, * on a function pointer gives the function pointer back, so (*f)(acc, x), (*c.op)(5) and (*ops[i])(5) call it just like f(acc, x).

    Any expression whose type is a function pointer can be called: a cast to a function pointer type (((fn(i64) i64)p)(5)), the result of a call that returns one, or of an assignment ((f = &Mul)(2, 3)). The arguments are checked against the pointer's parameters, as for a named function:

    import str;

i64 add(i64 a, i64 b) { return a + b; }
i64 mul(i64 a, i64 b) { return a * b; }

void *lookup(u8 *name)
{
  if (!str.cmp(name, "add")) { return &add; }
  return &mul;
}

void main()
{
  fn(i64 a, i64 b) i64 f;
  printf("%d\n", ((fn(i64, i64) i64)lookup("add"))(2, 3));
  printf("%d\n", ((fn(i64, i64) i64)lookup("mul"))(2, 3));
  printf("%d\n", (f = &mul)(4, 5));
}

    An array of function pointers puts the size after the name, as in C. It works for locals, globals, struct fields and parameters:

    i64 dbl(i64 x) { return x * 2; }
i64 sq(i64 x) { return x * x; }

fn(i64 x) i64 ops[] = {&dbl, &sq};

void main()

  for (i64 i = 0; i < 2; i++) {
    printf("%d\n", ops[i](5));

    A default in a function pointer's parameter list fills a left-out argument when you call through it, for variables and struct fields alike. A void * converts to and from a function pointer without a cast, and compares (==, !=) with one:

    i64 dbl(i64 x) { return x * 2; }

struct Calc { fn(i64 x = 21) i64 op; };

void main()
{
  Calc c;
  c.op = &dbl;
  printf("%d %d\n", c.op(5), c.op());

  void *raw = &dbl;
  fn(i64 x) i64 back = raw;
  printf("%d %d\n", back(4), raw == &dbl);
}

    A function pointer only takes a function, or a function pointer, with the same signature: the same return type, the same parameter types and the same .... Anything else is an error naming both types, wherever the conversion happens (an assignment, an initialiser, an argument, a return or a conditional), so i64 (*op)(u8 *) = &t; with a t taking an i64 gives cannot convert fn(i64) i64 to fn(u8*) i64. A void * and null still convert without a cast. A function whose parameters are typed pointers, passed where one taking void * is expected (a comparator, a thread function), needs a cast, which makes the mismatch visible:

    struct Item { i64 key; };

i64 itemLess(Item *a, Item *b) { return a.key < b.key; }

void main()
{
  Item a, b;
  a.key = 1;
  b.key = 2;
  fn(void *, void *) i64 cmp = (fn(void *, void *) i64)(&itemLess);
  printf("%d\n", cmp(&a, &b));
}

    The other C declarator forms work too: a function returning a function pointer is written T (*Name(params))(fn_params), and a pointer to a function pointer is T (**pp)(params), for locals, globals, struct fields and parameters alike.

    i64 dbl(i64 x) { return x * 2; }
i64 sq(i64 x) { return x * x; }

fn(i64 x) i64 choose(bool square)
{
  if (square) { return &sq; }
  return &dbl;
}

void main()
{
  fn(i64 x) i64 f = choose(true);
  (fn(i64 x) i64) *pf = &f;
  printf("%d ", f(5));
  *pf = choose(false);        // changes f through the pointer
  printf("%d\n", f(5));
}

    fn(...) types#

    A function pointer type is written fn ( types ) RetType: fn(i64) i64 takes an i64 and returns one, and has the same size, calls and argument checks as C's i64 (*)(i64). Parameter names are optional and ignored. RetType can itself be another fn(...) type:

    i64 twice(i64 x) { return x * 2; }
i64 addOne(i64 x) { return x + 1; }

fn(i64) i64 op = &twice;
fn(i64) i64 pick(bool sq) { if (sq) { return &twice; } return &addOne; }
void apply(fn(i64) i64 f, i64 x) { printf("%d\n", f(x)); }

i32 main()
{
  apply(op, 5);
  fn(i64) i64 g = pick(true);
  printf("%d\n", g(5));
  return 0;
}

    10
10

    A * after the return type is part of it: fn(u8 *) u8 * returns a u8 *. A pointer to a function pointer puts the fn type in parentheses, (fn(i64) i64) *slot, in declarations, parameters, fields, casts, sizeof and typeof, and typeof prints it that way. Parameters can have defaults, filled in when a call through the pointer leaves them out, and take varargs in every form a function does (..., ...args, i64 ...nums):

    u8 *skip(u8 *s) { return s + 1; }
i64 add(i64 a, i64 b) { return a + b; }
i64 count(...args) { return args.len; }

i32 main()
{
  fn(u8 *) u8 * f = &skip;
  fn(i64 a, i64 b = 10) i64 k = &add;
  fn(...args) i64 c = &count;
  (fn(u8 *) u8 *) *pf = &f;
  printf("%s %d %d %d %s\n", f("xyz"), k(1), k(1, 2), c(4, 5, 6), (*pf)("ab"));
  return 0;
}

    yz 11 3 3 b

    fn is a keyword, like self, module, import and fallthrough: none of them can name a variable, a parameter or a declaration. The old C declarator form (i64 (*)(i64), an array of them, a function returning one, a pointer to one) is documented above and keeps working; it is converted to fn(...) everywhere in a later pass.

    Pointers and arrays#

    void main()
{
  i64 x = 5;
  i64 *p = &x;
  *p = 10;
  printf("%d\n", x);

  i64 squares[5];
  for (i64 i = 0; i < 5; i++) {
    squares[i] = i * i;
  }
  i64 *q = squares;              // arrays decay to pointers
  printf("%d %d %d\n", q[3], *(q + 4), &squares[4] - &squares[1]);

  i64 grid[3][4];
  grid[2][3] = 7;
  printf("%d %d\n", grid[2][3], sizeof(grid));
}

    As in C, n + p is the same as p + n, a pointer can be compared with an integer on either side, and n - p is a compile error. An array can't be assigned as a whole (a = b; is an error): assign its elements or copy it with mem.copy.

    Storing one pointer type in another is a warning, as in C: i64 *q = &f; with f64 f (also when assigning, passing or returning it), and q -= q, which stores a pointer difference (an integer) back into the pointer. void * and byte pointers (u8 *, i8 *, bool *) convert to and from any pointer without one; otherwise cast: (&f)(i64 *).

    Call arguments are checked against the parameter types as in C, for functions, function pointers and extern functions alike. Numbers convert silently (an i64 passed for an f64 becomes a float), 0 and null pass as any pointer, void * converts both ways, and a pointer to a derived struct is a pointer to its base struct. A pointer passed for an integer, an integer for a pointer (other than 0) and a pointer to an incompatible type are warnings (Twice("str"): "makes an integer from a pointer without a cast"); a struct passed where another struct or a number is expected, or a number or pointer where a struct or a float is, is an error. Extra arguments of a ... function are not checked.

    An initialiser list may be shorter than the array or struct it initialises; as in C, everything it leaves out is zero, for locals and globals alike:

    struct Point { i64 x, y, z; };

i64 counts[4] = {1, 2};

{
  i64 grid[2][3] = {{1}, {4, 5}};
  Point p = {7};
  printf("%d %d %d %d\n", counts[0], counts[1], counts[2], counts[3]);
  printf("%d %d %d | %d %d %d\n", grid[0][0], grid[0][1], grid[0][2],
                           grid[1][0], grid[1][1], grid[1][2]);
  printf("%d %d %d\n", p.x, p.y, p.z);
}

    Unlike C, braces only go around an array, struct or union: a scalar can't be initialised from a list (i64 x = {1};), and neither can a scalar element or field (i64 a[2] = {1, {2}};). Both are compile errors.

    As in C, the braces of an inner array or struct can be left out: its items are then taken from the list in order, as many as it has, and a list that ends early zero-fills the rest. A string still initialises a whole u8 array, and a value of the struct itself a whole struct field.

    struct Point { i64 x, y; };

    Heap memory#

    mem.alloc allocates, mem.allocZero allocates zeroed memory, mem.realloc resizes and mem.free releases. Nothing is garbage collected.

    import mem;

void main()
{
  i64 n = 4;
  i64 *nums = mem.allocZero(n * sizeof(i64));
  nums[2] = 7;
  nums = mem.realloc(nums, 8 * sizeof(i64));
  printf("%d %d\n", nums[0], nums[2]);
  mem.free(nums);
}

    Strings#

    Strings are NUL-terminated u8 arrays, as in C. The library has the usual helpers (more in the library guide):

    import mem, str;

void main()
{
  u8 *copy = str.dup("hello");
  printf("%s %d %d\n", copy, str.len(copy), str.cmp(copy, "hello"));

  u8 *msg = str.formatTo(null, "%s has %d letters", copy, str.len(copy));
  printf("%s\n", msg);

  i64 vowels = 0;
  for (u8 *c = copy; *c; c++) {
    if (*c == 'e' || *c == 'o') { vowels++; }

  mem.free(copy);
  mem.free(msg);
}

    void main()

    Structs#

    A struct (or struct, the same thing) is a C struct, and its name is a type straight away, with no typedef needed. Several fields can share a line. pub (or pub) marks what a library exports.

    import mem;

struct Point
{
  i64 x, y;
};

Point make(i64 x, i64 y)          // structs can be returned by value
{
  Point r;
  r.x = x;
  r.y = y;
  return r;
}

i64 sum(Point p)                  // and passed by value
{
  return p.x + p.y;
}

void main()
{
  Point a = {1, 2};               // initialise fields in order
  Point c = make(11, 22);
  printf("%d %d %d\n", c.x, c.y, sum(a));

  Point copy = c;                 // assignment copies
  copy.x = 0;
  printf("%d %d\n", c.x, copy.x);

  Point *p = mem.alloc(sizeof(Point));
  p.x = 5;                       // -> through a pointer
  p.y = 6;                        // . works through one pointer too
  printf("%d %d\n", p.x, p.y);
  mem.free(p);
}

    p.x on a pointer to a struct is p->x. It goes through one pointer only: on a Point **pp, pp.x is an error and (*pp).x or pp[0].x is what you write.

    A field that is itself a struct or an array takes a nested list:

    struct Point { i64 x, y; };

    A string for a u8 array field or row is copied in the same way, and must fit with its NUL. A u8 * field points at the string instead:

    Inheritance#

    A struct can extend one other struct. It starts with all of the base struct's fields, so a pointer to it can be used wherever the base struct is expected:

    struct Shape
{
  u8 *name;
  fn(Shape *s) f64 area;
};

struct Circle : Shape
{
  f64 r;
};

struct Rect : Shape
{
  f64 w, h;
};

f64 circleArea(Shape *s) { Circle *c = s; return 3.14159 * c.r * c.r; }
f64 rectArea(Shape *s)   { Rect *r = s; return r.w * r.h; }

void main()
{
  Circle c;
  c.name = "circle";
  c.area = &circleArea;
  c.r = 1.0;

  Rect r;
  r.name = "rect";
  r.area = &rectArea;
  r.w = 2.0;
  r.h = 3.0;

  Shape *shapes[2];
  shapes[0] = &c;
  shapes[1] = &r;
  for (i64 i = 0; i < 2; i++) {
    printf("%s: %.2f\n", shapes[i].name, shapes[i].area(shapes[i]));
  }
}

rect: 6.00

    Methods#

    A method is written outside its struct, as a function named Type.name. Inside, self is a pointer to the object it was called on (a User * here), and it can't be assigned. A method is called on a value or on a pointer, with . or ->:

    struct User
{
  u8 *name;
  i64 age;
};

struct Admin : User
{
  i64 level;
};

void User.describe()
{
  printf("%s is %d\n", self.name, self.age);
}

i64 User.older(i64 years = 1)    // default arguments and `T ...name` work as usual
{
  self.age += years;             // self points at the caller's object
  return self.age;
}

void Admin.describe()            // hides User.describe for an Admin
{
  printf("admin %d: ", self.level);
  User.describe(self);           // the base's, called explicitly
}

void main()
{
  User u = {"ann", 30};
  User *p = &u;
  u.describe();
  p.older(5);                    // the same as p->older(5)
  p.describe();

  Admin a;
  a.name = "bob";
  a.age = 40;
  a.level = 2;
  a.older();                     // inherited from User
  a.describe();

  User *as_user = &a;
  as_user.describe();            // no virtual dispatch: the pointer's type decides

  fn(User *) void f = &User.describe;   // a method is a function taking self first
  f(p);
}

    ann is 30
ann is 35
admin 2: bob is 41
bob is 41
ann is 35

    A derived struct has its base's methods; a method of the same name on it hides the base's, which Base.name(self) still calls. Which method runs is decided by the type the compiler sees, never at run time. &User.describe is an ordinary function pointer whose first parameter is self, so it works as a callback; u.describe without () is an error (there are no bound methods). A prototype, void User.describe();, declares a method defined later, and static keeps one to its file. A union can have methods too.

    These are compile errors: a method with the name of a field (inherited ones included), the same method defined twice, a method of something that isn't a struct or union, a method added to a type of the standard library or of another module, and a parameter named self.

    Enums#

    An enum is a scoped set of named integer constants, at file scope only. The first member is 0, then each next one is the previous plus 1, unless it has its own = constexpr; an earlier member can be used unqualified inside the braces. The underlying type defaults to i32; : Type picks any other integer type, and sizeof/alignof follow it. Outside the braces a member is only reachable as Name.member, which is itself an integer constant expression (an array size, a case label, another const's initialiser):

    enum Color { red, green, blue };
enum Status : u16 { ok = 200, notFound = 404, gone };
pub enum Mode { read = 1, write = 2, both = read | write };

i32 main()
{
  Color c = Color.green;
  i64 sizes[Color.blue + 1];
  switch (c) {
    case Color.red:   printf("red\n");
    case Color.green: printf("green\n");
    case Color.blue:  printf("blue\n");
  }
  printf("%d %d %d\n", sizeof(sizes), Status.gone, Mode.both);
  return 0;
}

    green
24 405 3

    An enum value converts to any integer type implicitly, as arithmetic and comparisons with integers do; an integer, or a different enum, needs a cast to become one ((Color)2). Two different enums never mix without a cast either.

    Modules#

    A module is a directory of .ktm files. Each file in it starts with module and the directory's name, and a program uses it with import; its names are then written with the module's name in front:

    // geo/shapes.ktm
module geo;

pub struct Point { i64 x; i64 y; };
pub enum Kind { square, circle };
pub const i64 SIZE = 4;

pub i64 area(Kind k, i64 side) {
  if (k == Kind.square) return square(side);   // square() is in another file of geo
  return 3 * side * side;
}

// geo/helpers.ktm
module geo;

i64 square(i64 n) { return n * n; }             // private to geo

// main.ktm
import geo;

i32 main() {
  geo.Point p;
  i64 cells[geo.SIZE];
  printf("%d\n", geo.area(geo.Kind.square, 5));
  return 0;
}

    Inside a module every name of every one of its files is visible, in any order: a function can call one defined in a later file, and a struct can hold a later file's struct (by value too), enum or const (as an array size). Only a cycle of structs that hold each other by value is an error: one of them needs a pointer. Outside it, only the names marked pub are, and always through the prefix (geo.area, the type geo.Point, geo.Kind.square, geo.SIZE, which works in constant expressions too). A module can't use the names its program defines: a library doesn't depend on whoever uses it. The C functions it declares with extern "c" are its own names as well, private unless pub.

    A C function declared with extern "c" in a module keeps its C symbol, so libc.write(fd, buf, n), or &libc.write, is C's write. A module named libc holds the C library's declarations and nothing else: its files contain only extern "c" functions, structs, unions, enums and constants, and a function with a body, a ktm prototype, a method or a variable there is an error.

    Only the module that defines a type can define its methods. Outside it, the pub methods are called on the object with no prefix (a.deposit(5) on a bank.Account *a), and &bank.Account.deposit is one as a function pointer; a method that isn't pub is private to the module:

    // bank/account.ktm
module bank;

pub struct Account { u8 *owner; i64 balance; };

pub Account *open(u8 *owner) {
  Account *a = MAlloc(sizeof(Account));
  a.owner = owner;
  a.balance = 0;
  return a;
}

pub void Account.deposit(i64 x) { self.balance += x; self.audit(); }
void Account.audit() { }                         // private to bank

// main.ktm
import bank;

i32 main() {
  bank.Account *a = bank.open("ann");
  a.deposit(5);
  return 0;
}

    A field marked private can be used only inside the module that defines its struct: in any of the module's files, its functions and its methods. Outside, reading or writing it, taking its address, an initialiser list that reaches it, a range-based for over it and a struct that inherits it all say `buf` is a private field of net.Conn. The rest of the struct stays usable: its public fields, sizeof, copying it and passing it by value, since only the names are hidden, not the layout:

    // net/conn.ktm
module net;

pub struct Conn {
  i32 fd;              // public, as in C
  private u8 *buf;     // only net uses it
};

pub u8 *peek(Conn *c) { return libc.buf; }

// main.ktm
import net;

i32 main() {
  net.Conn c;
  libc.fd = 3;            // fine
  net.Conn copy = c;   // fine
  libc.buf = null;        // error: `buf` is a private field of net.Conn
  return 0;
}

    private fields are only for a module's structs: in the main program, where there is nothing outside to hide them from, they are an error, and so is pub on a field (fields are public unless marked). On a function, a method or a type, private just says what leaving out pub already means; pub private together is an error. The editor's completion leaves out the private fields outside their module.

    import net.http; loads the directory net/http (its files start with module http;) and its names are http.get; import h = net.http; names it h instead. One line can import several: import fs, str, h = net.http;. The imports come first in a file, before any declaration. A module is looked for under the main file's directory, then in the standard library's module directory, then in each directory of KTM_PATH (separated by :); found in two places is an error. Each module is compiled once, before the code that imports it, so its globals are set up before its importers' (the files of a module in name order).

    One module needs no import: the prelude, the standard library's modules/prelude. Its pub names are seen by every file, the program's and every module's, with no prefix: Error (what a catch binds), EXIT_OK and EXIT_FAIL, and the integer limits, the smallest and largest value of each integer type: I8_MIN, I8_MAX, U8_MAX, and the same for 16, 32 and 64 bits (I16_MIN ... U64_MAX). import prelude; is an error, and a directory of the program called prelude is not it.

    Another is the runtime, the standard library's modules/rt: it is part of every program, imported or not, but no program imports it. import rt; in a program or in a program's own module is an error ("rt is internal"), and nothing binds the prefix rt; only the standard library's modules may import it.

    These are compile errors: using a name that isn't pub from outside its module, a module that isn't found or is found twice, an import cycle (the message shows it, a -> b -> a), a file whose module line is missing or doesn't match its directory, and a global named like an import's prefix (i64 geo; at file scope would hide the module). An import that is never used is a warning.

    A local variable or a parameter may have an import's name: as in Go, it shadows the module for its scope (u8 *str in a file that imports str). There str.x is the local's field or method, and a member the local doesn't have is the error "u8 * has no member `len` (note: the local `str` hides the module str)". The local's own initialiser still sees the module (u8 *str = str.format(...)), a type name (str.Thing) is still the module's, and outside the scope the module is there again.

    A module can be built into a library once and used from there: ktm -lib geo lib/geo writes libgeo.a and its shared object into lib/geo, with a .ktmlib file naming them. A program importing geo then reads only its declarations (the sources stay, as headers would) and links the library: the archive when compiled, the shared object in the JIT. A library has no code that runs before main, so in a module built this way a global needs a constant initialiser.

    ktm -lib name dir, where dir is not the directory of a module name, builds every module under dir (dir/net/http is net.http) into one library, dir/libname.a and its shared object, and gives each module's directory a .ktmlib. The files at the top of dir and a prelude directory there are not built. A .ktmlib names its library relative to itself, so a built tree can be moved. -v prints the commands that build a library.

    A module's names are emitted as symbols of their own (geo.area is _K3geo4area, the method Account.deposit of bank _K4bank7Account7deposit), so they never clash with C functions or with the program's names. #include still pastes a file in, for C-style headers and the preprocessor.

    The preprocessor#

    #define#

    Macros name a single value: a number, a float, a string, or an expression that evaluates to one. Function-like macros (#define F(x) ..., no space before the () are not supported: they are a compile error ("function-like macros are not supported"), so write a function instead. With a space, #define CALC (2 * 21) is an ordinary macro whose value is the expression in brackets. Names in a macro's value must be other macros. A numeric macro has the type of its value, as in C: if any operand is a float the macro is an f64 (#define AREA (1.5 * SIDE) and (SIDE * 1.5) both are), otherwise an i64. A comparison or a logical operator (&&, ||, !) is an i64 0 or 1 even with float operands, and a float counts as true when it isn't 0.0, as at run time: #define ON (0.5 && 1) is 1. A cast to a built-in type works and gives the macro that type: #define BIG ((u64)5 % 3) is a u64, #define HALF ((f64)5 / 2) an f64 (2.5). Structs are not known to the preprocessor, so (MyStruct *)0 is an error in a macro. A numeric constant is usually better written as const. A long value can go on over several lines: end each line but the last with a \, as in C.

    const i64 MAX_USERS = 64;
#define APP_NAME  "demo"
const f64 RATE = 0.5;
const i64 BUFFER = (MAX_USERS * 16);
const f64 BUDGET = (MAX_USERS * RATE);

void main()
{
  printf("%s %d %.1f %d\n", APP_NAME, MAX_USERS, RATE, BUFFER);
  printf("%.1f %s\n", BUDGET, typeof(BUDGET));
}

    Conditional compilation#

    #if, #ifdef, #ifndef, #elif, #else, #endif, #undef and #error work as in C. Define a macro from the command line with -D:

    void main()
{
#ifdef VERBOSE
  printf("verbose mode\n");
#else
  printf("quiet mode\n");
#endif
}

    verbose mode

    That example was built with ktm -DVERBOSE. #if and #elif take a constant expression of macros, which can use defined(NAME), and they nest:

    #define LEVEL 2

void main()
{
#if LEVEL > 2
  printf("high\n");
#elif LEVEL == 2 && !defined(QUIET)
  printf("level two\n");
#else
  printf("low\n");
#endif
}

    A conditional directive without its partner (#else or #endif without #if, a second #else, an #if never closed) and extra tokens after an #if condition are compile errors. #error stops the build and prints the rest of its line. #undef takes effect where it appears: code above it keeps the old value. These macros are always predefined:

    #include and #link#

    #include "file.ktm" is relative to the including file; #include <file.ktmh> searches the installed include directory. A file that can't be opened or read (a directory, say) is reported as an error at the #include, and the rest of the file is still checked. #link records a library dependency in the source itself (see calling C).

    Exceptions#

    A throw carries an Error, a struct every program has:

    struct Error { i64 code; u8 *message; u8 *file; i32 line; };

    The code is usually an enum member. throw(code) throws one with an empty message, throw(code, fmt, ...) formats the message like printf (the format and its arguments are checked at compile time the same way), and the compiler fills in the file and line of the throw. A try block catches it in the nearest enclosing catch; catch (Error e) gets the error in e. Throws unwind through any number of function calls, running the defers on the way.

    enum BankError { funds, locked };

void withdraw(i64 balance, i64 amount)
{
  if (amount > balance) { throw(BankError.funds, "need %d, have %d", amount, balance); }
  printf("withdrew %d\n", amount);
}

void main()
{
  try {
    withdraw(100, 30);
    withdraw(100, 500);
    printf("never printed\n");
  } catch (Error e) {
    if (e.code == BankError.funds) {
      printf("insufficient funds: %s\n", e.message);
    }
  }
  printf("carrying on\n");
}

    withdrew 30
insufficient funds: need 500, have 100
carrying on

    e.message is never null (it is "" without a message) and is freed when the catch block is left: copy it (str.dup(e.message)) to keep it. throw(e) throws the same error again, with its original message, file and line, so a handler can look at an error and pass it on. A catch that doesn't need the error can leave out the binding.

    The code is converted like an argument to an integer parameter: throw(42.75) throws 42. The catch handler runs after its try has ended, so a throw inside it goes to the next enclosing try.

    A return, break, continue or goto may leave a try body (or a catch handler) at any depth of nesting; the tries it leaves stop catching:

    enum Err { late };

i64 find(i64 *items, i64 n, i64 want)
{
  i64 i;
  for (i = 0; i < n; i++) {
    try {
      if (items[i] == want) { return i; }
      if (items[i] < 0) { break; }
    } catch {
    }
  }
  return -1;
}

void main()
{
  i64 items[4] = {3, 7, -1, 9};
  try {
    printf("%d %d\n", find(items, 4, 7), find(items, 4, 9));
    throw(Err.late);
  } catch {
    printf("caught here, not in Find\n");
  }
}

    1 -1
caught here, not in Find

    Each thread has its own catch chain: a throw is caught only by a try of the thread that threw, so threads can use try/catch at the same time.

    An error that no try catches, in any thread, is printed on stderr (after what the program printed so far) and ends the program with exit code 1:

    uncaught error 0: need 500, have 100 (bank.ktm:5)

    Each try and each defer reached saves the registers but not the signal mask, so they cost no system call; the flip side is that a throw out of a signal handler leaves that signal blocked.

    defer#

    defer followed by a statement (or a { } block) runs that statement when control leaves the enclosing block, however it leaves: at the end of the block, through return, break, continue or a goto out of it, or because a throw is passing through it on its way to a catch (after the deferred statements have run, the throw carries on to that catch). It keeps clean-up next to the code that needs it:

    import mem;

enum Err { neg };

void copy(i64 n)
{
  u8 *buf = mem.alloc(64);
  defer { mem.free(buf); printf("freed\n"); }
  if (n < 0) { throw(Err.neg); }
  printf("copied %d\n", n);
}

void main()
{
  {
    defer printf("1st registered, runs last\n");
    defer printf("2nd registered, runs first\n");
  }
  for (i64 i = 0; i < 3; i++) {
    defer printf("end of iteration %d\n", i);
    if (i == 1) { continue; }
  }
  copy(5);
  try {
    copy(-1);
  } catch {
    printf("caught\n");
  }
}

1st registered, runs last

end of iteration 2
copied 5
freed
freed
caught

    The rules:

    • The scope is the block the defer is written in (not the whole function): in a loop body it runs at the end of every iteration. It must be a statement of a { } block, so a defer directly after a case label needs braces.
    • Several defers in a block run in reverse order, the last one first; inner blocks finish before outer ones.
    • A defer only runs if it was reached: one written after an early return does not run on that return.
    • The statement runs as written when the block is left, so it sees the values variables have then. return evaluates its value first: return buf[0]; with defer mem.free(buf); returns the right value.
    • A throw from a deferred statement goes on like any other throw.
    • A deferred statement can't be left by return, break, continue or goto (a loop inside it keeps its own break and continue), can't contain a label, and a goto can't jump past a defer into the rest of its block. These, and defer outside a function, are compile errors.
    • Returning from main runs its defers, but os.exit(), exit() and a crash end the program without running any. Switching coroutines doesn't leave a block either, so it runs no defers.

    Only functions that use defer pay for it (each one reached sets up a frame like a try does); code without it compiles exactly as before.

    Calling C#

    Declare any C function with extern "c" and call it directly. libc is always linked:

    import libc;

extern "c" i32 abs(i32 x);
extern "c" u8 *getenv(u8 *name);

void main()
{
  printf("%d %d\n", abs(-5), libc.getenv("PATH") != null);
}

    5 1

    Use f32 for C float, i32 for int and u8 * for char *. To use another library, link it from the source and it works in compiled programs, the JIT and the REPL alike:

    #link &lt;sqlite3&gt;          // like -lsqlite3
#link "./libmine.so"     // a path, relative to the working directory

extern "c" i32 sqlite3_libversion_number();

    Inline assembly#

    An asm block defines labelled routines. _extern binds one to a ktm prototype. Arguments arrive in the platform's C calling convention:

    #ifdef IS_X86_64
asm {
_ADD_ONE::
  MOV RAX, RDI
  INC RAX
  RET
}
#endif

#ifdef IS_ARM_64
asm {
_ADD_ONE::
  ADD X0, X0, 1
  RET
}
#endif

_extern _ADD_ONE i64 addOne(i64 x);

void main()
{
  printf("%d\n", addOne(41));
}

    42

    Differences from its origins#

    ktm grew from a language made for its own operating system (see History and credits); ktm runs on a normal operating system instead. The differences:

    Featurektm
    f32Added, for C libraries that use float
    auto, typeof, range-based for, if (init; cond)Added
    extern "c", #link, #ifjit / #ifaotAdded, for working with the host system
    ?:Not supported
    Sub-integer access (x.u8[1])Not supported
    Exponent operator `Not supported; use math.power or libc.pow
    FsGone: catch (Error e) gives the error; there are no tasks
    DolDoc, graphics, the system shellNot available; use the C library through extern "c"
